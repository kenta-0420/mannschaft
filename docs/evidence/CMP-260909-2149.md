## 注記（削除の認可は実機で到達できない）
- **削除経路には HTTP の入口も画面の入口もない**。`ShiftHourlyRateDeletionFacade` の呼び出し元は 0 件で、DELETE /api/v1/shifts/hourly-rate/{id} は 404、?id= は 405、/hourly-rates/{id} は 404。
- したがって、本行の主題である「削除の認可」は IT（`ShiftHourlyRateDeleteAuthzIT`）だけが担保している。実機で確認したのは時給の作成・取得のみ。
- 呼び出し元がないため、導線を作るか削除するかの判断は別行 CMP-261014-1423 に分けた。
- 完了条件の後半（認可を通さない public メソッドを検出する番人の適用範囲の拡張）は、別行 CMP-261012-2337 に分割済みで、本行の完了根拠には含めない。

## 実機E2E（ロール横断・URL直打ち）
- ADMIN（画面）: 「設定」から時給 1,500・適用開始日を保存し、DB に永続化される。一覧は人名表示・未設定タグ・「9名未設定」警告が出る。
- ADMIN（API）: 他メンバーへの作成 201、取得 200、チーム一括 200。チーム非所属者を対象にした作成は 403。
- 一般メンバー（API）: 他人への作成・取得、チーム一括はすべて 403。自分の取得 200、自分への作成 201（認可の仕様どおり本人は可）。
- 他テナント（API）: 他人・自身名義とも作成・取得、チーム一括すべて 403。拒否された作成は DB に残らない。
- URL 直打ち（画面）: 一般メンバー・他テナントとも汎用エラー画面になり、時給は出ない。
- UI 検証の一部（一覧反映の表示、導線の表示切替）は WSL の高負荷で時間切れとなり未完。ADMIN のメニュー導線は TeamSidebar.vue:132 のソース確認のみ。
- 後始末: 作成した時給行は削除し、元の 2 行に戻した。
