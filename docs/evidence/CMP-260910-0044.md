# CMP-260910-0044 完了証拠: 監査ログのアーカイブ基準を UTC に統一

## 概要
- 実装PR: #3816（head 01c1dcf0b2、マージ済み）。レビュー: Codex 検分合格。
- 実機・アリシゼーション: 2026-10-14 に main 7d478d98b9（#3816 を含む）に対して実施。結果は pass。
- 環境: 監査ログのアーカイブは共有DBのパーティションを DROP するバッチのため、共有環境を避けた。使い捨ての MySQL（:3317、`--log-bin-trust-function-creators=1`）、MinIO（:9010）、専用の BE（:8084）、FE（:3004）で実施した。共有 DB と共有 MinIO には触れていない。

## 実機E2E（UTC 境界）
- 投入した行（UTC）: 2024-03-31 23:30、2024-04-01 00:30、2024-09-30 23:30、2024-10-01 00:30、および現在時刻付近の2行。
- SYSTEM_ADMIN で `POST /api/v1/system-admin/batch/auth-audit-log-archive-monthly/trigger` を実行した。
- アーカイブ対象月は UTC で決まり、2024-03 / 04 / 09 になった。JST 基準なら 3/31 の行は 4月、9/30 の行は 10月に入るはずだった。
- 生成ファイルは `audit-archive/2024/{03,04,09}/audit-2024-MM.json` で、各1件ずつ。
- DROP されたのは p_2024_03 / 04 / 09 だけ。p_2024_10 と p_2026_10、10/1 の行、直近2行は残った。
- 安全動作: 1回目は MinIO の接続先誤りでアップロードに失敗したが、その場合は DROP に進まず、失敗した月をまとめて例外にした。

## 実機E2E（ロール横断・URL直打ち）
- バッチの起動・一覧: SYSTEM_ADMIN は 202。ADMIN、一般メンバー、他テナントは 403。未認証は 401。
- チーム監査ログ API: 自チームの ADMIN は 200。一般メンバー、他テナントは 403。
- 画面: ADMIN は一覧が表示される。一般メンバー、他テナント、他チームの ADMIN は「ログがありません」と表示される（権限不足の表示にならない件は別件 CMP-261020-1529）。未認証は /login へ遷移。URL を直接打っても同じ結果。

## アリシゼーション
- 導線を住民の視点で触り、所見4件を台帳へ別行で起票した（いずれも本行の実装範囲外）。
  - CMP-261020-1528: 監査ログ画面で日時が9時間ずれる（API が UTC の値に `+09:00` を付けて返す）。
  - CMP-261020-1529: 403 の監査ログ画面が権限不足ではなく「ログがありません」と表示される。
  - CMP-261020-1530: LOGIN_SUCCESS の監査行で `ip_address` と `user_agent` が入れ替わる（`LoginSuccessEvent` の引数順の食い違い）。
  - CMP-261020-1531: 権限のない一般メンバーにもチームの全メニューが見える。

## 既知の別件
- アーカイブ JSON の `created_at` が JST の壁時計のまま（例 "2024-04-01T08:30"）になっている件は、既知の別件 CMP-261012-2344 であり、本行では扱わない。
