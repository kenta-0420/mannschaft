# 実機E2E CMP-260826-1456（実装PR #3590 本人の村参加申請履歴・存在秘匿の維持）— 合格

実施 2026-11-03。BE 8081（origin/main の bootJar）、FE 3001。村は接頭辞 `e2e1103` で、承認制村（申請後に UNLISTED 化）2件と公開村1件を用意した。UNLISTED 化すると新規申請は 404 になるため、公開の間に申請してから UNLISTED 化した（これが本件の再現条件）。資格情報は本書に記載しない。

## 役割
- 村長2名、申請者2名（本人）、未申請の第三者、他の村の村長、未認証。

## 実測（API）
- UNLISTED 村の申請者本人: `GET /api/v1/village-join-requests/me` が 200 で、UNLISTED 2件と公開村1件の計3件（villageName・villageState=ACTIVE・status=PENDING）を返す。旧 API は申請者本人でも 404 VILLAGE_001 のまま存在秘匿を維持。
- 第三者: `/me` は 200 で空配列。UNLISTED 村の旧 API・詳細・存在しない村 ID の 3 つはすべて 404 VILLAGE_001 で完全に同一。他人のユーザー ID や村 ID をクエリで指定しても空配列（他人指定は無視される）。
- 他の村の村長が UNLISTED 村の審査者一覧を引くと 404（村の存在は漏れない）。未認証は 401。
- 状態: 承認・却下（審査コメント付き）・取り下げを実行後、3件とも履歴に残る。村の論理削除後は villageState=DELETED（名前は保持）、凍結後は ARCHIVED。
- ページング（申請 158 件）: size=0 は 1 に丸め、size=101 以上は 100 に丸め、page=-1 は 0、不正値は 400、範囲外は空配列で total を維持。size=20 の全6ページ走査で 158 件・重複なし・欠落なし。createdAt 降順・同時刻は id 降順で、5回繰り返して同順。
- N+1: MySQL の general_log で 100行・53村の取得を採取し、申請 SELECT 1・COUNT 1・villages の IN 検索 1 の計3文のみ。

## 実測（画面）
- UNLISTED 村に審査待ちの申請者: `/my/village-join-requests` に「審査待ち／申請先の村／申請日時／申請メッセージ」が出る。`/my` の「自分の村参加申請」から到達できる。
- 第三者: 「自分が送信した参加申請はありません」。
- 却下・承認済み・取り下げ済みは、削除済み・凍結済みのバッジ付きで新しい順に並ぶ。
- 未ログインの直打ちは `/login?redirect=...` へ誘導される。

## 未踏
village の行が物理的に null のケースは、FK（ON DELETE CASCADE）により実 DB では作れず、実機では踏めない。サービスの該当分岐は単体テストの担保にとどまる。

## 合否
合格。本人は審査待ちの間も自分の申請を確認でき、第三者には村の存在が漏れない。size 境界・安定順序・N+1 も実測で満たす。
