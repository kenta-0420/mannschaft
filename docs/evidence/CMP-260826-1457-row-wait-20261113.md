# CMP-260826-1457 行ロック待機観測の回帰証拠

2026-11-13。C4/C7 のテスト補助処理を、`LOCK_DATA LIKE` による対象行の推定から、保持中の実 lock ID と待機辺の厳密照合へ変更した。製品コード・DDL・待機期限・`InviteGenerationConsistencyIT` は変更していない。親 CMP は実装中を維持する。

固定 base は `783443444d82b4ede0fe3b03ddc96e64f771d738`。赤コミットは `8eb0e79a93ae28a1e5614130daf403f0eb20eb8c`、緑を実行したコードは `61b5f425d53a78ccb537320047c4f2d6488d7331`。この文書は検証後の証拠追記である。[担当宣言](https://github.com/kenta-0420/mannschaft/issues/4022#issuecomment-6839363465)は具体本文の投稿許可後に1回だけ行った。

## 条件と実装・検査の対応

| 条件 | 実装 | 実 MySQL 契約 IT の検査 |
|---|---|---|
| AC1: 実 target PK の保持後・worker 開始前に唯一の保持 lock を capture | `InviteAcceptanceItSupport.captureTokenLock`。同 TX/接続、所有 schema/table、PRIMARY・RECORD・GRANTED を検査 | 保持 0件・2行・他接続の拒否 |
| AC2: opaque ENGINE/lock ID と実待機辺を同一 SQL で照合 | `rowWaitSql`。held/requested/waits/owner を ENGINE と両 lock ID で join。両 table/index/type/status を照合し、厳密1件だけ成功 | 通常列・両 NULL 投影が各1件、別行 proof・owner・table が0件、実 waiter 2本は成功拒否 |
| AC3: 保持 TX の寿命と対象 consumer の所有 | TX completion で proof を失効。同 TX の再 capture を拒否。C4/C7 は新 scope/UUID token を当 worker だけへ渡す | commit/rollback 後に新 TX で再利用拒否、別 lock の再 capture 拒否 |
| AC4: 既存の業務契約・失敗診断・解放を維持 | C4/C7 の実 target SELECT 直後に capture。capture 失敗でも barrier を開き、finally で解放と Future 回収 | 元 Concurrency 46件・診断 formatter 3件の回帰、全17メソッド名・DisplayName の同一性照合 |

保持 lock の観測 SQL は既存と同じ root observer を使い、lock を所有する blocker 接続との一致を検査する。観測用接続自体が blocker 接続であるとは主張しない。requester 接続は辺由来の観測値であり、Java thread との独立した対応証明ではない。

## 赤から緑への実測

共有 Testcontainer と既存 Entity fixture で実際の待機辺を成立させ、辺が存在することを先に確認した。SQL は helper と共有し、実 `data_locks` の `LOCK_DATA` 列だけを `CAST(NULL AS CHAR)` に投影した。ENGINE・lock ID・thread・waits は実サーバーの値を保持する。これは明示的な欠損注入であり、自然に NULL が発生した再現実績とは区別する。

|---|---:|---|
| 赤: 旧 predicate、通常列/NULL 投影 | 2 | 通常列は成功。NULL 投影だけ実辺存在確認後に期待1・実0で失敗。skip/error 0 |
| 緑: 元 `InviteAcceptanceConcurrencyIT` | 46 | 全成功、skip/error 0 |
| 緑: `InviteAcceptanceRowWaitContractIT` | 12 | 全成功、skip/error 0 |
| 緑: `InviteAcceptanceRowWaitDiagnosticsTest` | 3 | 全成功、skip/error 0 |
| 緑: `archUnitTest` | 37（18 suites） | 全成功、skip/error 0 |
| 緑: `archUnitFreezeStoreIntegrityTest` | 2 | 全成功、skip/error 0 |

共通 `scripts/verification-run.mjs` を clean Git HEAD から使用し、外部の新規 evidence、turnstile、`--no-daemon`、1800秒の有限上限で実行した。赤は既定 fork 条件、緑は規約のローカル WSL 条件 `-Pfork.every=0 -Pmax.parallel.forks=1`。fork 条件差を query 修正の因果や性能受入の根拠には使わない。緑の通常 `test` は実61件、全体 exit 0、7分44秒だった。

最初の runner 起動前の shell/Git 参照エラーと、初回 canonical copy 後の `gradlew` 実行 bit 不足は環境失敗として保全し、赤には数えていない。Git 参照の上書きは source 読取時だけ使い、検証子コマンド入口で解除した。実行 bit 不足は既存 wrapper を `bash` 経由で起動して解消した。
