# 実機E2E CMP-260821-1027（実装PR #4252 存在オラクルの本文正規化）— 合格

実施 2026-11-03。BE 8081（origin/main の bootJar）、FE 3001。テスト専用データは接頭辞 `e2e1103`（SQL で投入）。比較スクリプトは 7 対象・53 項目で、結果は 53 PASS・欠陥候補1件だった。欠陥候補1件は殿が範囲外と裁定した（下記）。資格情報は本書に記載しない。

## 役割（ロール名で表す）
- チーム1: ADMIN（ra）、MEMBER（rm1・rm2）、無所属（rout）。チーム2: ADMIN（rb、他テナント）。チーム3: rout が ADMIN。
- 求人2件・応募・契約・マッチ募集・マッチ応募・備品・チームフレンド関係を用意し、同じ操作者・同じ本文で「実在 ID」と「不在 ID」を呼んで、status・error.code・message の一致を見た。

## 実測（7対象）
| 対象 | 非閲覧者 vs 不在 | 閲覧者の診断 |
|---|---|---|
| 求人（close/cancel/delete/応募一覧/apply） | 無所属・他テナント ADMIN とも 404 JOB_NOT_FOUND で不在と一致 | 同チーム MEMBER の close は 404 JOB_PERMISSION_DENIED を維持 |
| 応募（accept/reject/withdraw） | 無所属・他テナント ADMIN・同チーム MEMBER とも不在と一致 | 応募者本人の accept は JOB_PERMISSION_DENIED |
| 契約（report/approve/reject/cancel/check-in） | 無所属・他テナント ADMIN・同チーム MEMBER とも不在と一致 | Worker の approve・Requester の report は 404 JOB_PERMISSION_DENIED。Requester のチェックインは 403 JOB_QR_TOKEN_WRONG_WORKER が残る（殿の裁定どおり） |
| マッチ募集（CANCELLED の delete/PUT） | 無所属・他テナント ADMIN とも不在と一致 | OPEN 募集を他チーム ADMIN が delete すると MATCHING_010 |
| マッチ応募（accept/reject/withdraw/cancel） | 無所属とも不在（MATCHING_002）と一致 | 募集チームの MEMBER は MATCHING_010、cancel は 409 MATCHING_009（状態診断）。閲覧者向けの従来診断として残存 |
| フレンド公開設定 | 第三者チームの ADMIN が関係を変更 → 不在関係と一致 | 当事者 ADMIN は 204、MEMBER は SOCIAL_107（関係 ID に依存しない） |
| 備品貸出（返却） | 他備品の貸出記録を指定 → 404 EQUIPMENT_002 が不在貸出と一致 | - |

## 画面（URL 直打ち `/jobs/1`）
- 無所属・他テナント ADMIN: 実在 ID も不在 ID も同じ「求人が見つかりませんでした」。
- 同チーム MEMBER: 求人詳細（タイトル・報酬・「この求人に応募する」）が出る。不在 ID は「見つかりませんでした」。
- 正の視点 ADMIN: 詳細が出る。
- 契約・マッチ・フレンド・備品の6対象は、画面から到達する操作が限られるため API の本文比較で確認した（実 BE・実 JWT）。

## 欠陥候補 D-1027-1 と殿の裁定
- 無所属・他テナント ADMIN が備品の返却・履歴を呼ぶと、実在の備品は 403 COMMON_002、不在の備品は 404 EQUIPMENT_001 となり、備品 ID の実在が分かる。
- 殿の判定（2026-11-03）: `docs/features/F07.3_equipment.md` 766 行目「この404統一はチーム備品詳細GETだけに適用する。組織版、一覧、変更、画像、貸出返却、履歴、QR、共通所属判定の契約は変更しない」の裁定により、本戦役の範囲外。#4252 の7対象はすべて一致。よって実機E2Eは合格とする。範囲外の差を閉じるかは別枠で判断する。

## 合否
合格。7対象のうち、本戦役の範囲の差は 0 件。D-1027-1 は範囲外として据え置き、合格に丸めた事実を隠さない。
