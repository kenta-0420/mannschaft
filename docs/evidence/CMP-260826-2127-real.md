# 実機E2E CMP-260826-2127（実装PR #3099 シフト表APIのステータス可視性制御）— 合格（条件付きの注記あり）

実施 2026-11-03（1回目）と 2026-11-04（再実機）。BE 8081、FE 3001。一覧・期間一覧・詳細・枠・PDF（team/personal）・summary・検索を 7 視点で実 JWT により実測した。データは接頭辞 `e2e1103`、資格情報は本書に記載しない。

## データと役割
- シフト表7種（枠1・必要2・MEMBER 割当済み）: DRAFT / COLLECTING / ADJUSTING / PUBLISHED / ARCHIVED（公開済）/ ARCHIVED（DRAFT 直行＝publishedAt NULL）/ PUBLISHED かつ published_at を SQL で NULL。
- 役割: 純粋なチーム ADMIN、MEMBER、SUPPORTER（招待のロールでは MEMBER になるため SQL で補正）、DEPUTY_ADMIN、別チーム ADMIN、無所属、非メンバーの SYSTEM_ADMIN、未認証。

## 1回目の実測と欠陥
- 合格: AC-1〜7・17（一覧・期間一覧・詳細・枠・PDF・検索での DRAFT／未公開 ARCHIVED の同一扱い、publishedAt=NULL の PUBLISHED は公開扱い、枠の骨格を維持して割当のみ伏せる）、AC-9・10。
- D-2127-1（AC-12 違反）: SUPPORTER が DRAFT と未公開 ARCHIVED では 404、それ以外では 403 になり、存在とステータスが読める。`ShiftScheduleFacade#getSchedule` が `scope.isHidden()` の 404 を SUPPORTER の 403 より先に評価していた。
- D-2127-3: SUPPORTER が shift API では 403 なのに、検索には COLLECTING・ADJUSTING を含むシフト表の title が出る。
- D-2127-2: 非メンバーの SYSTEM_ADMIN の検索が 0 件。検索全体が所属方式という既存仕様との整合の問題で、殿が範囲外と裁定し、据え置く。
- 文書側の乖離: AC-12 の文言が「常に 403」だが、実装は別スコープ・無所属に存在秘匿の 404。存在オラクルは無く安全側。

## 再実機（2026-11-04、#4269 反映の main）
- D-2127-1 解消: SUPPORTER は7ステータスすべてで 詳細・枠・PDF・summary・一覧・期間一覧が 403 COMMON_002 で、404 は混ざらない。
- D-2127-3 解消: SUPPORTER の検索は 0 件。MEMBER は公開系5件のみ、ADMIN は7件。
- 変更依頼の作成: SUPPORTER は全7ステータスで 403、MEMBER・DEPUTY・ADMIN は DRAFT・COLLECTING・ADJUSTING で 201、PUBLISHED・ARCHIVED・publishedAt NULL で 409 SHIFT_012。別チーム ADMIN・無所属は 404 SHIFT_001。
- 親削除済みの変更依頼: 親シフト表を論理削除した後、本人以外の全視点で GET・review・withdraw が 404 SHIFT_030 となり、存在しない依頼と status・code・本文まで完全一致した。
- AC-8 合格: COLLECTING の枠へ希望提出（POST）が MEMBER・DEPUTY で 201、SUPPORTER で 403、他チームで 404。
- AC-14 合格: 48時間前リマインドのバッチと手動 remind の双方で、通知本文にシフト表名を含む。
- AC-15 合格（画面）: MEMBER には COLLECTING・ADJUSTING・PUBLISHED・ARCHIVED（公開済）・publishedAt NULL の PUBLISHED が並び、DRAFT と未公開 ARCHIVED は出ない。SUPPORTER は一覧 API が 403 で、案内のエラー表示になる。
- DEPUTY_ADMIN は ADMIN と同じく変更依頼作成・希望一覧・summary・手動 remind が可。

## 未確定
SUPPORTER の `/shift/{id}` 直打ちのうち、一部は dev サーバーの初回コンパイルの遅延で描画が完了せず、画面の判定が確定しなかった。API 層は 403 を確認済みで、画面での確認はアリシゼーションが担った（探索記録を参照）。

## 殿の裁定（2026-11-04）
- CMP-260826-2127 の実機E2Eは合格とする。受け入れ条件（SUPPORTER へのステータス漏洩の遮断、AC-8・14・15、DEPUTY）はすべて満たした。
- O-2127-4（MEMBER が DRAFT に変更依頼を作成でき 201、希望提出は 409。存在とステータスが読め、見えないはずの下書きに依頼が作れる）は、設計書 `05_unpublished_visibility.md` §2 の「DRAFT は存在ごと秘匿」と矛盾する欠陥と認める。ただし本戦役の射程（SUPPORTER）の外で、変更依頼とシフト表ステータスの境界は既存の CMP-260903-0654（保留、設計書 §8 B-4）が扱う。そこで、作成経路（POST /shifts/change-requests）にも境界が無く、不在と同じ 404 にするべきという内容を 0654 へ畳み込み、台帳の 0654 の行に注記する（別 PR）。

## 合否
合格（条件付き）。D-2127-1・D-2127-3 は解消、D-2127-2 は範囲外で据え置き、O-2127-4 は 0654 へ畳み込む。
