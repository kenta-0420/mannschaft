# CMP-261010-1615 再現記録: チーム slug の 403/404 差

## 概要

- 日時: 2026-10-10
- 環境: ローカル開発 BE（8080、main 相当）
- アカウント: `e2e-dummy-1`（組織9の別チームの管理者。チーム `e2e` には非所属）

## 実測

| # | リクエスト | 結果 |
|---|---|---|
| 1 | `GET /api/v1/teams/{実在する非公開チームの slug}` | 403 `VISIBILITY_001`（本文「このコンテンツを閲覧する権限がありません」のみ） |
| 2 | `GET /api/v1/teams/{存在しない slug}` | 404 `TEAM_001` |
| 3 | `GET /api/v1/timeline/feed?scopeType=TEAM&scopeId={実在する slug}` | 403 `COMMON_002`（所属確認が投稿検索より先） |
| 4 | `GET /api/v1/timeline/feed?scopeType=TEAM&scopeId={存在しない slug}` | 404 `TIMELINE_001` |
| 5 | `GET /api/v1/public/teams/slug-resolve?slug=e2e`（未ログイン） | `CURRENT` |
| 6 | `GET /api/v1/public/teams/slug-resolve?slug={存在しない slug}`（未ログイン） | `NOT_FOUND` |

拒否時の本文にチームの名前・メンバー・投稿は含まれない。判別できるのは「slug が実在する」1 ビットのみ。

## 判断

2026-08-04 確定の「slug の実在は非機密として扱う」（`docs/security/01_authorization_baseline.md` §3.3 の注記）の範囲内。同じ 1 ビットを `slug-resolve` が未ログインで返しているため、是正対象としない。注記の直後に確認事項として追記した。

## Codex 軍議検分の結論

- 上記 2 経路に限定すれば妥当。
- 「認証付きの slug 経路すべてで許容する」という包括適用は不可（F01.2.1 の招待先・加盟受付設定、§3.3.2 の子リソース契約は免責しない）。
- 資格 API に、子リソースの `error.code` 差の疑いがある。

## 別行に分けた課題

CMP-261010-2226: チームの資格 API で、第三者が資格 ID の実在と所属チームを応答コードの差から判別できる疑い。`docs/task-list.md` に登録。
