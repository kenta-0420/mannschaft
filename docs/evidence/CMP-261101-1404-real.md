# 実機E2E CMP-261101-1404（実装PR #4257 カレンダー週グリッドの秋の重複時刻）— 合格

実施 2026-11-03（夏時間切替後の実行日。バグの再現条件そのもの）。FE 3001（main に #4257 を含む）、BE 8081。ブラウザの OS タイムゾーンは Asia/Tokyo とし、ユーザーのタイムゾーンと別にして取り違えを弁別した。資格情報は本書に記載しない。

## データ
- ユーザー2名（America/New_York と America/Havana を `users.timezone` に設定）。個人予定を3件作成（title 接頭辞 `e2e1103-dst-`）。

## 実測
入口 `/calendar` → 「週」→ 2026/11/01〜11/07（日曜が切替日）→ 日曜列でドラッグ → 「予定を追加」フォーム → タイトル入力 → 「作成」→ `POST /api/v1/me/schedules` → 週グリッドを再表示。
| 予定 | TZ | ドラッグ（壁時計） | フォーム | 保存値（offset 付き） | DB(UTC) |
|---|---|---|---|---|---|
| A | NY | 0:00 から（1:30 の枠） | 00:00〜01:45 | 00:00-04:00 〜 01:45-04:00（夏時間側） | 04:00Z〜05:45Z = 105分 |
| B | NY | 1:45 から（2:30 の枠） | 01:45〜02:45 | 01:45-04:00 〜 02:45-05:00 | 05:45Z〜07:45Z = 実時間120分 |
| H | Havana | 0:00 から（1:30 の枠） | 00:00〜01:45 | 00:00-04:00 〜 01:45-05:00（01:45 は切替後に一意） | 04:00Z〜06:45Z |
- 重複時刻（NY の 01:45）は、実行日（切替後）に依存せず常に先の側（夏時間、-04:00）へ解決され、105分で保存された。旧実装なら切替後は 01:45 が -05:00 へ倒れて 165分になる。
- 保存値の往復: `GET /api/v1/me/schedules/{id}` の startAt・endAt は保存時と一致。週グリッドの位置と長さは壁時計で描画され、保存→再読込で変わらない。

## ロール横断
個人カレンダーのため権限あり・なしの差は無い（本人のみ）。他アカウントが別ユーザーの予定を `GET /api/v1/me/schedules/{id}` で引くと 403 SCHEDULE_022（所有者ではありません）で、URL 直打ちでも見えない。

## 未実施
重複時刻の編集後の再保存（フォームの再オープン→再保存）の往復は、API の読み戻しまでで未実施。

## 合否
合格（欠陥なし）。
