# CMP-260909-2151 完了証拠: シフト表 API のフラグゲート

## 概要
- 実装PR: #3810（head 0a75bc0116、マージ済み）。レビュー: Codex 検分合格。
- 実機・アリシゼーション: 2026-10-14 に main 7d478d98b9（#3817 を含む）に対して実施。結果は pass。
- 環境: BE は WSL native で bootJar を 8083、FE は nuxt dev 3003。DB は共有の開発 DB。ロールは ADMIN / 一般メンバー / 他テナント / 委員長 / SYSTEM_ADMIN（フラグ切替・バッチ起動のみ）。

## 実機E2E（ロール横断・URL直打ち）
- フラグの ON/OFF は SYSTEM_ADMIN の PUT /api/v1/system-admin/feature-flags/FEATURE_SHIFT_ENABLED（キャッシュ evict が働く正規経路）で切り替えた。
- ON・ADMIN: 画面の「新規作成」からシフト表を作成し、DB に永続化され一覧に出る。
- ON の API: 一覧は ADMIN・一般とも 200、他テナントは 403。詳細は ADMIN 200・他テナント 404。一般メンバーの PATCH は 403。
- OFF の API: 9 経路 × (ADMIN, 一般, 他テナント) = 27 通りすべて 403 FEATURE_GATE_001。OFF 中の作成・更新・削除・複製で行数は不変。
- OFF の画面: /teams/fc-u-18/shifts の URL 直打ちは ADMIN・一般とも /dashboard へ戻る。ON に戻すと同 URL でシフト画面が戻る。
- 手順の注意: feature_flags を SQL で直接更新するとキャッシュ（Valkey）が evict されず OFF が効かない。製品欠陥ではなく手順の罠。
- 後始末: フラグは ON に復旧、作成したシフト表は削除済み。

## アリシゼーション
- [軽微] フラグ OFF でもサイドバーに「シフト管理」「マイシフト」が残り、押すと理由の表示なしに /dashboard へ戻る（導線が残る）。/my/shifts も同様。別行 CMP-261014-1425 で起票。
- 既知: OFF かつ不正本文は 400 COMMON_001 が返る（CMP-261012-2339）。
