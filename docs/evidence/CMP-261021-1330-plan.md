# CMP-261021-1330 LINE/SNS設定ヘッダーの国際化計画

完了対象scopeは `app`。対象は `/admin/line-settings` と `/admin/sns-settings` のタイトル・副題4文言である。6言語化とlocale切替追従、ja/de実画面確認という台帳の原ACを維持する。

## 受け入れ条件

| ID | 条件 | 試験・証拠予定 |
|---|---|---|
| AC1 | 両ページのタイトルと副題4文言をlocale経由で表示し、日本語の意味を維持する | 実ページ・実PageHeaderのヘッダーassert、ja実機 |
| AC2 | ja/en/zh/ko/es/deの対象キーが存在し非空、非jaに未翻訳日本語を混入せず、未定義キーやfallbackに頼らない | 6言語実辞書render、既存locale品質番人 |

## 範囲と進軍順序

1. 登録PRで本計画・台帳の実装中記録を先にmainへ採用後、先行試練PRをmainへ追従させる。
2. 既存の実タイトルキー `orgSidebar.lineSettings` / `orgSidebar.snsSettings` を再利用する。副題用 `integrationSettings.lineSubtitle` / `integrationSettings.snsSubtitle` を6言語のcommon.jsonへ追加する案を採る。2ページのPageHeaderをreactiveなtemplate `$t` bindingへ変更する。
3. **製品変更前にCIでコンパイル成功とactual redを確認する。** 先行試練は `frontend/tests/unit/pages/admin-integration-settings-i18n.spec.ts`。実ページ・実PageHeader・実Vue-i18n・本番辞書を使い、API等の表示外境界だけをstubする。辞書/翻訳関数/PageHeaderのstubで合格を作らない。
4. actual red確認後に製品greenへ進み、CI・検分・AC5/6実機・AC7の順で完了証拠を揃える。

試練specはAC1/2/4の6言語×2ページとAC3/6表示部分の切替×2ページを扱う。実認可・画面幾何・住民探索をUTで検証済みとは扱わない。ローカルの重いinstall・WSLコピー・runtime起動は行わず、actual redはCIで確認する。

対象ページ内の保存通知・Dialog・table等の他文言、他画面の日本語直書き、共通PageHeader本体、外部連携設定の仕様は今回へ広げない。
