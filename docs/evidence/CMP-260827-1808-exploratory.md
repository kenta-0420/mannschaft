# CMP-260827-1808 探索（アリシゼーション）記録

> 記録が消えたため、2026-11-07 に再確認をやり直した記録である。

## 前回の確定事項

前回のアリシゼーションで、不具合 V1 が確定した。業務コード付きの 429（VILLAGE_012「参加可能な村数の上限」）を受けると、画面側の個別エラー表示に加えて、共通の「操作が集中しています」トーストが重なって出ていた。PR #4330 で、共通トーストを「業務コードを持たない基盤のレート制限 429」に限る形に是正され、main に入っている（回帰テスト: `frontend/tests/unit/composables/useApi.rateLimitToast.spec.ts`）。

## 今回の再確認

- 環境: main `ecd2da3fe2`、FE 3007 / BE 8087、実ブラウザ。
- 操作: 100 村に所属済みの住民が、101 村目の画面（`/villages/<id>`）で「参加する」を押す。
- 観測: API は `POST .../memberships` が 429（VILLAGE_012）。画面に出たトーストは 2 枚。1 枚は「エラーが発生しました／参加可能な村数の上限（100村）に達しました」。もう 1 枚は「掲示板の取得に失敗しました」。
- 後者は、同じ画面を開くだけ（ボタンを押さない）でも 1 枚出ており、非参加者が閲覧できない掲示板の取得失敗である。参加操作の 429 とは無関係。
- 「操作が集中しています」の共通トーストは出なかった。V1 は是正済みと判断する。
- 参考: 上限の数値は文言に `{0}` として差し込まれ「100村」と表示された（固定文言ではない）。
- スクリーンショット: `docs/evidence/CMP-260827-1808-assets/v1-village012.png`

## その他の観測（欠陥とは断定しない）

- 非参加者が公開村を開くと「掲示板の取得に失敗しました」のトーストが常に出る。権限の無い画面を開いただけでエラー扱いになるのは導線として気になるが、本戦役の範囲外。
- BAN 後の再申請（承認制）は受付され PENDING になり、承認時に初めて拒否される。受付時に弾くかは仕様判断。
