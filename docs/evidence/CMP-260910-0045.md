# CMP-260910-0045 完了証拠: 郵便番号マスタの時刻列を UTC で充填

## 概要
- 実装PR: #3807（head faecf6fef0、マージ済み）。レビュー: Codex 検分合格。
- 実機・アリシゼーション: 2026-10-14 に main 7d478d98b9（#3817 を含む）に対して実施。結果は pass。
- 環境: BE は WSL native で bootJar を 8083、FE は nuxt dev 3003。DB は共有の開発 DB。ロールは ADMIN / 一般メンバー / 他テナント / 委員長 / SYSTEM_ADMIN（フラグ切替・バッチ起動のみ）。

## 注記（DB 値だけでは旧実装と区別できない）
- 検証 DB の MySQL は time_zone が +00:00 で動いており、NOW() と UTC_TIMESTAMP() が同値になる。そのため **DB に入った値だけでは旧実装（NOW()）と区別できなかった**。
- 判定は、デプロイしたコード（UPSERT_SQL に UTC_TIMESTAMP() があること）と値の両方で行った。コード側の裏付けは `GeonamesImportServiceTest` の単体テスト。

## 実機E2E
- SYSTEM_ADMIN の /system-admin/batches から、月次取り込みバッチを画面で実行した。取得 URL はローカルの偽 allCountries.zip（国コード ZZ、5,101 行）に差し替えた。
- 新規行・既存行（ON DUPLICATE KEY UPDATE）とも updated_at が UTC_TIMESTAMP と 1 分以内で一致した。
- 後始末: ZZ の行、偽 zip、ローカルサーバを削除・停止。

## アリシゼーション
- [重大] 本 PR の範囲外の既存欠陥。`GeonamesImportService.parseAndUpsert` の try-with-resources が zip ストリームを閉じるため、次の getNextEntry で Stream closed になり、月次取り込みが毎回失敗する。端数バッチ（5,000 件未満）が反映されず、行数下限チェックと geonames_metadata 更新にも届かない。5,101 行で再現（先頭 5,000 件のみ反映、残り 101 行は未反映）。CMP-261014-1421 で起票。
