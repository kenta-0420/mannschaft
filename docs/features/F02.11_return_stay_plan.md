# F02.11: 帰省・滞在予定

> **ステータス**: 🟡 設計精査中
> **関連**: [F02.2 マイダッシュボード](F02.2_dashboard.md)、[F01.2 組織・チーム・メンバー・ロール](F01.2_org_team_member_role.md)、[F00 ContentVisibilityResolver](F00_content_visibility_resolver.md)、[F09.16 居住実態管理・見守り](F09.16_residence_status_management.md)

## 1. 目的・境界

本人が個人ダッシュボードから帰省／滞在を複数登録・編集・削除し、予定ごとに選んだ所属 TEAM だけへ公開する。未来は「帰省予定／滞在予定」、期間中は「帰省中／滞在中」をチームの既存メンバー一覧の名前横 pill と予定詳細に表示する。

本機能は本人の任意行動予定であり、F09.15/16 の `expected_absence_periods`、居住実態、封緘見守り、同意、推定スコア、イベント、テーブル、API、権限、監査と**依存・統合・流用しない**。F00 の汎用コンテンツ可視性、公開検索、通知、timeline、コルクボードにも登録しない。

初回は国内都道府県だけとし、市区町村・住所・座標・郵便番号・理由・メモを保存も入力も禁止する。将来は国コード＋任意地域名へ安全に拡張できるが、初回 API は海外を拒否する。

## 2. 値・上限・状態

| 項目 | 仕様 |
|---|---|
| `planType` | `HOMECOMING` / `STAYING` |
| 日付 | `LocalDate` の `startDate` / `endDate`、両端含む。timestampではない |
| 地点 | `countryCode='JP'`、`prefectureCode` は JIS X 0401 `^(0[1-9]|[1-4][0-7])$`。`regionName` は初回 `null` |
| 将来海外 | trim後空文字を禁止した ISO 3166-1 alpha-2 `countryCode` と最大100文字 `regionName`。JPでは `regionName=null`、海外では`prefectureCode=null`。feature flagまで400 |
| 公開 | `isPublished`（初期 `false`）と `teamIds`。公開先初期0件、OFFでも選択済みteamIdsは保持し、ON時だけ可視化 |
| 上限 | `endDate >= ownerToday` の予定30件、公開先20 TEAM、開始はownerToday以上、終了はownerToday+365日以下 |

重複期間を許可し、同日開始は `createdAt,id` で安定ソートする。重複 `teamIds` は400で拒否する。`isPublished=false` のまま active 予定の公開先編集、ON/OFF、終了日の延長は可能。状態は保存せず、owner timezone で `UPCOMING` / `ACTIVE` / `ENDED` を算出する。国内初回は予定に `timezone='Asia/Tokyo'` をスナップショットし、API日付ずれを防ぎ、将来海外有効化時にcountry timezone選択へ拡張する（既存の `UserTimezoneCache` 利用方針とも矛盾しない）。

終了予定はチームから即時除外する。本人履歴は `GET /api/v1/me/return-stay-plans?includeEnded=true&page&size`（size 1–50、終了日降順）で最大1年表示し、終了後1年で日次 purge が物理削除する。purge は ShedLock・実行件数metric・失敗alertを必須とする。

## 3. 認可・可視性

- 本人 collection（一覧、作成）だけを `@SelfScopedEndpoint` とする。URLに userId/planId を置かない。
- item（取得、更新、削除）は `ReturnStayPlanAccessGuard.findByIdAndOwnerUserId(planId, currentUserId)` を必ず経由し、所有者以外・不在は同じ404。Service の認可シグナルと `ScopeContractIT` で強制する。
- team read は、viewer と owner の双方について `memberships.scope_type='TEAM' AND role_kind IN ('MEMBER','DEPUTY_ADMIN','ADMIN') AND left_at IS NULL`、`users` active、`teams.deleted_at IS NULL AND teams.archived_at IS NULL`、かつ `is_published=1` と allow-list 行を単一SQLで検証する。SUPPORTER/PUBLIC/未所属は403（item型の存在は返さない）。
- SYSTEM_ADMIN は特権迂回を持たず、当該 TEAM の active MEMBER 以上として所属している場合だけ通常閲覧でき、無所属では不可。F02.2 の「SYSTEM_ADMIN は全dashboard可」はこの私的予定 widget / team member plan query の例外である。
- 脱退・除名・チーム削除／archive は可視性行を削除し、SQLのactive条件により非同期失敗中も即時非表示とする。

## 4. DB / Flyway

既存ユーザー・TEAM・member ID は `BIGINT UNSIGNED`（Long）。UUIDv7 `BINARY(16)` は新規予定 `id` と可視性 `id`・`plan_id` だけである。ユーザー／TEAM／membership は別ドメインなので FKなし、同一ドメインの `plan_id` のみ FK CASCADE とする。テーブル既定 `DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci`、列個別の `COLLATE` 上書きは禁止。

### `return_stay_plans`

`id BINARY(16) PK`、`owner_user_id BIGINT UNSIGNED NOT NULL`、`plan_type VARCHAR(16) NOT NULL`、`is_published BOOLEAN NOT NULL DEFAULT FALSE`、`location_country_code CHAR(2) NOT NULL`、`prefecture_code CHAR(2) NULL`、`region_name VARCHAR(100) NULL`、`timezone VARCHAR(64) NOT NULL DEFAULT 'Asia/Tokyo'`、`start_date DATE NOT NULL`、`end_date DATE NOT NULL`、`version BIGINT NOT NULL DEFAULT 0`、`created_at DATETIME(6) NOT NULL`、`updated_at DATETIME(6) NOT NULL`。

`KEY idx_rsp_owner_end (owner_user_id,end_date,start_date,id)`、`KEY idx_rsp_owner_history (owner_user_id,end_date DESC,id)`、`CHECK(plan_type IN (...))`、`CHECK(end_date>=start_date)`、国内／将来海外の地点排他 CHECK を置く。owner単位の30件上限は親行を `SELECT ... FOR UPDATE` する owner lock 行（既存 user row）で直列化し、countとinsertを同一transactionで行う。

### `return_stay_plan_team_visibilities`

`id BINARY(16) PK`、`plan_id BINARY(16) NOT NULL`、`team_id BIGINT UNSIGNED NOT NULL`、`created_at DATETIME(6) NOT NULL`。`UNIQUE(plan_id,team_id)`、`KEY idx_rsptv_team_plan(team_id,plan_id)`、`FOREIGN KEY(plan_id) ... ON DELETE CASCADE`。`team_id` には FK を張らない。

候補 Flyway は `V185.{UTC timestamp}__create_return_stay_plans.sql`。origin/main の現在最大major=184からの仮値であり、**マージ時に origin/main 最大+1 を再確認**する。DDL番人（UUID、cross-domain FKゼロ、index/check/unique/collation/version/audit列）を実装時に追加する。

## 5. API 契約

全 endpoint は `/api/v1`、JSON lowerCamelCase。`ApiResponse<T>` は `{ "success":true, "data":T, "timestamp":"2026-08-17T12:34:56.123456Z" }`（timestampはUTC instant）。`PagedResponse<T>` は `{ "content":[T], "page":0, "size":20, "totalElements":0, "totalPages":0 }`。日付は `YYYY-MM-DD`、Plan IDだけUUID文字列、owner/team/member IDはnumber。null は明示し、配列は常に `[]`（省略しない）。

| endpoint | request / response | 認可 |
|---|---|---|
| `GET /api/v1/me/return-stay-plans` | `includeEnded`既定false、`page,size`。`data` は `PagedResponse<OwnPlan>` | 本人。false時はENDEDなし |
| `POST /api/v1/me/return-stay-plans` | `{planType,isPublished,location:{countryCode,prefectureCode,regionName},startDate,endDate,teamIds}`。createにversionなし | 本人、201 |
| `GET /api/v1/me/return-stay-plans/{planId}` | `data: OwnPlan` | AccessGuard、404秘匿 |
| `PUT /api/v1/me/return-stay-plans/{planId}` | create同等＋必須`version` | AccessGuard、200/409 |
| `DELETE /api/v1/me/return-stay-plans/{planId}` | 204 | AccessGuard |
| `GET /api/v1/teams/{teamId}/members/return-stay-plans` | `memberIds`最大100。`data:{items:[{memberId,plans:[TeamPlan]}]}` | active MEMBER以上。既存members endpointの拡張ではなく、member listが必ずこの**バッチAPI**を同時呼出してpillを合成する。N+1禁止 |
| `GET /api/v1/teams/{teamId}/members/{memberId}/return-stay-plans` | `page,size`のみ。`data:PagedResponse<TeamPlan>` | active MEMBER以上。ENDEDは常に除外。from/to/date指定なし |

`OwnPlan` は `teamIds`、`isPublished`、`version`、`createdAt/updatedAt`（UTC timestamp）を含む。`TeamPlan` は teamIds・公開トグル・versionを含まない。チームの開始日順詳細は同日安定ソート。Owner timezone はバッチ対象ownerIdを集めて `UserTimezoneCache#getTimezones` で一括解決し、各owner local dateで状態を算出する。クライアント指定日付・from/toは受けない。

create validation は「未来・30件・候補TEAM・初回国内・timezone」を検証する。update validation は現在ACTIVEでも公開OFF、公開先変更、終了延長を許し、過去開始日を再拒否しない一方で終了がownerToday未満にならないことを検証する。

## 6. 退会・監査・PII

`UserAnonymizedEvent` の独立 `ReturnStayPlanAnonymizationEventListener` を `REQUIRES_NEW` で購読し、ownerの予定と可視性行を物理削除する。`deleteByOwnerUserId` は0件でも成功する冪等処理、失敗は例外を握り潰さずmetric/alert/補正キューへ記録する。`AccountPurgedEvent` listener は最終保険として同じ冪等削除を再実行する。退会 API から DB 消去までを contract ITで検証する。

標準監査保持は2年。監査は create/update/delete/publish toggle の actor、planId、操作時刻、結果だけで、地点・日付・teamIdsを記録しない。ログ、metric、trace、例外にも予定内容を出力しない。GDPR export は削除前の本人履歴を含め、退会後は即時削除済みとして含めない。

## 7. エラー・構成

`ReturnStayPlanErrorCode` は実装開始時の既存最大+1を予約し、マージ前再確認する。候補は NOT_FOUND=404/WARN、INVALID_REQUEST=400/WARN、LIMIT_EXCEEDED=409/WARN、VERSION_CONFLICT=409/WARN、TEAM_ACCESS_DENIED=403/WARN、MEMBERSHIP_CHANGED=409/WARN、PAGING_INVALID=400/WARN。HTTP mapを `GlobalExceptionHandler` に明示登録し契約IT化する。

BE は `returnstayplan` feature package（Entity/Repository/AccessGuard/Service/TeamQueryService/Controller/DTO/Mapper/EventListener/PurgeJob）。FE は `useReturnStayPlanApi.ts`、`ReturnStayPlanWidget.vue`、`ReturnStayPlanPill.vue`、詳細dialog。全選択／解除はactive MEMBER以上候補だけに作用し、OFFでも選択を残すと明示する。i18nは ja/en/zh/ko/es/de の6言語で種別・状態・都道府県catalog・validation・プライバシー文言を同一keyで追加する。

## 8. AC・試練・実機

| AC | 検証 |
|---|---|
| 正常/空/null | 0公開OFF、ON、複数・重複予定、`regionName:null`、`items:[]`、null/省略JSON契約 |
| 境界/入力 | 当日開始・終了ACTIVE、翌日ENDED非表示、365日/30件/20TEAM境界、都道府県regex/catalog、ISO/trim空文字、重複teamIds400 |
| 更新/途中失敗 | ACTIVEのOFF・延長可、version競合、membership喪失時409・部分更新なし、owner lockで並行31件目なし |
| 認可 | 他人item404、SUPPORTER/PUBLIC/無所属SYSTEM_ADMIN不可、所属SYSTEM_ADMIN通常閲覧、viewer/owner双方active・team削除/archive・active user条件 |
| 退会/保持 | UserAnonymizedEvent REQUIRES_NEW削除、失敗観測・AccountPurged保険、退会API経由即時DB削除、1年終了purge |
