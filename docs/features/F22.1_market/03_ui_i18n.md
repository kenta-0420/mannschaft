## 2. 市一覧画面（`/market`）

`pages/villages/index.vue` のヘッダー＋フィルタバー＋グリッド＋Paginator 構成を流用する。

```
┌─ ヘッダー ────────────────────────────────┐
│ PageHeader「市」      [札を立てる ▸]                         │  ← 個人の作成フォームへ
├─ パンくず ────────────────────────────────┤
│ 全国 ＞ 大分県 ＞ 別府市                          │
├─ フィルタバー（flex-wrap, gap-3）────────────────┤
│ [都道府県 ▾] → [市区町村 ▾(連動)]  [ジャンル ▾]  [🔍キーワード]  件数:42 │
├─ 結果グリッド grid-cols-1 sm:2 lg:3 ──────────────┤
│ [札カード] [札カード] [札カード] …                   │
│  └ タイトル / 主催（チーム公称名+アイコン）/ ジャンル / 地域 / 締切 / 募集◯人中△人 / 状態バッジ │
├─ Paginator（PrimeVue）──────────────────────┤
└──────────────────────────────────────┘
```

### 2.1 フィルタ連動（都道府県 → 市区町村）
- 都道府県 `Select`（`constants/prefectures.ts` ではなく **API `GET /market/regions`** を正典にする。コード値が必要なため）。
- 都道府県選択 → `GET /market/regions?prefecture=44` で市区町村 `Select` を動的ロード。`useMarketRegions(prefecture)` composable（cities/selected を保持）。
- ジャンル `Select` は `recruitment_categories`。`show-clear` で「すべて」。
- 札主 `Select` は `PERSONAL` / `TEAM` / `ORGANIZATION`。`show-clear` で「すべての札主」。選択値は `owner_type` として API へ送り、URL の `owner` に同期する。
- キーワードは 500ms debounce（村一覧踏襲）。
- フィルタ状態は URL クエリに同期（共有・ブックマーク可能、SEO）。

### 2.2 パンくず（階層市）
- `全国 ＞ 都道府県 ＞ 市区町村`。各ノードは `GET /market/summary` の件数をバッジ表示（例: `別府市 (7)`）。
- 県ノードは配下市区町村の札をロールアップ表示。
- **「地域なし」札**（地域未指定）は「全国」ノードに `全国（地域指定なしを含む）` と括弧表記で含める。フィルタで `include_region_none` を切り替えると地域なし札の表示/非表示を制御できる。

### 2.4 レスポンシブ・アクセシビリティ
- **モバイル（sm未満）**: フィルタバーは縦積み4行を避け、**折りたたみ（accordion / bottom-sheet）**に格納。ドロップダウンのタップ領域は最小48px。
- **WCAG AA**: フィルタの各コントロールに `aria-label`（例「都道府県を選択」）、札カードはキーボード focus 可能（Tab順: フィルタ→一覧→Paginator）、Paginator はモバイルで折返さない簡易表示。ダークモード対応（`dark:` クラス）。既存 villages/recruitment 画面の a11y 方針を踏襲。

### 2.3 空状態（閲覧者の立場別に出し分け）
公開市から個人札を立てる導線と、チーム・組織の管理市へ進む導線で迷子にしないため、空状態の CTA を立場別に出し分ける。
| 立場 | メッセージ（key） | CTA |
|---|---|---|
| ログイン済み | `market.action.post` | **[札を立てる ▸]** → `/me/market?create=true`。チーム・組織名義は各主体の管理市から作成する |
| 未ログイン | `market.empty.cta.guest` | 「[ログイン ▸] して札を立てる／応募する」 |

- ヘッダーの「`market.action.post` 札を立てる」は個人の `/me/market?create=true` へ遷移し、作成フォームを開く。チーム/組織名義は各主体の管理市にある「札を立てる」から既存作成画面へ遷移する。

## 3. 札詳細画面（`/market/listings/[id]`）

- 公開札（`visibility='PUBLIC'`）のみ表示。非公開/scope限定は **404**（存在秘匿）。
- 未ログイン: 連絡先・応募者個人名は非表示。応募ボタンは「`market.action.loginToApply` ログインして応募」に置換（F19.1 §8.4 準拠）。
- ログイン済み・応募可能者: 「`market.action.apply` 札に応じる」ボタン。
- 主催表示はチーム/組織の**公称名＋アイコン**のみ（PII抑制）。

## 4. 札立て導線（主体別の管理市）

公開市の「札を立てる」は個人市の作成フォームを開く。チーム/組織はそれぞれ `/teams/[slug]/market`・`/organizations/[slug]/market` の「札を立てる」から、主体を保持した recruitment 作成画面を開く。

### 4.1 入力負担の軽減
- **テンプレート**: 既存 `recruitment_templates`（F03.11）から「テンプレートから作成」。市独自テンプレは作らない。
- **前回地域の既定値**: 直近の自 scope 札の `prefecture_code`/`city_code` を初期選択。
- **チーム所在地の自動補完**: `teams.prefecture`/`teams.city`（文字列）→ `cities` マスタへ正規化候補を提示（完全一致時は自動選択、不一致時は候補ドロップダウン）。※正規化マッパは §8-7（teams側カラム正規化は別軍議、当面はマッパで吸収）。
- **履歴コピー**: 直近札の「複製して新規作成」。

### 4.2 フレンド宛非公開札の宛先セレクタ（3粒度・混在可）
`visibility='FRIEND_TEAMS_ONLY'` 選択時に表示。3 つの粒度を**混在指定**できる。
```
公開範囲: ( ) 市に公開   (•) フレンドチームのみ（非公開札）
  └ 宛先:
     [✓] すべての成立フレンド（ALL_FRIENDS）
     [✓] フォルダ指定:  [大分の仲間 ▾] [西部リーグ ▾]      （FOLDER・複数可）
     [✓] 個別に指定:    [別府FC ✕] [大分FC ✕] [+追加]        （TEAM・成立フレンドのみ候補）
```
- 「個別に指定」の候補は**成立済みフレンドのみ**を提示（未成立は出さない・誤指定防止 §8-3）。各チップに `[✕]` 削除ボタン。
- フォルダは札主チーム所有フォルダのみ。**重複選択は不可**（選択済みは候補から除外）。フォルダ選択数の上限は実装時に定義（目安10）。
- フレンドフォルダ未実装環境では「フォルダ指定」行を**非表示**（gating。01_data_model §4 依存関係）。

## 5. 通知文言（i18n）

| 場面 | キー | 例（ja） |
|---|---|---|
| 自分（チーム）の札に応募が来た | `market.notify.applicationReceived` | あなたの札に声がかかりました（別府FC / U-12練習試合） |
| フレンドから非公開札が届いた | `market.notify.friendListing` | 大分FCから「練習試合の相手募集」が届きました |
| 要件充足・最終認証のお願い | `market.notify.finalizeRequest` | 募集が定員に達しました。確定して札を下げますか？ |
| 締切前・要件未達の事前通知 | `market.notify.reminderShortfall` | 締切が近づいています。あと◯名の応募が必要です |
| 募集不成立（自動キャンセル） | `market.notify.autoCancelled` | 「{title}」は応募が集まらず締め切られました |
| 札が下げられた（手動・既応募者向け） | `market.notify.cancelledToApplicant` | 申し訳ありません。「{title}」は主催者により取り下げられました |

- 手動取下げ通知には**理由（`cancelled_reason`）とお詫び文**を含め、再応募導線（`market.notify.seeOtherListings`「{team}の他の札を見る」→ scope別一覧）を付す（§8 配慮）。

## 6. i18n 設計（6言語）

- 新規名前空間 **`market`** を新設：`frontend/app/locales/{ja,en,zh,ko,es,de}/market.json`（または既存 recruitment.ts に倣い `market.ts`）。
- `village`（村＝別概念）/`recruitment`（札の内部語彙）/`public`（公開導線）とは**責務分離**（混ぜない）。
- キーは**意味ベース**（直書き禁止・CLAUDE.md i18nルール）。**UIボタンは短語**、比喩（集市/장터/挂牌/방을 붙이다 等）は**見出し・空状態・ツールチップに限定**。
- `nuxt.config.ts` の i18n files 配列に `{locale}/market.json` を6言語分追加。
- **キー命名規約**: `action.*` は動詞（短語）、`notify.*` は文、`empty.*`/`visibility.*` は名詞/状態。意味ベースで統一（CIで命名一貫性を検査してもよい）。

### 6.2 地域名の多言語表示（既知の制約・Phase 2拡張）
`prefectures.name`（VARCHAR(10)）・`cities.name`（VARCHAR(20)）は**日本語名のみ**を持つ（F08.1 マスタ）。
- **Phase 1**: 地域名はマスタの日本語名をそのまま表示する（コード値での絞り込みは全言語で機能。地域名のみ日本語）。日本国内向けサービスとして許容。
- **Phase 2（拡張）**: マスタに `name_en` 等の訳列、または別途 i18n キー対応表を追加し、`GET /market/regions` のレスポンスをロケールに応じた名称で返す（`useMarketRegions` をロケール対応に拡張）。本制約は §04_security §3-16 に未解決→解決方針として記載。

## 7. 型定義（フロント）

- `frontend/app/types/market.ts` を新設（手動型）。`MarketListingResponse` / `MarketRegion` / `MarketSummary` / `FriendTargetInput`（`target_kind` + 任意 `folder_id`/`team_id`）。
- enum・カテゴリは i18n キー化（`name_key`）。生成型 `types/generated/index.ts`（API追加後に再生成）をラップする方針（recruitment.ts/village.ts 同様）。
- `any` 禁止・複雑な型パズル禁止（CLAUDE.md）。
