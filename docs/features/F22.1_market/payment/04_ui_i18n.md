# F22.1 市（Market）謝礼決済 — 04. 画面設計・i18n

> 親: [README.md](README.md) ／ 関連: [02_api_design.md](02_api_design.md) / [03_security.md](03_security.md)

> i18n 原則（CLAUDE.md）: UI 文字列は**直書き禁止**。`payment` / `market.payment` 名前空間に追加し `$t('key')` 参照。6言語（ja/en/zh/ko/es/de）に追加（未翻訳は ja 値で暫定可）。

## 1. 口座登録導線（Connect onboarding）

### 1.1 個人の口座登録
- **マイページ → 「謝礼の受取口座」** セクション（`/me/payment/payout-account` 想定）。
- 状態バッジ `<ConnectStatusIndicator>`: `未登録 / 登録中 / 受取可能 / 要対応 / 停止中`（`onboarding_status` に対応）。
- 「口座を登録する」ボタン → `POST /connect/onboarding-link`（scopeKind=USER）→ Stripe hosted onboarding へリダイレクト → return_url で着地し状態再取得。
- `RESTRICTED`（要対応）時は `requirements_due` を平易な文言で提示（「本人確認書類の提出が必要です」等）。

### 1.2 チーム/組織の口座登録
- **チーム/組織ダッシュボード → 「謝礼の受取口座」** セクション（scope ADMIN のみ表示）。
- 「チームの受取口座を登録する」→ `POST /connect/onboarding-link`（scopeKind=TEAM/ORG, scopeId）。
- 非 ADMIN には**セクションを表示しない**（認可・03 §3）。

## 2. 札立て時の謝礼設定 ＋ 受領主体選択 UI

札作成フォーム（チーム/組織ダッシュボード）に謝礼ブロックを追加（市から直接立てない原則・F22.1 本体 §2）。

- **「この札に謝礼を設定する」トグル**（`paymentEnabled`）。
- ON で展開:
  - **謝礼額** 入力（`price`・JPY 整数・円単位）。
  - **受領者を選ぶ** ラジオ（`payeeKind`）:
    - 「**個人が受け取る**」（USER）→ 受領者選択（札主チーム所属者から選ぶ・審判/助っ人本人）。例文「審判を担う個人が謝礼を受け取ります」。
    - 「**チームが受け取る**」（TEAM）→ 札主チームの受取口座へ。例文「遠征費などチームの活動費として受け取ります」。
    - 「**組織が受け取る**」（ORG）→ 組織の受取口座へ。
  - **受取口座の状態表示**: 選んだ受領主体の `connect/status` を即時取得。`payouts_enabled=false` なら**警告**「受取口座が未登録です。札は立てられますが、口座登録が完了するまで謝礼は確定（払出）されません」（02 §5.2・症状を隠さず案内）。
- ADHD 配慮（memory `user_adhd_tendency`）: 受領者は**既定で「個人＝自分」または「チーム」をプリフィル**し、入力摩擦を最小化。詳細は後から編集可能。

## 3. 応募時の謝礼提示（支払者側）

- **札詳細・応募ダイアログ**に「謝礼 ¥5,000」を明示。
- 応募確定で **Stripe Elements（カード直送・PCI SAQ-A・03 §1）** を表示し `clientSecret` で confirm。
- 「**いまは課金されません。最終認証（札の確定）時に確定します**」と**与信＝エスクロー**の説明文を必ず添える（誤解防止）。
- 与信成功で「応募が成立しました（謝礼は確定時にお支払い）」、与信失敗（カード拒否）で原因を提示（`PAYMENT_041`・握りつぶさない）。

## 4. 払出・返金の通知文言

| 契機 | 宛先 | 文言キー（例） |
|---|---|---|
| 与信成立 | 支払者 | `market.payment.notify.authorized` 「応募が成立しました。謝礼 {amount} は札の確定時にお支払いされます」 |
| 払出確定（capture） | 支払者・受領者 | `market.payment.notify.captured` 「謝礼 {amount} のお支払いが確定し、受取口座へ送金されました」 |
| 払出保留（HELD） | 札主・受領者 | `market.payment.notify.held` 「受取口座の登録が未完了のため謝礼が保留されています。72時間以内に登録してください」 |
| 保留期限切れで取消 | 支払者・札主 | `market.payment.notify.heldExpired` 「受取口座が未登録のため謝礼を確定できず、与信を取り消しました」 |
| 返金（全額/部分） | 支払者 | `market.payment.notify.refunded` 「謝礼 {amount} が返金されました（理由: {reason}）」 |
| 与信取消（札下げ） | 支払者 | `market.payment.notify.cancelled` 「札が取り下げられたため、謝礼の与信を取り消しました（課金はありません）」 |
| Connect 制限/停止 | 札主・受領者 | `market.payment.notify.accountRestricted` 「受取口座に対応が必要です。謝礼の受け取りには本人確認の完了が必要です」 |

> 通知は F04.9 確認通知 / F04.x 通知基盤に委譲（市で再実装しない）。

## 5. 共通コンポーネント（FE）

| コンポーネント | 役割 |
|---|---|
| `<ConnectStatusIndicator :status>` | Connect 口座状態バッジ（未登録/登録中/受取可能/要対応/停止中） |
| `<PayoutAccountSection :scope-kind :scope-id>` | 口座登録セクション（マイページ/ダッシュボード共通） |
| `<PaymentSettingsBlock v-model>` | 札立てフォームの謝礼設定ブロック（額＋受領主体ラジオ＋口座状態警告） |
| `<PayeeSelector v-model :scope-id>` | 受領主体選択（個人/チーム/組織・所属者ピッカー） |
| `<EscrowStatusBadge :escrow-id>` | エスクロー状態（与信中/保留中/確定済/返金済） |
| `<StripeCardElement @confirmed>` | Stripe Elements ラッパ（カード直送・clientSecret confirm） |

> `any` 禁止（CLAUDE.md）。型は `frontend/app/types/` に手動定義（生成型があれば優先）。
