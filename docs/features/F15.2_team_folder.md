# F15.2 チーム・組織フォルダ永続化機能

## 概要

ユーザーが所属するチームまたは組織を、自由に作成したカスタムフォルダに分類して管理する機能。
フォルダはユーザーごとに保持され、スコープタイプ（TEAM / ORGANIZATION）別に管理される。

### 主な仕様

- 1ユーザー × 1スコープタイプあたり最大20フォルダまで作成可能
- フォルダ名はユーザー × スコープタイプ単位で一意
- 1チーム/1組織（スコープ）は複数フォルダには属せない（1アイテム1フォルダ制約）
- 別フォルダへの追加時は自動的に旧フォルダから移動
- フォルダ削除はソフト削除。アイテムはDBのCASCADEでハード削除される
- フォルダの並び順は手動で変更可能

## DBスキーマ

### my_scope_folders テーブル

| カラム名   | 型              | 制約                | 説明                          |
|----------|----------------|---------------------|-------------------------------|
| id       | BIGINT         | PK, AUTO_INCREMENT  | フォルダID                    |
| user_id  | BIGINT         | NOT NULL, FK→users  | 所有ユーザーID                |
| scope_type | VARCHAR(20)  | NOT NULL            | TEAM または ORGANIZATION      |
| name     | VARCHAR(100)   | NOT NULL            | フォルダ名                    |
| color    | VARCHAR(7)     | NULL                | HEXカラーコード（#RRGGBB）    |
| sort_order | INT          | NOT NULL DEFAULT 0  | 表示順序                      |
| created_at | DATETIME(6)  | NOT NULL            | 作成日時                      |
| updated_at | DATETIME(6)  | NOT NULL            | 更新日時                      |
| deleted_at | DATETIME(6)  | NULL                | 論理削除日時（NULL=有効）     |

**インデックス:** `idx_msf_user_scope (user_id, scope_type, deleted_at)`
**Flyway:** `V9.100__create_my_scope_folders.sql`

### my_scope_folder_items テーブル

| カラム名   | 型           | 制約                         | 説明                            |
|----------|-------------|------------------------------|--------------------------------|
| id       | BIGINT      | PK, AUTO_INCREMENT            | アイテムID                      |
| folder_id | BIGINT     | NOT NULL, FK→my_scope_folders | 所属フォルダID                  |
| scope_id | BIGINT      | NOT NULL                     | チームIDまたは組織ID             |
| sort_order | INT       | NOT NULL DEFAULT 0           | フォルダ内表示順序               |
| created_at | DATETIME(6)| NOT NULL                   | 作成日時                        |

**一意制約:** `uq_msfi_folder_scope (folder_id, scope_id)`
**インデックス:** `idx_msfi_folder (folder_id)`
**Flyway:** `V9.101__create_my_scope_folder_items.sql`

## APIエンドポイント一覧

ベースURL: `/api/v1/me/scope-folders`

| メソッド | パス                               | 説明                                             |
|---------|-----------------------------------|--------------------------------------------------|
| GET     | `/`                               | フォルダ一覧取得（?scopeType=TEAM&#124;ORGANIZATION） |
| POST    | `/`                               | フォルダ作成（?scopeType=...）                    |
| PUT     | `/reorder`                        | フォルダ並び替え（?scopeType=...）                |
| PUT     | `/{folderId}`                     | フォルダ更新                                     |
| DELETE  | `/{folderId}`                     | フォルダ削除                                     |
| POST    | `/{folderId}/items`               | アイテム追加                                     |
| DELETE  | `/{folderId}/items/{scopeId}`     | アイテム削除                                     |

### レスポンス形式（ScopeFolderResponse）

```json
{
  "id": 1,
  "name": "お気に入りチーム",
  "color": "#FF6B6B",
  "sortOrder": 0,
  "itemScopeIds": [101, 202, 303]
}
```

`itemScopeIds` はチームID / 組織IDのリスト。フロントエンドはストア（`useTeamsStore` / `useOrganizationsStore`）から詳細情報をenrichする。

### リクエスト形式

**CreateFolderRequest / UpdateFolderRequest**
```json
{
  "name": "お気に入りチーム",
  "color": "#FF6B6B"
}
```

**ReorderFoldersRequest**
```json
{
  "orderedIds": [3, 1, 2]
}
```

**AddFolderItemRequest**
```json
{
  "scopeId": 101
}
```

## セキュリティ設計

### 認証

全エンドポイントは `SecurityUtils.getCurrentUserId()` によるJWT認証が必須。

### IDOR防止

`folderRepository.findByIdAndUserIdAndDeletedAtIsNull(folderId, userId)` で必ず自分所有のフォルダかを確認。他ユーザーのフォルダIDを指定しても `SCOPE_FOLDER_NOT_FOUND (404相当)` を返す（存在有無を漏らさない）。

### スコープ所属確認

アイテム追加時（`addItem`）に `UserRoleRepository` で以下を確認:
- TEAM の場合: `existsByUserIdAndTeamId(userId, scopeId)`
- ORGANIZATION の場合: `existsByUserIdAndOrganizationId(userId, scopeId)`

所属していない場合は `SCOPE_FOLDER_NOT_MEMBER` を返す。

### エラーコード（ScopeFolderErrorCode）

| コード                      | 説明                                 |
|----------------------------|--------------------------------------|
| SCOPE_FOLDER_NOT_FOUND     | フォルダが存在しない / 他ユーザーのフォルダ |
| SCOPE_FOLDER_ACCESS_DENIED | アクセス権限なし（予備）              |
| SCOPE_FOLDER_LIMIT_EXCEEDED | フォルダ上限（20件）超過            |
| SCOPE_FOLDER_NAME_DUPLICATE | 同名フォルダが存在                  |
| SCOPE_FOLDER_NOT_MEMBER    | 指定スコープに所属していない          |

## フロントエンドとの接続方法

### API呼び出し

フロントエンドは `Authorization: Bearer <JWT>` ヘッダーで認証して各エンドポイントを呼ぶ。

### データの利用方法

1. `GET /api/v1/me/scope-folders?scopeType=TEAM` でフォルダ一覧（`itemScopeIds` 付き）を取得
2. `useTeamsStore` の所属チーム一覧と `itemScopeIds` を突き合わせて詳細情報をenrich
3. フォルダ内チームの詳細情報はストアのキャッシュから参照（APIは追加コールしない）

### フォルダ操作のUXフロー

- フォルダ作成: モーダルで名前・色を入力 → `POST /api/v1/me/scope-folders?scopeType=TEAM`
- フォルダにチームを追加: ドラッグ＆ドロップまたはコンテキストメニュー → `POST /{folderId}/items`
- フォルダの並び替え: ドラッグ＆ドロップ後 → `PUT /reorder?scopeType=TEAM`
- フォルダ削除: 確認ダイアログ → `DELETE /{folderId}`

### 注意事項

- `scopeType` クエリパラメータは大文字・小文字を区別する（`TEAM` / `ORGANIZATION`）
- `color` フィールドは `#RRGGBB` 形式（7文字）。null可
- フォルダ削除時、アイテムはDBのCASCADE設定で自動削除されるため、フロントエンドでの個別削除呼び出しは不要
- `itemScopeIds` の順序は `sort_order` 昇順
