## 1. 共通契約

以下のpathは `/api/v1` 配下。認証必須、認証方法とCookie/refreshは既存基盤を使用し変更しない。JSONはcamelCase、queryはsnake_case、enumはUPPER_SNAKE_CASE。IDは新規UUIDをハイフン付き小文字文字列、既存user/team/organization/templateのBIGINTを既存契約どおりJSON整数で扱う。ownerUserIdは入力させず認証主体から決定。未知のfield key、重複field key、未知enum、値の型不一致は400。

成功は `ApiResponse<T>={"data":T}`、一覧は `CursorPagedResponse<T>={"data":[T],"meta":{"nextCursor":null,"hasNext":false,"limit":20}}`。削除/取消も200 `{"data":{"id":"UUID","version":2,"state":"REVOKED"}}` とし、204やsuccessフラグを混在させない。エラーは `{"error":{"code":"COMMON_001","message":"...","fieldErrors":[{"field":"values.duration","message":"..."}]}}`。fieldErrorsは検証失敗だけの任意項目。

nullableは明記した項目だけnullを許可する。レスポンスではnullable項目も省略せずnull、配列は空配列。書込は全置換PUTであり、任意値削除は明示null、required項目省略不可。日時はInstant由来のISO8601 UTC `2026-11-08T03:00:00Z`、日付は `YYYY-MM-DD`、TZはIANA文字列。数値入力・出力は固定小数の10進文字列（例 `"30.00"`）、ID/version/countは整数。FEは表示前のchart描画だけNumberへ変換し、集計や永続値は再計算しない。

一覧queryは `date_from` / `date_to`（両端包含、対で指定）、`definition_uuid`（任意UUID）、`cursor`（任意）、`limit`（既定20、1〜100）。未指定期間は全期間の履歴をcursorで読む。未知queryは400。順序はrecordedOn DESC, createdAt DESC, id DESC。cursorはこの組＋filter hash＋認証scopeをAES-GCMで暗号化・認証したopaque文字列（scope/filterもAADへ束縛）、最大2048字。有効期限24時間、改竄/別filter/別scope/期限切れは400。次ページにも同じfilterを送る。スナップショット一覧ではないため途中編集の重複はUUIDでFEが排除し、再読込で最新へ戻す。

## 2. 型

```ts
// UUID/Date/Instant/Decimalは上記形式のstring。
type FieldValue = { fieldKey: string; value: string | null }
type FieldDefinition = {
  fieldKey: string; label: string; labelKey: string | null;
  type: 'NUMBER' | 'TEXT' | 'SELECT' | 'DATE' | 'DATETIME' | 'CHECKBOX'; required: boolean;
  semantic: 'DURATION' | 'WEIGHT' | 'INTENSITY' | 'SUBJECT' | 'MENU' | 'NUMBER' | 'TEXT' | 'DATE' | 'DATETIME' | 'CHECKBOX';
  unit: string; aggregation: 'SUM' | 'LATEST' | 'NONE'; scale: number; min: string | null; max: string | null;
  options: { key: string; label: string; labelKey: string | null }[];
}
type DefinitionSnapshot = {
  definitionUuid: string; revision: number;
  source: 'PRESET' | 'TEAM'; presetCode: string | null;
  teamTemplateId: number | null; templateName: string;
  durationFieldKey: string | null; subjectFieldKey: string | null;
  fields: FieldDefinition[];
}
type OwnerShare = {
  id: string; teamId: number; state: 'PENDING' | 'VISIBLE' | 'FAILED' | 'REVOKED' | 'MODERATED';
  version: number; sourceVersion: number; selectedFieldKeys: string[];
  lastErrorCode: string | null; updatedAt: string;
}
type OwnerRecord = {
  id: string; version: number; contentRevision: number; recordedOn: string; recordTimezone: string;
  definition: DefinitionSnapshot; values: FieldValue[]; privateNote: string | null;
  share: OwnerShare | null; createdAt: string; updatedAt: string;
}
type SharedRecord = {
  id: string; version: number; teamId: number;
  author: { userId: number; displayName: string; avatarUrl: string | null };
  recordedOn: string; recordTimezone: string;
  definitionUuid: string; templateName: string;
  fields: { fieldKey: string; label: string; type: 'NUMBER' | 'TEXT' | 'SELECT' | 'DATE' | 'DATETIME' | 'CHECKBOX';
    semantic: string; unit: string; value: string | null; displayValue: string | null }[];
  createdAt: string; updatedAt: string;
  interactions: { canLike: false; canMitayo: false; canComment: false;
    canReply: false; canQuote: false; canRepost: false };
}
```

文字列は文字数上限を親設計で定め、fieldKeyは `[a-z][a-z0-9_]{0,63}`、unitは最大32字。SELECTのvalueはoption key、NUMBERは小数2桁以内（整数semanticは小数部0のみ）、TEXTは文字列。labelKeyは標準プリセットのみ非null。SharedRecord.fieldsはallowlistの定義順だけ、私的IDやnoteを含まない。共有authorは既存プロフィール可視性を適用し、非公開情報を足さない。既存profileが非表示なら許可された匿名表示を使う。

## 3. 個人API

| Method / path | 入力・成功 | 認可 |
|---|---|---|
| GET `/effort-records/me/presets` | queryなし。200 data: DefinitionSnapshot[]（標準3種） | 認証本人、所属不要 |
| POST `/effort-records/me/definition-snapshots` | `{teamId:number,teamTemplateId:number}`。200 `{definition:DefinitionSnapshot,definitionToken:string,expiresAt:string}` | 現在所属＋TEAM templateのscopeId一致。廃止は409 |
| POST `/effort-records/me` | 下記Create。201 OwnerRecord | 本人。TEAM定義なら現在所属・同チーム定義を再検証 |
| GET `/effort-records/me` | 共通一覧query。200 cursor OwnerRecord[] | owner束縛 |
| GET `/effort-records/me/{id}` | queryなし。200 OwnerRecord | owner束縛、不在/他人404 |
| PUT `/effort-records/me/{id}` | 下記Update。200 OwnerRecord | owner束縛、version一致 |
| DELETE `/effort-records/me/{id}` | 必須query `version` 非負整数。200 `{id,version,state:'DELETED'}` | owner束縛 |
| GET `/effort-records/me/stats` | §5 query。200 Stats | owner束縛 |

Createは `{recordedOn,recordTimezone,definitionUuid,definitionRevision,definitionToken,values,privateNote}`。definitionTokenはPRESETのみnull可。TEAMではsnapshot APIの10分有効署名tokenを必須とし、organizationId/teamId/definitionUuid/revision/hash/本人IDを束縛する。serverはtoken検証後に指定organization shardのServiceを1回呼び、総当たり検索しない。privateNoteはnull可、他は必須。snapshot自体やowner IDをクライアントから受け取らない。serverがdefinitionUuid/revisionを取得し同一snapshotを保存する。definition-snapshots APIはチーム定義の不変revisionを登録・返すための操作で、原本を作らず個人一覧にも出ない。標準はpresets応答をそのまま指定する。

Updateは `{version,recordedOn,values,privateNote}`。definition/recordTimezoneの変更不可。versionは非負整数、成功時1以上増加。snapshotに存在する全fieldをvaluesへ渡し、任意未入力はnull。削除済みは404。共有済み原本の更新は、現在の共有先所属者なら既存allowlistで同期要求を新versionへ更新し202ではなく200 OwnerRecord（share.state=PENDING）を返す。非所属ならprivate更新は成功するが共有の更新は行わず、旧共有をどう扱うかは親設計§4.1の裁可に従う（裁可まで実装不可）。

`@SelfScopedEndpoint` はscope IDを受け取らない本人一覧/詳細/保存/集計だけ候補とし、Controller#methodを名指す契約ITを付ける。teamId/templateIdを受け取るsnapshot/共有APIへ流用しない。

## 4. 共有API・チームAPI

previewは永続済み原本のUUIDを必須とする。初回画面の「保存して共有内容を確認」は、明示的な個人保存POST成功後に返却UUID/versionでpreview POSTを呼ぶ。最終previewの「この内容を共有」で初めて共有PUTを呼ぶ。previewを閉じる/期限切れ/取得失敗でも保存済み原本は残り、共有は発生しない。既存原本は同じUUIDへのPUT（変更がある場合だけ）→preview→共有PUTとし、原本を複製しない。具体的なボタンとAPI呼順は[親設計§2.1](F06.4.1_personal_effort_records.md#21-初回保存と共有確認のapi順序)に従う。

| Method / path | 入力・成功 |
|---|---|
| POST `/effort-records/me/{id}/team-share/preview` | `{version,teamId,definitionToken,mappings,selectedFieldKeys}` →200 `{previewToken,expiresAt,recordVersion,contentRevision,definitionRevision,projection:SharedRecord}`。previewのidは予約share UUID、version0 |
| PUT `/effort-records/me/{id}/team-share` | `{version,previewToken}` →202 OwnerRecord（PENDING）。同じshareを再利用 |
| POST `/effort-records/me/{id}/team-share/retry` | `{version,shareVersion}` →202 OwnerRecord。FAILEDまたは60秒超PENDINGのみ。token再利用で内容変更不可 |
| DELETE `/effort-records/me/{id}/team-share` | query `version`, `share_version` 必須 →200 OwnerRecord（REVOKED） |
| GET `/teams/{teamId}/effort-records` | 共通一覧query＋`user_id`（任意既存ID）→200 cursor SharedRecord[] |
| GET `/teams/{teamId}/effort-records/{shareId}` | queryなし →200 SharedRecord |
| DELETE `/teams/{teamId}/effort-records/{shareId}` | query `version` 必須 →200 `{id,version,state:'MODERATED'}` |

preview/共有/retryは本人原本ownerを確認し、現在の所属、TEAM templateの所属一致、共有先TEAM定義tokenのteam一致、有効revisionを検証する。原本定義と共有定義は異なってよい。原本1件から選んだTEAM定義へ共有専用mappingを行い、原本や個人集計の行を増やさない。mappingsは `{targetFieldKey:string,sourceFieldKey:string|null,valueOverride:string|null}[]`。同一semantic/unit/typeのsourceだけ候補として値を引き継ぎ、本人が確認する。sourceFieldKeyとvalueOverrideの同時指定は拒否し、単位変換や未知の意味の推測はしない。target必須の不足は共有画面でvalueOverrideとして入力し共有設定だけへ保存する。任意不足はnull。selectedFieldKeysはtarget keyのallowlist。target必須値は未選択でも入力検証するが、非選択値をprojectionへ含めない。元の私的noteはmapping元にできない。既に別teamの有効shareがあれば409。

previewTokenは10分有効の署名opaque、owner/record/contentRevision/team/共有definition revision/mapping/allowlist/projection hash/share UUIDを束縛する。previewはDBへ共有を作らず、通常再表示も公開しない。投稿までに原本contentRevision/共有定義/所属が変化したら409・再preview。定義revisionの比較は同一TEAMテンプレートの変更検知に使い、既存recordのsnapshotを書換えない。共有値はserverが許可項目だけから確定する。tokenをquery/log/localStorageに保存しない。

本人取消は脱退後でもowner照合で許可し、現在所属を必須にしない。チーム一覧/詳細はteamの現在所属とF00を両方確認。非所属403、organization/team不一致・別team share UUIDは404。user_idが他teamの人でも存在を推測する検証エラーを返さず該当なし。管理者非表示は既存のチーム管理者権限判定を使用（ADMIN、既存テンプレート管理権限を正規に委任されたDEPUTY_ADMIN）。MEMBERは他人のshareを削除不可。SYSTEM_ADMINもチーム可視性をバイパスしない。

チーム履歴のテンプレート候補は既存有効TEAM templateに、履歴内に存在する廃止済みdefinitionを追加して選べるようにする。候補専用API `GET /teams/{teamId}/effort-records/definitions` は200 data:`{definitionUuid,templateName,isRetired:boolean}[]`、現在所属認可、当該teamでVISIBLEな履歴があるものだけ返す。これは一覧/{shareId}より先にroute解決する。

### 4.1 冪等性と応答消失

POST create、PUT share、POST retry、DELETE owner/share/moderationに `Idempotency-Key` UUID必須。scopeは認証主体＋HTTP method＋path、request hashにbody/query/versionを含める。同じkey/同じhashは24時間、同じstatus/bodyを返す（完了後の再送でも重複書込なし）。同じkey/異なるhashは409 COMMON_003。進行中同keyは409で `Retry-After: 1`、FEは自動別keyへ変更しない。owner UUID/versionを含むためteam境界でkeyが衝突しない。

原本PUTはversionによる重複検知とする。応答消失後に同じversionで再送すると409、GETで保存結果を比較してUIを回復する。共有202後はGET ownerを手動更新または最大5秒間隔・画面可視時のみ取得し、30秒で自動取得を止め「確認」を表示する。60秒未満PENDINGのretryは409、60秒経過後PENDINGまたはFAILEDでは明示再試行ボタンを表示する。FAILEDは明示retryだけ、ネットワーククライアントの無条件POST再送をしない。DELETE取消は許可失効をowner TXで確定してから200を返すため、team後処理を待たない。

## 5. 集計API

必須query `date_from`,`date_to`,`definition_uuid`,`field_key`,`chart`（BAR/LINE/PIE）。任意`grain` DAY/MONTH（省略時親設計の期間規則。DAYは62日以下、MONTHは366日以下）。chartとsemanticが不適合なら400。PIEは対応durationFieldKey指定が必須で、SUBJECT対応がない定義は400。filter値をレスポンスへechoし、rangeの端数月は指定期間内だけ集計する。

```ts
type Stats = {
  definitionUuid: string; fieldKey: string; unit: string; semantic: string;
  chart: 'BAR' | 'LINE' | 'PIE'; grain: 'DAY' | 'MONTH';
  dateFrom: string; dateTo: string; totalSampleCount: number;
  buckets: { startOn: string; endOn: string; value: string | null; sampleCount: number }[];
  categories: { key: string; label: string; value: string; sampleCount: number }[];
  total: string | null; emptyReason: 'NO_DATA' | 'ZERO_TOTAL' | null;
}
```

BAR/LINEはbucketsを空白bucket含め昇順に返しcategories=[]。PIEはbuckets=[]、categoriesを値降順/key昇順、null数値は分母に含めない。BAR totalはSUM、LINE totalはnull、PIE totalはduration SUM。全データなしはtotal=null/NO_DATA。BAR/PIEの0記録ありだけtotal="0.00"/ZERO_TOTAL、LINEは値が0でもtotal=null/emptyReason=null。sampleCountは数値が非nullの記録件数。SELECT未指定はreserved subject keyで集約する。

## 6. エラー割当

`EFFORT` は実装時に全ErrorCode prefix重複を再検索する。新規採番は「現在の最大＋1で予約、確定はマージ時に再確認」とし、以下001〜005は設計上の予約。COMMONのHTTP割当もGlobalExceptionHandlerへ明示登録する。

| code | HTTP / Severity | 条件 |
|---|---|---|
| COMMON_001 | 400 / WARN | 型/範囲/桁/上限/空allowlist/不正cursor/非対応chart |
| COMMON_002 | 403 / WARN | チーム非所属/管理権限なし |
| COMMON_003 | 409 / WARN | version/preview失効/key不一致/別team共有/状態競合 |
| EFFORT_001 | 404 / WARN | 原本不在/他人/共有不在/別tenant（区別しない） |
| EFFORT_002 | 409 / WARN | template廃止・revision変更で新規共有不可 |
| EFFORT_003 | 403 / WARN | 努力由来sourceへのlike/mitayo/comment/reply/quote/repost/通常本文更新 |
| EFFORT_004 | 503 / ERROR | F00/source照会障害。詳細・一覧とも取得失敗とし、障害を空一覧に置換しない |
| EFFORT_005 | 503 / ERROR | 共有処理インフラ障害で要求を保存できない（保存済み原本は残る） |

無認証は既存認証基盤の401。タイムライン・共有一覧ではdeny対象を件数/previewで漏らさず、hasNext/nextCursorは走査継続位置を返す（非表示行だけの空pageでも次cursorを返せる）。1回の走査上限は1000行。全てdenyでも暗号化した継続位置で空page＋hasNext=trueを返し、次の有限走査へ進める。非表示IDや値をtokenから推測できない。F00障害を「0件」として成功表示することはしない。

### 5.1 グラフ許可表と画面対応

| semantic | BAR | LINE | PIE |
|---|---|---|---|
| DURATION | SUM | 不可 | SUBJECT対応ありの時間内訳のみ |
| WEIGHT | 不可 | 日/月内のcreatedAt,id最新 | 不可 |
| NUMBER | snapshotでaggregation=SUMのときのみ | 不可 | 不可 |
| INTENSITY/SUBJECT/MENU/TEXT/DATE/DATETIME/CHECKBOX | 不可 | 不可 | 不可 |

週/月ボタンはDAY、年はMONTH、任意は62日以内DAY・それ以外MONTHを送る。手動grainを変えるUIは今回作らない。APIにも同じ上限を適用する。DATE値はYYYY-MM-DD、DATETIMEはオフセット必須ISO8601（UTC正規化）、CHECKBOXは文字列true/falseまたは任意null。TEXTAREAはTEXTへ正規化し、未知型はsnapshot作成時400で拒否する。

## 7. 管理者の指標設定と既存型互換

既存activity templateへsemantic等が存在すると仮定しない。チームテンプレート編集画面へ「個人の頑張り記録の指標」セクションを追加し、既存fieldごとにsemantic/unit/aggregationを設定する。duration↔subject対応は各1項目だけ選択する。設定しないテンプレートも共有に使えるが、数値はNUMBER/NONEとして個人集計対象外とする。個人の独自定義作成や式エディタは追加しない。

`GET /teams/{teamId}/effort-records/template-settings/{templateId}` →200 `{version,definition:DefinitionSnapshot}`。`PUT` 同path、body `{version,fields:[{fieldKey,semantic,unit,aggregation}],durationFieldKey:string|null,subjectFieldKey:string|null}` →200 同型。両方、既存TEAMテンプレート管理権限＋templateのscope一致。MEMBERは403、他tenantは404。PUTは全field設定を要求し、未知key/重複/互換しないsemantic（TEXTへWEIGHT等）/対応の二重指定は400、version競合409。設定保存先はeffort_definition_revisions.definition_jsonで、activityテンプレートの既存列へ勝手に属性を追加しない。min/max/scaleはsemanticの固定規則からserverが決定し、管理者の任意設定にしない。

NUMBER→NUMBER、TEXT/TEXTAREA→TEXT、SELECT→SELECT、DATE→DATE、DATETIME→DATETIME、CHECKBOX→CHECKBOX。型がない/未知型/複合値は400（COMMON_001、該当fieldKey付き）。DATE/DATETIME/CHECKBOXと自由TEXTはaggregation=NONE。SUBJECTはSELECTまたはTEXT、DURATION/WEIGHT/INTENSITYはNUMBERだけ。MENUはTEXTだけ。NUMBERは管理者が明示SUMを選んだ場合だけ合計可、unitは空不可（無単位はNONE）。共有値の型を適合させられない場合は保存前にエラーを示す。

snapshot APIは毎回activity ServiceからTEAM template全定義を取得し、field ID/key/type/label/options/required/順序をcanonical JSON hashに含め、effort指標設定と合わせたhashを現在revisionと比較する。異なれば同じdefinitionの新revisionを同一effort TXで発行する。activity更新イベントがあればretired/changedを先行反映するが、イベントに依存せずpreview投稿時にactivity Serviceの現在hashを再検証し、定義変更の取りこぼしを防ぐ。廃止はその確認で新規共有不可。既存snapshotの編集/個人集計はactivity照会に依存させない。
