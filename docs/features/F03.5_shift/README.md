## 1. 概要

管理者が週/月単位のシフト表を作成・編集・確定・公開し、メンバーが希望日時を事前に提出できるシフト管理機能。希望収集フェーズで全メンバーの希望を一覧化した上で管理者がシフトを確定し、確定後はメンバーへプッシュ通知を配信、個人ダッシュボードに自動反映する。スタッフ別・日付別の一覧表示に加え、ポジション（役割）別のスロット管理に対応し、整骨院・飲食店・美容室・ジム等の実店舗運営に必要なシフト管理を実現する。

> ⚠️ **【最重要】自動割当結果は必ず管理者が目視確認し、承認してから公開すること**
>
> 自動割当アルゴリズムは便利だが万能ではない。下記のようなシステム外の文脈は拾えないため、**管理者による最終目視確認が必須**である。
>
> - **希望の背景事情**: 「介護で17時退勤が望ましい」「受験直前のため短時間希望」等、フリーテキスト（`note`）欄にしか書かれていない情報
> - **人間関係・配置配慮**: 「A さんと B さんは同時間帯を避けたい」「C さんには必ず先輩をペアにする」等、システム外の文脈
> - **季節要因・突発イベント**: 繁忙期・祭事・臨時休業予定・大型予約の入り具合
> - **スキル・資格のバランス**: 有資格者（整体師免許・食品衛生責任者・アルコール販売責任者等）が各時間帯に最低1人いるか
> - **新人教育のペアリング意図**: 新人と指導役を必ず同枠にする、逆に自立期にはあえて分けて独り立ちさせる等
>
> フロー上の担保として、`ADJUSTING → PUBLISHED` 遷移時には「目視確認済み」同意ボタンを押さないと公開できない（§5 §8 参照）。

v2 では以下を拡張する:
- **5段階の希望強度**（出勤希望 / 指定なし / 出れなくはない / できれば休み / 絶対休み）。管理者が希望の強弱を細かく把握できるようにし、自動割当アルゴリズムの判断材料とする
- **時間帯分割スロット**（同一日に複数スロットを定義し、時間帯ごとに必要人数を設定。例: 11-15 時 = 3 人、15-18 時 = 2 人）
- **自動割当（オートアサイン）**（Strategy パターンで抽象化し、MVP は貪欲法。将来 CSP ソルバへ差し替え可能）
- **任意の勤務制約**（月次労働時間上限・連続勤務日数上限・勤務間隔・夜勤上限をメンバー単位で設定可能）
- **D&D シフト編集 UI**（`vuedraggable` ベースのマトリクス編集）
- **希望提出リマインド強化**（24h/48h 前の段階通知、提出率ベースのアラート）

v2.1 では以下を追補する:
- **シフト変更依頼 3 パターン**:
  - (A-1) **確定前の変更依頼**（`DRAFT / COLLECTING / ADJUSTING` 中に作成者＝管理者へ「この日の割当を変えてほしい」等を依頼する新テーブル `shift_change_requests`）
  - (A-2) **公開後・個別交代依頼**（既存 `shift_swap_requests` の 1 対 1 指名パターン）
  - (A-3) **公開後・全体募集**（オープンコール。`shift_swap_requests.is_open_call = TRUE` + `target_user_id = NULL` でチーム全体へ broadcast、先着手挙げ方式）
- **自動割当結果の目視確認必須化**: `shift_assignment_runs` に `visual_review_confirmed_by` / `visual_review_confirmed_at` を追加し、公開時に同意ボタン押下を必須化。監査ログ `SHIFT_SCHEDULE_VISUAL_REVIEW_CONFIRMED` を記録

v2.2 では以下を追補する:
- **シフト表PDF出力**: `GET /api/v1/shifts/schedules/{id}/pdf` を新設。`layout=team`（マトリクス）/ `layout=personal`（個人タイムライン）の 2 パターンを提供し、紙運用施設（整骨院・飲食店・美容室・ジム等）での掲示・配布・個人への手渡しを支援。F12.1 PDF 生成共通基盤を使用した**同期生成**、Flyway マイグレーションは不要（監査ログ `SHIFT_PDF_EXPORTED` を `audit_logs` 既存テーブルに追加するのみ）。SUPPORTER は PDF 出力不可（情報二次配布リスクで画面閲覧と権限を分離）。未公開状態 PDF は ADMIN のみ「内部確認用」ウォーターマーク付で出力可

## 2. スコープ

### 対象ロール
| ロール | 操作可能な範囲 |
|--------|--------------|
| SYSTEM_ADMIN | 全チームのシフト参照 |
| ADMIN | シフトスケジュールの CRUD・公開・確定・スロット管理・希望一覧参照・統計閲覧・**【v2】自動割当実行/確定/破棄・勤務制約管理・D&D 割当操作**・**【v2.1】変更依頼の審査（承認/却下）・目視確認承認・オープンコール候補選定**・**【v2.2】チーム全体のシフトPDF出力（確定版・内部確認用ウォーターマーク版）・任意メンバーの個人シフトPDF出力** |
| DEPUTY_ADMIN | `MANAGE_SHIFTS` 権限を持つ場合: シフトスケジュールの CRUD・公開・確定・スロット管理・希望一覧参照・統計閲覧・**【v2】自動割当実行/確定/破棄・勤務制約管理・D&D 割当操作**・**【v2.1】変更依頼の審査（承認/却下）・目視確認承認・オープンコール候補選定**・**【v2.2】チーム全体のシフトPDF出力・任意メンバーの個人シフトPDF出力**。自分自身が割り当てられた枠については MEMBER と同様に変更依頼・交代依頼も作成可能 |
| MEMBER | 希望シフトの提出（**【v2】5段階の希望強度**）・編集・取り下げ。確定シフトの閲覧。シフト交代リクエストの作成・引き受け。デフォルト可否プロファイルの管理。**【v2】自分の勤務制約の閲覧**。**【v2.1】確定前の変更依頼作成（自分に関する範囲）・公開後のオープンコール作成/手挙げ**・**【v2.2】自分の個人シフトPDFのみ出力可** |
| SUPPORTER | 確定シフトの閲覧のみ（希望提出不可・変更依頼/交代依頼不可・**【v2.2】PDF 出力不可**: 情報の二次配布リスクを避けるため。紙/PDF 配布は ADMIN / DEPUTY_ADMIN / 本人のみ） |
| GUEST | 対象外 |

### 対象レベル
- [ ] 組織 (Organization)
- [x] チーム (Team) — シフトの作成・管理
- [x] 個人 (Personal) — 希望提出・確定シフトの確認
