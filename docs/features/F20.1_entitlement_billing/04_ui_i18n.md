### U-1 プラン一覧

- 3 カラムのプランカード（FREE / BASIC / FULL）。各カードに月額（**未定のプランは「価格はベータ終了後に決定」バッジ**）・機能リスト（`FeatureItem.displayNameKey` を `$t()` 解決）・現在プランのハイライト。
- **BASIC カードの表示可否（L-2）**: BASIC は構成・価格ともに R-3 未確定。**R-3 確定までは BASIC カードを「準備中」表示（CTA 無効・機能リスト非表示）**とする（推奨）。または `plans.enabled=false` で完全非表示にする運用も可（マスタ側で切替）。中身が空のカードを「選べるプラン」として出さない（誤契約防止）。
- チーム/組織文脈で開いた場合は人数バンド表を折りたたみ（`<details>` 相当）で段階開示。
- CTA: 「このプランにする」→ 確認モーダル（現在→新プランの差分機能を明示）→ `POST .../billing/contracts`。

### U-2 ペイウォールモーダル（402 ハンドリング）

- API が `ENTITLEMENT_003`(402) を返した際に共通ハンドラで発火。`details`（featureKey / addonAvailable / addonPriceJpy / plansContaining）から描画:
  - 機能名・説明（i18n キー解決）
  - 選択肢カード: 「アドオンで追加（¥300/月 想定）」「FULL プランにまとめる」
  - CTA は 1 画面 1 主行動（ADHD 原則）。詳細比較は U-1 へのリンクで段階開示。
- **ベータ中の 402 体験＝「ワンクリック無償契約」導線（L-1）**: ベータ期間は実額が未定で無償（`priceJpySnapshot=null`）。ここで「¥300/月」等の価格を出すと「無料と言いつつ購入モーダル」の矛盾になる。よって**ベータ中は価格を出さず、モーダルの主 CTA を「無料で有効にする」1 ボタン**にし、押下で即 `POST .../billing/contracts`（ADDON または FULL）を無償契約＝その場で機能解放する（決済ステップなし）。ベータ終了後（価格確定後）に初めて価格表示＋決済導線へ切り替える（Phase 2）。この分岐は `plan.baseMonthlyPriceJpy==null` / `addonPriceJpy==null`（未定＝ベータ中）で判定。
- **FE はこのモーダルを出すだけで機能を解放しない**（BE ゲートが正・03 §4。ワンクリック契約も BE の契約 API を必ず経由し、権利は entitlements 行で発行される）。

### U-3/U-4/U-5 課金管理

- 現在の契約（プラン・アドオン・開始日・ベータ無償バッジ）・有効機能一覧（`EntitlementSummaryResponse`）。

- 操作: プラン変更・アドオン追加/解約・解約（確認ダイアログ・破壊的操作は赤系）。
- 権利サマリの閲覧はメンバーにも許可（U-3/U-4 の読み取り専用ビュー）。操作ボタンは ADMIN のみ表示（BE 認可と一致）。

## 3. i18n（`billing.json` 新設・6 言語）

- **新設ファイル**: `frontend/app/locales/{ja,en,zh,ko,es,de}/billing.json`（6 言語すべて。未翻訳は暫定で日本語と同値可）。
- **nuxt.config への登録が必須**: `i18n.locales[].files` 配列の各言語に `billing.json` を追加しないと読み込まれない（memory `project_i18n_locale_file_registration_required`・JSON が存在するだけでは効かない）。現状 `nuxt.config.ts` の `files` は各言語 `common.json`/`auth.json`/`validation.json`/`landing.json` を列挙（実確認）。ここへ `{lang}/billing.json` を 6 言語分追加する。
- **キー格納形の確定（⑤・origin/main 実挙動を確認して確定）**: 実ファイルの慣習は「**各ロケールファイルはトップレベルに名前空間キーを持ち、それが `$t()` の前置になる**」である（実確認: `landing.json` は `{ "landing": { … } }` で `$t('landing.hero.badge')`／`common.json` は `{ "chat": …, "button": … }` で `$t('button.save')`／唯一 `validation.json` だけが裸キー `{ "required": … }` で `$t('required')`）。
  - よって **`billing.json` はトップレベルを単一の `billing` キーでラップ**し（`landing.json` と同型・feature スコープファイルの標準形）、参照は **`$t('billing.plans.full.name')`** とする。
  - **DB 格納形の確定**: `feature_catalog.display_name_key` / `description_key`・`plans.display_name_key` 等には**フルパス（`billing.` 前置を含む実解決キー）を格納**する。例: `billing.features.reservation_notification_recipients_extended.name`・`billing.plans.full.name`。FE は `$t(row.displayNameKey)` でそのまま解決できる（実装時判断に流さない・V146 シードにこの実値を書く）。
- 文言に裸の `@` を使わない（`{'@'}` エスケープ・memory `project_i18n_at_sign_breaks_nuxt_build`）。
