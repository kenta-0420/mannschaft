## 1. 概要

宅地建物取引業法第35条に基づく **重要事項説明書**（重説書）を、F09.13 物件履歴台帳・F09.1 住民台帳・F09.3 駐車場マスタなどから自動引用して **PDF / Excel / Word** で出力する機能。

各都道府県の宅建協会・自治体ごとに様式が微妙に異なるため、**国交省標準書式 + 主要5都道府県（東京/神奈川/大阪/愛知/福岡）**を Phase 2 で対応し、残り42都道府県は Phase 3 の JSON エディタでユーザー側で追加可能とする。

### 対象ユースケース

- マンション売買時、不動産仲介業者が重説書を作成する際の **下書き**として組合作成版を提供
- 賃貸借契約時に管理組合が補助情報として提供
- 物件調査依頼に対する正式回答書類（管理組合作成版・参考情報）

### 重要な免責

本機能で出力される書類は、**宅建業者の代替ではなく管理組合からの参考情報**である。法定の重要事項説明は宅地建物取引士による説明が必須であり、本書類は仲介業者が宅建士の責任で内容確認・整形した上で正式書類として利用することを前提とする。出力される PDF にはフッターに以下の固定文言を入れる:

> **本書類は管理組合が物件調査に応じて作成した参考情報であり、宅地建物取引業法に基づく正式な重要事項説明書ではありません。実際の取引では、宅地建物取引士による説明・記名押印が必須です。**

## 2. スコープ

### 対象ロール

| ロール | 操作可能な範囲 |
|---|---|
| SYSTEM_ADMIN | 全組織の出力履歴閲覧（監査用） |
| ADMIN | 様式テンプレートの選択・出力・PDF/Excel/Word ダウンロード・出力履歴閲覧・代替出力委任 |
| DEPUTY_ADMIN | 権限グループに `DISCLOSURE_EXPORT` が含まれる場合: 出力可。`DISCLOSURE_VIEW` のみ: 過去出力の閲覧 |
| MEMBER | 対象外（本機能は ADMIN 専用） |
| SUPPORTER | 対象外 |
| GUEST | 対象外 |

**理由**: 重説書は法定書式準拠の機密書類であり、誤情報・古い情報が出力されると不動産取引上のトラブルを招くため、ADMIN 限定とする。

### 対象レベル

- [x] 組織 (Organization) — 主たる対象（マンション管理組合）
- [ ] チーム (Team) — 対象外（重説書はマンション全体管理組合の文書）
- [ ] 個人 (Personal) — 対象外

### 対象テンプレート

`apartment` テンプレートを選択した組織で `property_history` を有効化した上で、追加で `real_estate_disclosure` を有効化する。`property_history` 未有効化では本機能を有効化できない。

## 5. ビジネスロジック

### 5.1 ドラフト作成 → 出力フロー

1. ADMIN が `/admin/disclosure` ページで「新規重説書」をクリック
2. 様式選択モーダル: `prefecture_code` で絞り込み、国交省標準書式 + 都道府県別を表示
3. 対象居室選択（任意）: F09.1 DwellingUnit から選択
4. ドラフト作成: `disclosure_form_drafts` レコード作成、`form_data` は `{}` で初期化
5. ドラフト編集画面: `form_schema` に従って動的フォームをレンダリング
   - `autoFillFrom` 指定フィールドは初期値を自動引用（§5.2）
   - 手動編集可能（自動引用は上書き可能）
6. ドラフト保存: `PUT` で `form_data` 更新
7. プレビュー: `GET draft` で最新の自動引用結果を含めて取得
8. 出力: `POST export?format=pdf|xlsx|docx`
   - PDF/Excel/Word 生成
   - F05.5 SharedFile に保存（`disclosure/{exportId}.{ext}`）
   - `disclosure_exports` レコード作成（`data_snapshot` に出力時データを保存）
   - レスポンスに presigned download URL
9. ドラフトの `status` を `EXPORTED` に遷移

### 5.2 自動引用元（autoFillFrom）

| 引用元キー | データソース | 説明 |
|---|---|---|
| `organization.name` | organizations | 物件名 |
| `organization.address` | organizations | 所在地 |
| `organization.construction_year` | organizations.metadata or 拡張カラム | 竣工年月（カスタムフィールドから取得） |
| `dwelling_unit.unit_number` | dwelling_units | 部屋番号 |
| `dwelling_unit.area` | dwelling_units | 専有面積 |
| `dwelling_unit.layout` | dwelling_units | 間取り |
| `dwelling_unit.owner` | resident_registry | 所有者氏名（個人情報配慮、ADMIN承認後のみ展開） |
| `property_history.packages` | property_work_packages | 工事履歴一覧 |
| `parking.spaces_total` | parking_spaces | 駐車場区画数 |
| `parking.assignment_status` | parking_assignments | 利用権形態（占有/共用） |

引用エンジン: `DisclosureAutoFillService` が `autoFillFrom` 文字列を解釈し、対応する Repository から取得。`autoFillFilter` で条件絞り込み（例: `{ "isDisclosable": true, "status": "COMPLETED" }`）。

### 5.3 様式バージョン管理

- 様式が更新されると `version` インクリメント、旧バージョンは `is_active=false` に
- ドラフトは `template_version_snapshot` で作成時のバージョンを記録
- 出力時、最新バージョンと異なる場合は警告（「テンプレートが更新されています。最新版に切り替えますか？」）
- `DISCLOSURE_006`: `effective_until` 経過の様式は出力不可

### 5.4 PDF / Excel / Word 出力

#### PDF（Phase 1: 標準書式 + 共通骨子のみ、Phase 2: 都道府県別 fragment 追加）
- `templates/pdf/disclosure/common.html` — 共通骨子（ヘッダー・フッター・免責文言）
- `templates/pdf/disclosure/fragments/{templateCode}.html` — 様式別本体
- Phase 1 では `MLIT_STANDARD_2024` のみ実装、Phase 2 で 5都道府県追加
- `PdfGeneratorService.generateFromTemplate("pdf/disclosure/common", contextWithTemplateInclude)` 経由

#### Excel（Phase 1: 標準書式、Phase 2: 都道府県別）
- `excel/disclosure/{templateCode}.xlsx` をリソースから読み取り、Apache POI でセル置換
- `ExcelGeneratorService.fillTemplate(InputStream template, Map<String,Object> data)` を新設

#### Word（Phase 3-B 実装済）
- **Apache POI XWPF** でテンプレート差し込み（`docx/disclosure/{templateCode}.docx`）
- `WordGeneratorService.generate(draft, template)` / `fillTemplate(InputStream, Map<String,Object>)`
- プレースホルダー記法は Excel と同じ `${key}` 形式（POI run 単位の分割を吸収するため段落ごとに連結 → 置換 → 先頭 run へ書き戻し）
- テンプレート 6 種は `WordTemplateGenerator`（test 配下のオフラインツール）で生成し `src/main/resources/docx/disclosure/` 配下にコミット
- 再生成: `./gradlew generateDisclosureWordTemplates`
- Phase 4 以降で正式な国交省/都道府県書式 docx に更新する前提（現在は最低限のプレースホルダー入り雛形）

#### ファイル名規約
- `{yyyyMMdd}_重要事項説明書(参考)_{物件名}_{部屋番号}.{ext}`
- 例: `20260506_重要事項説明書(参考)_サンプルマンション_301.pdf`
- 「参考」の文字列必須（法定書類との混同防止）

### 5.5 免責文言・透かし

- PDF/Word 全ページのフッターに固定文言（§1 概要 参照）
- PDF には半透明ウォーターマーク「参考情報・宅建士確認必須」
- Excel はワークシート上部に注意書き行を固定

### 5.6 電子印鑑承認（Phase 3）

- 出力後、ADMIN が「理事長押印」をクリック → F05.2 CirculationDocumentEntity 作成
- 理事長の電子印鑑（F05.3）を押印 → 押印済み PDF を別 SharedFile として再生成
- `disclosure_exports.circulation_document_id` で連携
- **Phase 4-C 有効化**: F05.2 `CirculationService#deleteDocument` が `CirculationDocumentDeletedEvent` を発行し、本機能の `DisclosureCirculationCleanupHandler` が購読して `disclosure_exports.circulation_document_id` を NULL 化する。`@Async("event-pool")` + `Propagation.REQUIRES_NEW` + `TransactionPhase.AFTER_COMMIT` の組み合わせで非同期かつ独立トランザクションで実行され、F05.2 削除トランザクションを阻害しない（既存パターン `AuthAnonymizationEventListener` 踏襲）。クロスドメイン FK 撤去（Phase 3-A）後のアプリ層整合性保証の完成形。

### 5.7 自動削除ポリシー

- `disclosure_exports.expires_at` デフォルト = `created_at + 90日`
- 90日経過後、SharedFile と共に自動削除
- ADMIN が「保管延長」を選ぶと `expires_at` を延長可能（最大 7年、F12.3 GDPR 整合）

#### Phase 3-E 実装（自動削除バッチ + 延長 API）

- バッチ: `DisclosureAutoDeleteBatchService`（毎日 02:00 JST、ShedLock で排他）
  - 期限切れ（`expires_at <= now` かつ未削除）レコードを抽出
  - R2 上の出力ファイル（PDF/Excel）を物理削除
  - `disclosure_exports` を <strong>論理削除</strong>（`deleted_at` セット）— 履歴メタデータは監査用に保持
  - 結果を `disclosure_auto_delete_batch_logs`（V61.018）に記録（`total_expired` / `total_deleted` / `failed_count` / `error_details`）
  - 1 件ずつ独立トランザクション（`REQUIRES_NEW`）で処理 → 部分失敗時も他レコードは継続処理
- 延長 API: `PATCH /api/v1/organizations/{id}/disclosure-exports/{exportId}/extend-expiry`
  - リクエスト: `{ "newExpiresAt": "2027-05-09T00:00:00" }`
  - 制約: 現在より未来 / 本日から 7 年以内 → 違反時は `DISCLOSURE_011`（422）
  - 延長 UI は別 PR で対応（本 PR は API のみ）

## 6. セキュリティ考慮事項

### 6.1 アクセス制御

- 全エンドポイント ADMIN または DEPUTY_ADMIN(`DISCLOSURE_*`) のみ
- カスタムテンプレートは作成組織内 ADMIN のみ閲覧・編集（クロステナント不可）
- SYSTEM_ADMIN は監査用閲覧のみ（書込不可）

### 6.2 データ機密性

#### 個人情報の取扱い
- **所有者氏名・賃借人氏名**: 自動引用時、ADMIN による「個人情報自動引用許諾」チェックが必須。許諾なしでは空欄出力（手動入力必須）
- **業者連絡先**: 重説書には原則記載しない（必要なら手動入力）
- **金額情報**: 工事金額は `is_disclosable=true` のパッケージのみ自動引用。非公開金額は除外

#### 出力ファイルの機密性
- F05.5 SharedFile に保存する重説書 PDF は **Private 設定固定**（公開リンク発行不可）
- 共有リンクは ADMIN が個別発行（最大有効期間 7日、パスワード必須）
- 端末ダウンロード時は IP ログを `disclosure_exports` の関連監査ログに記録

### 6.3 改ざん検出

- 出力時に出力ファイル（PDF/Excel/Word）の SHA-256 を計算し `disclosure_exports.output_sha256` に保存（Phase 3-A で `pdf_sha256` から汎用化）
- 後日ダウンロード時、再計算して照合（差異があれば 503 Service Unavailable / `DISCLOSURE_010`）
- Phase 3-D で電子印鑑承認回覧（F05.2）連携完了
- **Phase 4-C で参照整合性保証完成**: 回覧文書が論理削除された場合、`CirculationDocumentDeletedEvent` 経由で `disclosure_exports.circulation_document_id` を NULL 化することで「存在しない回覧 ID を参照したまま」の状態を防止し、改ざん検出の第 2 層（seal_stamp_logs 照合）の判定誤りを排除する（イベント駆動整合性保証）。
- **Phase 4-A 実装済**: F05.3 `seal_stamp_logs.seal_hash` との **AND 検証** による多層照合を実装。
  `disclosure_exports.generateDownloadUrl()` 内で 2 層検証を行う（`DisclosureExportService#verifyOutputIntegrity`）:
  1. **第 1 層**: R2 上のファイル SHA-256 と `disclosure_exports.output_sha256` を比較
  2. **第 2 層**: `circulation_document_id` が NULL でない場合、当該回覧の押印ログ
     （`seal_stamp_logs`、`target_type=CIRCULATION`）を全件取得し、`SealStampService#verifyStamp` で
     `seal_hash_at_stamp` と現在の `electronic_seals.seal_hash` の一致を確認
  - **判定**: 両層 PASS → 正常／いずれかが NG → `DISCLOSURE_010` (HTTP 503)
  - **取消済押印** (`is_revoked=true`) はスキップ（業務操作であり改ざんではないため）
  - **電子印鑑なし出力** (`circulation_document_id IS NULL`) は第 1 層のみで判定
- 実装上の注意: `DisclosureExportService` から `SealStampService` を `@Autowired` で直接呼出する
  （seal ドメインへのクロスドメイン参照、モノリス前提。将来イベント駆動化候補としてコメント明記）

### 6.4 Auto-fill のクロスサイト対策

- `autoFillFrom` の解釈は **ホワイトリスト方式**: `DisclosureAutoFillService.SOURCE_REGISTRY` に登録されたキーのみ受理
- 任意の Java プロパティを引数化することは不可（リフレクション禁止）

### 6.5 SQL/JSON インジェクション

- `form_schema`/`form_data`/`autoFillFilter` JSON は Bean Validation でスキーマ検証
- カスタムテンプレートの JSON Schema は登録時に静的バリデート（Jackson + jakarta.validation）

### 6.6 監査ログ

- 全操作を F10.3 audit_logs に記録: `eventType=DISCLOSURE_*`, `targetType=disclosure_*`, `targetId={id}`, `metadata={referenced_package_ids, dwelling_unit_id, output_format}`
- 出力履歴は永続保存（90日 TTL は SharedFile のみ、メタデータは保持）

### 6.7 入力バリデーション

- `form_data` は `form_schema` の各 field に対し:
  - `required: true` フィールド未入力 → `DISCLOSURE_007`
  - `maxLength`/`pattern`/`min`/`max` をサーバー側で再検証（フロントだけ信用しない）
- `referenced_package_ids` は組織内のパッケージ ID のみ受理（クロステナント不可）

### 6.8 レート制限

- エクスポート: 1ユーザー 1分5回
- ドラフト保存: 1ユーザー 1分20回
- 自動引用更新: 1ユーザー 1分10回

### 6.9 法令遵守

- 宅建業法 35条準拠を主張せず、参考情報として明記（§1 免責、§5.5 透かし）
- 出力 PDF にバージョン情報・出力日時・出力者を必ず印字
- 個人情報保護法: 自動引用前に許諾フロー、出力後の閲覧者制限

### 6.10 GDPR / 個人情報削除

- F12.3 GDPR 削除リクエスト時、`disclosure_exports.data_snapshot` 内の個人情報をマスキング
- ドラフトの `form_data` も同様にマスキング対象
- マスキング後は復元不可（出力履歴メタは残し、内容のみマスク）
