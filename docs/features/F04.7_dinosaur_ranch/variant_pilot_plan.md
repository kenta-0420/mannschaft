作成日: 2026-10-22。更新日: 2026-10-23。状態: 全16種の色・模様4外見制作scope採択済み・安全方式pilot先行。対象: 全16基礎種、各3成長段階×両style×確定4動作。制作範囲の承認を記録し、全素材の完成・各動作品質の承認・正式公開とは区別する。既存規約の正本は CLAUDE.md、軍議手順は `.claude/commands/軍議.md`。本書のACは後続の試練・検分・実機証拠へ引き継ぐ。

## 目的と今回の範囲

本人の分身となる恐竜について、現在の基本見た目と4frame歩行を保持し、同一speciesの4外見を見分けられる案を具体化する。最初の成果物は、現在の成体PAINT_2DをV1参照として、V2〜V4の追加静止案を同条件で並べた比較である。ユーザーが比較ページを見て「外見OK」と回答したため、4外見方向を採択済み。追加3案は `approvalreference`（成体2Dの外見方向の参照）であり、登録可能なanimation、既存atlasの改版、正式masterではない。

第1段階のアロサウルス成体2D静止比較は外見方向を採択済み。第2段階は同1種のBABY/JUVENILE/ADULT×PIXEL/PAINT_2D×4外見×待機/歩行/食事/喜びで安全方式を検証するpilotとする。安全方式確認後、第3段階として全16種へ同じ制作範囲を展開する。全16種展開は現在のユーザー承認済みscopeであり、新たな範囲承認待ちとは扱わない。各段階の技術検証・品質確認は省略しない。既存方式と隔離DEV境界を再利用し、DB/API変更と正式master登録は範囲外とする。

## 原本と制作方法の制約

第1段階の生成結果は採択された外見方向のapprovalreferenceとして使い、その生成全身画像を既存spriteの置換に使わない。元PNG、基準bytesとmanifestを保全し、ハッシュを制作前後に記録する。生成失敗、不要な眼/脚/輪郭の改変、模様の不適合は候補を不採用にして破棄対象へ分け、原本に修復を上書きしない。既存のユーザー資産を削除しない。

第2段階では既存の各stage/style/action/frameを正本とし、体色・模様・腹部等の変更可能部位と、眼/瞳/口/爪/輪郭/脚境界等の保護部位を意味別maskで明示する。mask自体をフレームごとに検分し、単一の色閾値を無検査で全素材へ適用しない。複数部位で同色を使う場合も部位の意味で区別する。本pilotでは採択済み方針に従い体型・歩行を共通とする。将来体型変更を提案する場合は本pilotの範囲外として、anchor・足/翼/ひれ・接地の個別調整案を別途提示する。

変更可能mask外の承認済basebytes、frame数/順序、frame寸法、anchor、床位置、phaseStarts、duration、timing、眼と脚の形・位置・可視性、FOODの素材と配置、食事/喜びの演出座標・発火位相を保持する。色/模様は4frame間で追従し、脚の交差や口/眼への侵入、模様の点滅をフレーム単位と再生の両方で検分する。生成画像の揺れ・拡縮だけを動作完成とは扱わない。

全種の制作はcode-nativeの意味別mask＋色/模様overlay方式を採用し、元PNGファイルを描き直さない。sourceは読み取り専用として前後SHA256を照合し、alpha/輪郭/目/角/爪/餌/体型/脚を保護する。V2の丸模様とV4の斑点は旧模様を消さず上から丸を重ねただけで完了にしない。appearance用cleanplateで旧模様の扱いを分離し、除去/置換結果を各frameで検分する。cleanplateの補間は原陰影の完全復元とは主張せず、陰影・部位境界の近似/未解決箇所を記録し、目視不合格を合格へ丸めない。

## 作業順序と完了判定

1. 本計画とACを軍議検分する。体型・歩行共通/色模様4外見比較の方法と、成体2Dの4外見方向のユーザー採択を記録する。
2. 第1段階の追加3案は採択された方向のapprovalreferenceとして保持する。VP01〜VP05および適用するVP12/VP15の静的条件の技術証拠は個別に確認する。
3. 意味別mask/cleanplateと4frame保全の試練を先行し、第2段階の24entryで安全方式を確認する。runtime接続前に性能予算・具体差分・認可の試験を確定する。
4. 安全方式確認後、承認済みscopeの全16種384entry/1,536clip参照/384fallbackへ段階展開し、VP06〜VP19を検分する。DEV接続を行う場合は実機E2E、その後にアリシゼーションを実施する。実施不能項目は理由と未実施を保持する。
5. 完了証拠は段階別に作る。静止比較、1種安全方式pilot、全16種制作の完了をそれぞれ区別し、正式診断・本番公開の完了に読み替えない。アプリ機能の完了証拠のscopeは `app` とする。本計画だけで完了証拠や台帳の完了状態を作らない。

今回Entity/Repository、Controller/DTO、正式master登録の部隊は不要。計画・静止候補制作、採否、mask/試練、動画展開、検分/実機の依存順で進める。新台帳行/commit/公開操作は本準備に含めない。
