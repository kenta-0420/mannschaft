## 1. 画面と導線

部屋ヘッダーの「遊び方」はページを移動せず `RanchGuideModal`（共通 PrimeVue Dialog）を開く。任意参加、7日経過と選定確定後の孵化、変更不可の10文字以内の名前、無料ケア・個人想起、ログインだけでは報酬なし、離れても保存状態を失わないことを説明する。準備中の方式・対応表・素材や停止中のケアを利用可能と扱わない。閉じるボタン・Escape、モバイルでの縦スクロールに対応し、説明は6言語の `ranch.guide` で管理する。

表示名は「恐竜の部屋」。ユーザーにowner/entity/outbox等の技術用語を見せない。任意開始前はダッシュボードへ勧誘モーダル/不利益表示/強制設定を加えない。設定内に説明付きの「恐竜の部屋をはじめる」を置く。開始で卵一つ/部屋一つを作る。卵期間に選定方式を確認（陸/海/空random、出生情報の占い風案、初期必須診断adapter）。未実装方式は準備中、入力収集なし。同選定再送で再抽選なし。一度休止しても再開で同じ恐竜アバターが現れる。

```text
┌ 恐竜の部屋                       [設定] ┐
│  [記念棚1] [記念棚2] [記念棚3]          │
│                                         │
│               小さな恐竜                 │
│             卵 → 幼体 → 成長期 → 成体         │
│                                         │
│  育成ポイント …      [ごはん（無料）]    │
│  最近の記録                             │
│  ・想起を終えた / ごはんをあげた          │
│  [想起へ] [記念品を飾る] [記録を見る]     │
└─────────────────────────────────────────┘
```

空腹/危険/残り時間/連続日数/他者順位は出さない。週上限はポイント詳細で中立に説明する。上限到達後も学習/投稿は通常通り可能。「今週の育成ポイントは上限に達しました。恐竜アバターの成長やポイントは減りません」。未利用を責めない。

部屋widgetから無料給餌・記念品配置・永久装飾交換・記録・無料想起へ到達できる。残高0/本体活動0でも無料給餌で成体へ育つ。週care枠後は成長加算なしで触れ合い可、次週まで操作自体を禁止しない。想起先は既存 `/reflections` 系本人導線を確認して使い、存在しない `/my/reflection` を推測して追加しない。無料利用・チーム未所属でも同じ導線。既存profile画像を恐竜へ置換せず、チャット/メンバー表示の本人識別を変えない。

設定は個別に「部屋を表示」「動き（通常/少なめ/止める）」「音（既定OFF）」「音量0〜100」「育成をお休みする」。非表示は報酬継続、休止は報酬停止で既存残高/成長保持を明示。動き既定REDUCED、音量保存既定50は提案（音OFFなので無音）。音ONも自動再生せず操作による短い効果音のみ。音OFFとreduced-motionは独立、OS動き抑制が有効なら個人NORMALより優先してREDUCED以下へ抑制、STOPPEDは常に静止。

## 2. 既存UIへの最小統合

運営画面 `/system-admin/ranch` は `useAuthStore.isSystemAdmin` の場合だけ運営フォームをmountする。非権限は既存6言語の `DashboardErrorState` のforbidden表示へ切り替える。同じ本人IDのrole降格でも同期watchで運営command scopeだけを破棄し、旧runをabortして画面世代を更新する。再昇格で入力や旧命令を持ち越さず、運営状態を再取得する。abortはサーバーで既に到達したcommitの取消保証ではなく、APIのfresh SYSTEM_ADMIN/ACTIVE再認可は引き続きサーバーが担保する。

`DashboardWidgetCard` / `SectionCard` / `DashboardErrorState` / `DashboardEmptyState` / `PageLoading` とuseApi/useErrorHandler/useNotificationを使用。`useDashboardWidgets('personal')` に新widgetキー/BE対応を追加し、表示/並び順の既存永続化を使う。新widget専用isVisibleは表示設定の正本と一致させ、二つの独立表示booleanを作らない（widget visibilityへadapter、stateのisVisibleはその投影）。 本人widget設定のGETは認証復元後のブラウザーで行い、SSRの既定表示値を保存結果として使わない。個人・チーム・団体のdashboardとwidget設定一覧は、既存ready判定でGET確定までPageLoadingを表示し、reload後も保存済み非表示・順序を反映する。

必要箇所: `useDashboardWidgets` のWidgetKeyMap/ALL_WIDGETS、BE WidgetKey、`DashboardPersonalWidgetGrid` の分岐、`DashboardPersonalAccordion` の所属section。既存accordionのkey登録を忘れるとwidgetが設定だけに出て画面に現れない。恐竜の部屋はcontent-affiliation内の一カード案。トップ固定の巨大常駐画面にしない。PC/スマホ/個人scopeのcarouselで同じstateを使う。

コンポーネント案: `RanchWidgetCard`（状態表示）、`RanchRoomScene`（静止絵＋slot）、`RanchSettingsDialog`、`RanchCollectibleDialog`、`RanchRecordList`。ロジックは `useRanchApi` / `useRanchState` へ分離。新規Piniaは画面跨ぎ共有が必要な場合だけ。アニメframe/位置をAPIへ送らない。

重いsceneはLazy prefixとClientOnly、初回展開/viewport内までassetを取得しない。widget非表示/未参加ではscene asset/audio/animation timerを一切読み込まない。展開後も非表示scope/背景tabではtimer・音・RAF停止。OS reduced motion変更とunmountに追従しlistenerを解除。静止fallbackは同じ論理stateから描く。初期は96×96ドットの少量画像と軽量CSSを使用し、Three.js/Lottie等を必須依存にしない。複数頭の常駐GPU処理は後続。

accordionが閉じた時やcarouselの非active panelはcomponentが保持されうるため、unmountだけで停止を判定しない。scene paused条件は未参加/widget非表示/対象context・scope非active/accordion閉/carousel非active/viewport外/document非visibleのいずれか。親のvisibility/context状態とviewportをsceneへ渡し、paused時は恐竜と背景のtimer/RAF/audioを停止する。初回有効表示前はasset未取得、既に取得したassetを保持していても停止を守る。STOPPED/OS reduced motionの抑制をこの条件と組み合わせ、復帰は最新stateの静止段階から行う。

## 3. 記念置物

持っている置物を選び、空いているslotへ配置する。Phase 1は自由座標dragを使わず、キーボード/タップで「slotを選ぶ→配置」。同じinventoryを二slotへ複製しない。交換/取り外しは一TX、所有/取消/versionをサーバー確認。slot競合409では最新の部屋を再取得する。取り外しても記念品はinventoryに残る。

既存badgeを見せる際はsystem badge→運営承認collectibleのadapterを使う。既存自由文やteam名をコピーして所属離脱後も表示しない。legacy badge IDは元identityの実値をnullable Stringとして保持し、award period/userと組にしたbinary acquisition_keyのuniqueで二重収集しない。beta badgeの記念置物を隠してもbeta entitlementは保持する。旧badge表/award依存を移すまでpackage/表を削除しない。

## 5. モバイル・アクセシビリティ

390px幅で横に伸ばさずmin-w-0、md=768pxで境界を統一。操作領域44×44px以上、入力16px以上。slotは折返しgrid、sceneはaspect-ratioでサイズを予約しCLSを抑える。成長色だけで意味を伝えず段階文字/進捗を表示。buttonに明確なaria-label、decorative画像はaria-hidden、恐竜は短いalt。給餌結果はaria-live=politeで一回、連続frameを読み上げない。Dialogのfocus移動/復帰/ESC、keyboardで全slot配置、200%ズーム、6言語長文、dark contrastを検証する。

OS動き抑制時はジャンプ/拡大/移動なし。NORMALは短い給餌反応、REDUCEDは移動なしの短い色/表情反応、STOPPEDは静止（結果文字だけ）。idle歩行は初期なし。設定保存前にOSが変わっても適用する。画像失敗時も段階/ポイント/給餌機能を使える。表示OFFは想起や本体への導線を消さない。

## ドットと通常2D切替の境界

ドットの最終論理サイズは96×96にユーザー確定。48標準を置き換える。比較ページは96を既定とし、ほかの粒度は比較用。96格子の整数倍表示/nearest-neighborと、足baseline・共通anchorをそろえる。アロサウルスv8には48pxの比較用出力があるが、全種・全成長・全動作の本番素材整備は未完了。

通常2Dも同時並行制作し恐竜表示を任意切替する方針はユーザー確定。同じdinosaur ID・成長段階・親密度・残高・報酬・育成条件を保持し、rendererのstyleだけを切り替える。追加育成通貨、個体再作成、再抽選は不要。基本設計の保存契約はowner.render_styleとSettings/RanchSettingsRequest.renderStyle=PIXEL/PAINT_2D（02/03）で、初期PIXEL。設定成功後の再読込/別端末でも選択を保持し、保存失敗/競合は明示して再取得し、成功したように扱わない。共通animation stateと素材参照schemaにstyle軸を持たせるが、具体renderer/素材schemaの詳細は後続モジュール設計で補完する。

対応するstyle/段階/動作の素材だけを遅延loadし、切替前のtimer/RAFを停止する。低動作・静止fallback・非表示時assetなしの契約を両styleで守る。renderer共通化より、同じ動作をドットと通常2Dの二セットで制作し、anchor/足/演出を調整する素材作業が主な負担。既定表示はドット、通常2Dも同時並行制作する。ドットの格子サイズは素材仕様で96×96と定義し、style名へ固定サイズを埋め込まない。選べるstyleは対象個体/成長段階の必要動作と静止fallbackが揃ったものに限定し、歩行だけの試作を全育成対応として見せない。

切替時は旧styleのtimer/RAF/audioと不要なlistenerを停止・解除してから新styleを表示する。素材欠落/取得失敗時は同個体・同段階の静止fallbackを優先し、それも無ければ段階文字/進捗/給餌操作を維持する。同個体の他styleへfallbackする場合も保存済み選択を勝手に書き換えず、fallback状態を明示する。別species/別個体へ差し替えない。追加6言語keyはranch.settings.renderStyle/pixel/paint2d、ranch.rendering.assetUnavailable/fallback。同一個体の両styleに同じalt/状態説明を使う。

海のゆっくりした泡、雲のゆっくりした移動など背景motionもmotionModeに従う。NORMALでは小さな背景motion、REDUCED/OS reduced motionでは泡の移動/雲の移動を止め静止背景、STOPPEDは全scene静止。非表示/背景tab/unmountでは背景を含むtimer/RAF/audioを停止し、復帰時に隠れていた時間分のanimationを一気に再生しない。両styleで同じ抑制を適用する。Phase 1のidle歩行は引き続き後続scopeで、歩行試作/背景試作は本番素材完成やPhase 1歩行実装を意味しない。

恐竜のドットと通常2Dを並行制作し、個体/育成状態を共有して表示だけを切り替える。牧場主・建物・家具・景観まで二方式にする範囲は別途検討。生成速度と、同一個体・成長段階・動作の整合性を保つ制作/確認時間は区別する。採用するドット粒度で、両styleの歩行・固定anchor・接地・ループ・小さなウィジェットの可読性を確認して展開する。アロサウルスの歩行と代表3体の静止画は、64タイプの全成長/全動作が二style完成した証拠ではない。

### 歩行素材の確認条件

歩行素材は共通の固定anchor・縮尺・地面基準を使い、frameごとのalpha bbox中心/足最下点で再配置しない。接地脚と遊脚の交代、体格/模様の連続性、最終frameから先頭への接続を実際のループで確認する。速度と歩幅の関係は表示側でも調整し、単なる庭の往復を歩行品質の証明にしない。両styleで同じ動作stateを使い、低動作/静止/非表示設定を守る。生成シートの採用前に、体形の揺れ・足滑り・余分な脚・切れた尻尾・frame境界の混入を確認する。

歩行の見た目はユーザー希望として、足を大きく動かしゆっくり体重を移す「のそのそ歩き」、歩みに合わせた小さなしっぽの揺れを両styleで採用する。demoの4fpsは比較用の提案値で、本番fps/コマ数/歩幅は品質確認後に決める。生成したコマの脚交代・接地・体形/模様の連続性が未調整のため、現試作を本番完成と扱わない。

歩行は手前/奥の脚が接地と遊脚を交代し、途中で交差して前後を入れ替える見た目が必要。生成済み8コマを並べる方式では十分に整わなかったため、胴体/脚/尾の画像パーツを共通の歩行制御で動かす比較試作も作成した。本番のスプライト/パーツ方式は採用する粒度での輪郭・接続部・負荷を確認して決める。二方式の成長/報酬stateは共通のまま。

### 恐竜アバターの制作基準（2026-10-02）

ユーザーは今回の緑の恐竜の見た目と歩行試作を、恐竜アバターの制作基準として採用した。アロサウルスのドットV3の顔・丸みと、現行2D歩行を組み合わせたv8（green-dinosaur-latest.html）を基準サンプルとして保存する。通常2Dの任意切替は維持するが、48×48固定は取り下げ、最新のユーザー判断で96×96を採用した。基準採用は全種・全成長段階の素材完成や本番描画方式の確定を意味しない。

体格ごとに軽快・標準・ゆったりの3歩行プロフィールを設ける案をユーザーが提示した。次の数値は比較制作の提案値であり未確定。周期は片足が次に同じ位置へ戻る一巡で、描画fpsとは別に扱う。
