## 1. 概要

機能C の空きグリッド（列=スタッフ・単日）を発展させ、**縦=日付＋予約対象（ライン）／横=時間（30分）**のマトリックスUIを実現する。会員は「セルをクリック → メニュー選択 → 連続枠プレビュー → 確定」の 3 ステップで予約グループ（F03.4.3）を作成できる。

BE 拡張は 3 点:
1. **ライン軸**: グリッドの列モデルに `lineId` を導入（`axis=LINE`。既定は従来の `STAFF` = 後方互換）
2. **日付レンジ**: 単日×7回呼びから `from`/`to`（最大7日）の 1 リクエストへ移行できる `days[]` 応答を追加
3. **メニューフィルター**: `menuId` 指定で「提供可能ラインの列のみ」＋「必要枠数」を返す（連続空きの網掛けは FE 責務・§5.2）

## 4. API設計

### 4.1 `GET /api/v1/teams/{teamId}/reservation-slots/grid` の拡張（後方互換）

既存の応答契約（親 §4.C）は**無変更で維持**し、以下を**追加**する。

> **⚠ `date` パラメータの required 解除が前提（実機E2Eクリティック B3）**: 現行実装の `date` は**必須 `@RequestParam`**（`required=false` なし・実測）。このままでは `from/to` 単独呼びが **Service 層の排他検証に到達する前に** `MissingServletRequestParameterException` の汎用 400 で全滅する。よって本拡張では **`date` を `required=false` 化**し、「`date` XOR (`from`,`to`)」の排他は **Service 層で明示検証**する（両方未指定も 400・専用メッセージ「date または from/to のいずれかを指定してください」。Bean バインド段階のエラーに任せず、検証位置と文言を制御する）。

**クエリパラメータ（追加分＋変更）**

| パラメータ | 型 | 必須 | 説明 |
|-----------|---|------|------|
| `date` | String(date) | **No に変更**（従来 Yes） | 単日指定。`from/to` とは XOR（Service 層検証・上記注記） |
| `axis` | String(enum) | No | `STAFF`（既定・従来動作）/ `LINE`。`LINE` は列=予約対象（ライン） |
| `from` / `to` | String(date) | No | 日付レンジ（**両方指定・最大7日・from <= to**）。指定時は応答が `days[]` になる。`date` とは排他 |
| `menuId` | String(UUID) | No | メニューフィルター。`axis=LINE` のときのみ有効（`STAFF` 指定時は 400）。提供可能ライン列のみ返し `meta` に必要枠数を載せる |

**パラメータ検証（Service 層・到達順）**
| ステータス | 条件 |
|-----------|------|
| 400 | `date` と `from/to` の同時指定 / **`date`・`from/to` の両方未指定**（専用メッセージ） / `from`/`to` 片方のみ / 8日以上 / `from > to` / `axis` 不正値 / `menuId` を `axis=STAFF` と併用 |
| 404 | `menuId` が不存在・他チーム・削除済み（RESERVATION_032 再利用） |
| 401 / 403 | 未認証 / view ゲート非許可（RESERVATION_021。既存と同じ Service 層判定） |

> 機能C の先例（親 §8「機能C は read-only のため専用エラーコードを追加しない」）を踏襲し、**本機能も新規エラーコードを追加しない**（上記は汎用 400/404 と既存コードの再利用のみ）。


**契約の定義（フィールド別）**

| フィールド | 型 | null | 説明 |
|-----------|---|------|------|
| `axis` | String | 不可（新設・既定 `STAFF`） | 応答の列軸。既存クライアントは未参照でも壊れない（additive） |
| `meta` | Object | 可 | `menuId` 指定時のみ非 null。`requiredCellCount = durationMinutes / 30`・`cellMinutes = 30`（固定・FE のマジックナンバー排除）。**用語整理**: `requiredCellCount`（本 API・grid 文脈）と `requiredSlotCount`（F03.4.1 メニュー一覧）は**同一値の文脈別名**で、いずれも BE が `durationMinutes / 30` から導出する（F03.4.3 §5.2-f の検証も同じ導出。三者が食い違ったら BE 導出が正） |
| `days[]` | Array | 可 | `from/to` 指定時のみ非 null。各要素は `{date, columns}`（単日応答の `columns` と同構造） |
| `date` / `columns` | 既存 | 可 | **単日呼び（`date=`）のときのみ非 null**（完全後方互換）。レンジ呼びでは null |
| `columns[].lineId` / `lineName` | Long / String | 可 | **`axis=LINE` のとき非 null**（共通枠列は両方 null）。`axis=STAFF` では常に null |
| `columns[].staffUserId` / `staffName` / `lineIds` / `cells` | 既存 | — | 既存契約のまま（`axis=LINE` では staffUserId/staffName は null・`lineIds` は空配列） |
| `cells[].unavailableReason` | String | 可 | **F03.4.5 §4.4 で追加予定（additive・W2-2 弾）**: `state=UNAVAILABLE` かつ判定元が `is_public=TRUE` の**定期予約不可枠**のときのみ事由ラベル（例「研修」）。それ以外は null（従来表示と完全一致）。PII 非該当。`GridCellDto` は record のため正準コンストラクタ変更＝既存構築箇所の null 引数追加が必須（H-1 と同じ「additive=BE 無改修ではない」注意）。詳細・AC は F03.4.5 §4/§9 R-4 が正 |

**`axis=LINE` の列モデル（確定仕様）**

- 列 = 当該チームの **active ライン**（`is_active=TRUE`・`deleted_at IS NULL`）を `display_order` 昇順で全列（最大20列・F03.4.2）。当日 slot の有無に関わらず列を出す（「枠がない」ことが見えるのが管理・会員双方に有益。セルなし列は空）。
- 各列のセル = `slot.line_id == 列の lineId` の枠。**共通枠（`line_id IS NULL`）は末尾の「共通」列に集約**（機能C の共通列と同じ思想。`lineId: null`）。
- `menuId` 指定時: `reservation_menu_lines` を結線し、**提供可能ラインの列のみ**返す（行 0 件のメニュー = 全ライン提供可 = 全列）。共通枠列は**常に含める**（共通枠はライン非拘束であり、予約時に提供可能ラインを選べるため）。
- セル state・PII 非露出・予約不可枠 overlap（`UNAVAILABLE` 最優先）は機能C と**同一実装**（`ReservationUnavailabilityChecker`・`GridCellDto` を共有。別実装厳禁）。

**レンジ呼び（`from`/`to`）の実装**

- BE は日付ループで単日ロジックを再利用し `days[]` に詰める（クエリは `slot_date BETWEEN` の 1 回取得＋日付でグルーピング。予約不可枠も `BlockedDateBetween` の既存レンジクエリを流用）。
- 最大 **7 日 × 21 列（20 ライン＋共通列）× 24 セル = 3,528 セル**が応答上限（≒ 300KB 未満・gzip で実用圏内。列カウントは「20 ライン＋共通=21 列」で F03.4.2 §3.4 と統一）。8 日以上を 400 で禁じるのはこの応答サイズ上限の担保。
- 既存 FE の「単日 API を 7 回呼ぶ」週タブ（実装済み・実測）は**レンジ呼びへ移行**する（§5.1）。移行後も単日契約は維持（他画面・既存テストを壊さない）。

### 4.2 変更しないもの（明記）

- `GET /reservation-slots/available`（リスト型空き枠検索）: 無変更。`SlotPicker`（リスト表示）が使い続ける。
- 機能C の単日・staff 軸契約: 無変更（`axis` 省略時の挙動が従来と完全一致することを回帰テストで担保）。
- 認可: 既存どおり `@PreAuthorize` なし＋ Service 層 `ReservationViewAccessGuard.assertCanView`（親 §4.C）。

## 5. ビジネスロジック・フロントエンド仕様

### 5.1 BE 実装方針

| 対象 | 変更 |
|---|---|
| `ReservationGridService` | `axis`/`from-to`/`menuId` の分岐を追加。ライン列の導出（active ライン全列＋共通列）・menu_lines 結線・`days[]` 組み立て。既存 staff 軸パスはリファクタせず温存（回帰面の最小化） |
| `ReservationGridResponse` | `axis`/`meta`/`days`/`GridColumnDto.lineId`/`lineName` を追加。**「additive」は API 契約（JSON）の話であって BE 無改修という意味ではない**: `GridColumnDto` は **record**（実測）のため lineId/lineName の追加は**正準コンストラクタのシグネチャ変更**であり、既存の `new GridColumnDto(...)` 構築 2 箇所（`ReservationGridService.java:94`〔スタッフ列〕/ `:108`〔共通列〕）の**同時改修が必須**（staff 軸パスでは `lineId=null, lineName=null` を渡す）。JSON 上は既存フィールドの型・null 性が不変＝クライアント互換。OpenAPI 再生成＋`generate:types` 同一 PR |
| `TeamReservationSlotController` | 新パラメータのバインド。**既存 `date` の `@RequestParam` を `required=false` へ変更**（B3。排他検証は Controller ではなく Service 層 — 検証位置・文言の一元管理） |

### 5.2 メニューフィルターの BE/FE 責務分担（確定・設計判断）

| 判定 | 担当 | 理由 |
|---|---|---|
| 提供可能ライン（menu_lines 結線・列の絞り込み） | **BE** | マスタ結合はデータ所有側の責務。FE に menu_lines を渡して結線させると可視性ルールが二重化する |
| 必要枠数（`requiredCellCount`） | **BE**（meta で供給） | duration/30 の導出を FE に再実装させない（F03.4.1 と同方針） |
| **連続空き N 枠の判定（開始可能セルの網掛け）** | **FE** | 応答済みセル配列の走査（同一列・時間昇順に AVAILABLE が N 個連続か）という純表示ロジック。BE で判定すると「開始可能フラグ」がセルに増えて応答が肥大し、かつ確定時に再判定が必須（TOCTOU）で二重実装になる |
| 確定時の最終検証（連続・提供可否・満席） | **BE（F03.4.3 §5.2）** | 権威判定。FE 網掛けはあくまで提案 |

- FE の開始可能判定: セル `c` から同一列で `requiredCellCount` 個の連続 AVAILABLE が取れる場合のみ `c` をクリック可能として描画。取れないセルは薄灰（`disabled`）＋ tooltip（i18n `reservation.matrix.cannot_start_here`）。**判定は §5.3 の 30 分正規化後のヘッダ列基準**で行う（B4。生セル配列の隣接比較ではなくヘッダ列インデックスの連番で判定 — 長尺枠混在時も正しく機能する）。
- **時刻値の扱い（B8）**: `startTime`/`endTime` は Jackson の `LocalTime` 既定シリアライズで **`"HH:mm"`（秒なし）**。FE の連続・整列判定は**文字列一致に依存せず「0:00 からの経過分（minutes）へ正規化してから数値比較**する（`"10:00"` と `"10:00:00"` の表記揺れ・辞書順比較の罠を構造的に排除。`fmt`/`toMinutes` ユーティリティを 1 箇所に集約）。
- メニュー未選択時はフィルターなしの全セル表示（従来の単セル予約もこの画面から可能 = 単枠予約フローを温存）。

### 5.3 FE マトリックス仕様（`SlotMatrixPicker.vue` 新設・SlotGridPicker 発展）

**レイアウト（確定）**

```
                horizon →（横 = 時間・30分刻み・09:00〜21:00 は営業時間から導出）
縦 ↓          | 10:00 | 10:30 | 11:00 | 11:30 | 12:00 | …
7/10(金) 席1  |  ○   |  ○   |  ●   |  ○   |  −   |
7/10(金) 席2  |  ○   |  ×   |  ×   |  ○   |  −   |
7/10(金) 共通 |  ○   |  ○   |  ○   |  ○   |  ○   |
7/11(土) 席1  |  ○   |  ○   |  ○   |  ●   |  −   |

```

- **縦 = 日付 × 予約対象（ライン）**の複合行（`days[] × columns[]` を行に展開）、**横 = 時間（30分）**。マスター御裁可のレイアウトそのもの。
- セル記号: ○=AVAILABLE / ●=BOOKED / ×=UNAVAILABLE（予約不可枠）/ 灰=CLOSED / −=枠なし。凡例を上部に常設（i18n）。

**cells[] → 固定30分時間ヘッダへの整列アルゴリズム（B4・長尺枠混在対応）**

F03.4.2 は 30 分セル生成を標準とするが**長尺の手動枠（60 分等）の作成を許容**するため、実機では必ず混在する。描画は以下の整列規則で行う:

```
1. 時間ヘッダの構築: 表示対象（単日 or 7日）の全列の cells から min(startTime)〜max(endTime) を取り、
   30 分刻みの固定ヘッダ列 [h0, h1, ...] を生成する（分正規化した数値で扱う・B8）
2. 各行（日付×ライン）について、各セル s を「s.startTime が一致するヘッダ列」に配置し、
   span = (s.endTime - s.startTime) / 30 を colspan として横に跨がせる
   （60 分手動枠 → colspan=2 で 2 ヘッダ列を1セルとして描画。クリック時は単枠予約フローへ）
   ※ 30 分グリッドに乗らない開始時刻の枠は生成経路上存在しない（既存 022 検証・親 §3）
3. どのセルにも覆われないヘッダ列 = 「−（枠なし）」を描画
4. 連続判定・網掛け（§5.2）は正規化後のヘッダ列インデックス基準で行う
   （colspan 枠は requiredCellCount 消費上も span 個ぶんのヘッダ列を占有として扱うが、
    グループ確保の対象は 30 分セルのみ＝長尺枠は連続確保の起点・構成要素にしない〔F03.4.3 §5.3 と整合〕）
```

**セルの描画規則の補完（B6・実機で必ず遭遇するケース）**

| ケース | 描画 |
|---|---|
| **過去時刻のセル**（当日で現在時刻より前に開始する枠） | state はそのまま・**クリック不可（disabled・薄灰）**。予約作成は BE の過去日検証（014）が最終防御だが、FE でも起点にさせない |
| **営業時間外のヘッダ列**（枠が存在しない時間帯） | 「−（枠なし）」（ヘッダは min〜max から構築するため、営業時間外は原則ヘッダ自体が現れない。手動枠が営業時間外にある場合はその枠だけが浮く=正しい実態表示） |
| **週表示の始まり** | **月曜起点**（`WEEKLY` の並び・schedule ドメインの曜日 UI と統一）。「今日を含む週」を初期表示し、過去日の行も表示する（グレーの実績として） |
- 既存 `SlotGridPicker.vue` の資産（単日/週切替・軸トグル `axisTimeRows`・スタッフ絞り込み・生成型参照・`slotSelected` emit 契約 — 実測確認済み）を**発展**させ、`axis=LINE`・レンジ呼び・メニューフィルターを追加した `SlotMatrixPicker.vue` を新設する。`SlotGridPicker` は staff 軸表示として当面残置し、`TeamReservationsPanel` のタブから両方に到達できる（段階移行。完了後に統合を検討）。
- **モバイル**: 時間方向は横スクロール（**`overscroll-contain` 必須・縦→横ホイール変換の実装は厳禁** — `project_horizontal_scroll_needs_wheel_handler` 規約）。日付×ライン列（行ヘッダ）は `position: sticky; left: 0` で固定。
- **UX改善（2026-07-08 追記・第三弾第一波AB）**: 縦スクロール時は時間ヘッダ行（列見出し）も `position: sticky; top: 0` で固定する。左上の交差セル（日付/対象ラベル）は左右上下の両軸 sticky（`left-0 top-0`）とし、時間ヘッダ・行ヘッダより高い z-index で最前面に描画する。縦スクロールを sticky top に確実に効かせるため、スクロールコンテナ自体に `max-h-[65vh] overflow-auto`（縦横両方をこのコンテナ内に閉じ込める）を付与し、`overscroll-x-contain` を `overscroll-contain`（両軸）へ拡張した。
- 行数上限: 7日 × 21 列（20 ライン＋共通）= 147 行。仮想スクロールは導入しない（DOM 数千セルは実用圏。パフォーマンス劣化が実測されたら第三弾で検討）。

**予約フロー（セルクリック → 確定）**

```
1. セル（○）クリック
2. メニュー選択ダイアログ（有効メニュー一覧 = GET /reservation-menus。

```

## 8. 受け入れ条件（テスト可能・正常/異常/境界）

### 実機E2E の前提データ手順（第二弾・/実機 用）

1. **準備順序を厳守**: チーム作成 → `PUT /reservation-settings/business-hours`（**非 NULL の実時刻**。NULL のままだと generate が全セル skip しマトリックスが空になる偽陰性）→ ライン作成 → メニュー作成 → テンプレ作成 → generate。
2. **当日セル・過去時刻セルの描画確認は手動 `POST /reservation-slots`** で当日枠を用意する（generate は tomorrow 以降のみ）。長尺枠混在（B4 の colspan 描画）も手動 60 分枠で用意する。
3. 週表示は**月曜起点**である前提で検証日を選ぶ（週跨ぎ確認は日曜→月曜の境界日で行う）。
4. 認可・非公開チームの 403 確認は使い捨てチームで行う（`feedback_authz_e2e_seed_membership_pollution`）。確定フローは認証付きで「セル選択→グループ作成→マトリックス再取得で BOOKED 反映」の一気通貫まで（`feedback_e2e_real_full_crud`）。

- **H-1（後方互換）**: `?date=` のみの従来呼びで、応答が拡張前と同一構造（`axis="STAFF"` が増える以外、`columns`/セルの JSON が既存期待値と一致）。**前提の明記**: `GridColumnDto` は record のためコンストラクタ引数が増える（§5.1）。既存 `ReservationGridServiceTest` が record を**直接 new していない場合のみ無修正 green**、直接 new している箇所があれば**引数追加（lineId/lineName に null）の機械的改修を許容**する — いずれの場合も**アサーション（期待値）側の変更はゼロ**であることが本 AC の合格条件。
- **H-2（axis=LINE・列モデル）**: ライン3本（席1/席2/席3・display_order 順）のチームで `axis=LINE&date=` を呼ぶと、列が席1→席2→席3→共通の 4 列。ライン軸枠は自ライン列に、`line_id NULL` 枠は共通列に載る。`columns[].lineId/lineName` が非 null（共通列は null）。
- **H-3（レンジ）**: `from=7/10&to=7/12` で `days[]` が 3 要素・各要素の `columns` が単日呼びと一致。`date` と `from/to` 併用・8日超・`from>to` は 400。**`from/to` 単独呼びが 200 で通る**（`date` の required 解除の観測点 — 解除漏れだと `MissingServletRequestParameterException` の汎用 400 で全滅・B3）。`date`・`from/to` の**両方未指定は 400**（Service 層の専用メッセージであること＝バインド段階の汎用 400 でないことをメッセージ本文で確認）。
- **H-4（メニューフィルター・列絞り）**: menu_lines=[席1] のメニューで `axis=LINE&menuId=` を呼ぶと列は席1＋共通のみ。menu_lines 0 件なら全列。`meta.requiredCellCount` が duration/30 と一致。`axis=STAFF&menuId=` は 400。
- **H-5（state 整合）**: `UNAVAILABLE`（予約不可枠 overlap）が FULL/CLOSED より優先される既存決定順（C-3）が `axis=LINE`/`days[]` でも同一（単一ユーティリティ共有の回帰確認）。
- **H-6（PII）**: `axis=LINE`/`days[]` の全セルに予約者氏名/userId が構造的に不在（DTO フィールド不存在で担保・C-4 踏襲）。
- **H-7（FE・開始可能網掛け）**: requiredCellCount=2 のとき、`[○,○,●]` の並びで 1 セル目のみクリック可・2 セル目は disabled（unit test: 網掛け関数の純ロジック）。
- **H-8（FE・確定フロー）**: セルクリック→メニュー選択→2 枠プレビュー→確定で `POST /reservation-groups` が正しい `slotIds`（時間昇順・連続）で呼ばれる。「メニューなし30分」選択時は既存 `POST /reservations` が呼ばれる。409 受信でグリッド再取得＋トースト表示（実機 E2E: 認証付きで作成→マトリックスに BOOKED 反映まで一気通貫 — `feedback_e2e_real_full_crud`）。
- **H-9（モバイル規約）**: 時間方向スクロールコンテナに `overscroll-contain` が付与され、縦→横ホイール変換ハンドラが存在しない（コードレビュー/lint 観点）。行ヘッダ sticky（左固定）・時間ヘッダ sticky（上固定・2026-07-08 追記）が機能する。
