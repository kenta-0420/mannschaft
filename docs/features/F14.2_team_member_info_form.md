# F14.2 チームメンバー定期更新フォーム

## 1. 概要

### 問題

チーム（マンション管理組合、企業チーム、クラブ等）では、メンバーの連絡先・緊急連絡先・
資格情報などを定期的に最新化する必要がある。現在のMannschaftにはこの仕組みがなく、
古い情報が放置されるリスクがある。

### ユーザー価値

- **管理者**: チーム固有のフィールドを自由に定義し、更新期限を設定できる
- **メンバー**: 自分の情報だけを参照・更新できる（他メンバーの情報は見えない）
- **プライバシー**: 機密フィールドはサーバーサイドAES-256-GCMで暗号化保存

---

## 2. スコープ

| 対象 | 範囲 |
|---|---|
| チームスコープ | TEAM のみ（ORGANIZATION は Phase 2 以降） |
| 操作権限 | ADMIN/DEPUTY_ADMIN: フィールド定義CRUD + 全メンバー回答確認（値マスク） |
| | MEMBER: 自分の回答のみ参照・更新 |
| 通知 | アプリ内通知（WebSocket + Notification テーブル） |

> **Phase 2 での ORGANIZATION スコープ追加時の注意**: 現在 `team_member_info_fields.team_id` は `teams.id` への直接 FK。ORGANIZATION スコープを追加する際は `scope_type + scope_id` カラムへの置換、または `org_member_info_fields` テーブル別途作成が必要になる。DBマイグレーションコストが高いため、Phase 2 着手前に設計レビューを行うこと。

## 3. DB設計

### 3-1. team_member_info_fields（フィールド定義）

```sql
CREATE TABLE team_member_info_fields (
  id                       BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  team_id                  BIGINT UNSIGNED NOT NULL,
  field_name               VARCHAR(100)    NOT NULL,
  field_type               ENUM('TEXT','PHONE','EMAIL','DATE') NOT NULL DEFAULT 'TEXT',
  is_required              TINYINT(1)      NOT NULL DEFAULT 0,
  is_sensitive             TINYINT(1)      NOT NULL DEFAULT 0
                           COMMENT '1=AES-256-GCM暗号化保存',
  refresh_interval_months  TINYINT UNSIGNED NULL
                           COMMENT 'NULL=無期限 / 12,36,60 のみ許可',
  sort_order               INT             NOT NULL DEFAULT 0,
  is_active                TINYINT(1)      NOT NULL DEFAULT 1,
  created_at               DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at               DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_tmif_team (team_id),
  CONSTRAINT fk_tmif_team FOREIGN KEY (team_id) REFERENCES teams(id) ON DELETE CASCADE,
  CONSTRAINT chk_tmif_interval CHECK (
    refresh_interval_months IS NULL
    OR refresh_interval_months IN (12, 36, 60)
  )
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 3-2. team_member_info_responses（回答）

```sql
CREATE TABLE team_member_info_responses (
  id                    BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  team_id               BIGINT UNSIGNED NOT NULL,
  user_id               BIGINT UNSIGNED NOT NULL,
  field_id              BIGINT UNSIGNED NOT NULL,
  value_plain           TEXT            NULL
                        COMMENT 'is_sensitive=FALSE の場合のみ使用',
  value_encrypted       TEXT            NULL
                        COMMENT 'is_sensitive=TRUE: AES-256-GCM Base64',
  encryption_key_version INT            NULL
                        COMMENT 'is_sensitive=TRUE 時のみ設定。is_sensitive=FALSE の場合は NULL',
  confirmed_at          DATETIME        NULL
                        COMMENT '最終確認日時。バッチ作成行（通知管理目的）は NULL のまま可',
  last_reminder_sent_at DATETIME        NULL,
  created_at            DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at            DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uq_tmir_user_field (user_id, field_id),
  KEY idx_tmir_team_user (team_id, user_id),
  KEY idx_tmir_field (field_id),
  CONSTRAINT fk_tmir_team  FOREIGN KEY (team_id)  REFERENCES teams(id)  ON DELETE CASCADE,
  CONSTRAINT fk_tmir_user  FOREIGN KEY (user_id)  REFERENCES users(id)  ON DELETE CASCADE,
  CONSTRAINT fk_tmir_field FOREIGN KEY (field_id) REFERENCES team_member_info_fields(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

> `encryption_key_version` は `is_sensitive=TRUE` の行にしか意味を持たない。`is_sensitive=FALSE` の行では NULL にすることで、将来のキーローテーション時に「暗号化されていない行（NULL）」と「旧キーで暗号化された行（version=1）」を区別できる。

### 3-3. ER概要

```
teams ──< team_member_info_fields ──< team_member_info_responses >── users
```

## 5. ビジネスロジック

### 5-1. フィールド削除時の挙動

- `is_active = 0`（論理削除）。対応する responses は保持。
- 物理削除は ON DELETE CASCADE で responses も自動削除されるが、管理者UIでは論理削除のみ提供する。

### 5-2. 回答の upsert

- `(user_id, field_id)` の UNIQUE KEY により、存在すれば UPDATE、なければ INSERT。
- upsert 成功時に `confirmed_at = NOW()` を更新する。
- `is_active = FALSE` のフィールドへの upsert は `INACTIVE_FIELD_UPDATE`（400）を返す。
- `is_required = TRUE` の未回答チェック: `value_plain IS NULL AND value_encrypted IS NULL` で判定する（バッチが先に `last_reminder_sent_at` のみ設定した行が存在していても、この条件で必須未回答と正しく判定できる）。

### 5-3. 期限切れ判定

```
isOverdue = (confirmed_at IS NULL OR confirmed_at + INTERVAL refresh_interval_months MONTH < NOW())
            AND field.is_active = 1
            AND field.refresh_interval_months IS NOT NULL
```

### 5-4. 暗号化（エンティティ実装方針）

エンティティのフィールド定義:
```java
@Convert(converter = EncryptedStringConverter.class)
@Column(name = "value_encrypted")
private String valueEncrypted;  // EncryptedStringConverter が透過的に暗号化/復号

@Column(name = "value_plain")
private String valuePlain;
```

サービス層での分岐（upsert 時）:
```java
if (field.isSensitive()) {
    entity.setValueEncrypted(value);   // @Convert で自動暗号化
    entity.setValuePlain(null);
    entity.setEncryptionKeyVersion(1);
} else {
    entity.setValuePlain(value);
    entity.setValueEncrypted(null);
    entity.setEncryptionKeyVersion(null);
}
```

管理者の status API では `isSensitive = TRUE` の値は必ず `"***"` に置換してから返す（エンティティの復号値をサービス層でマスクする）。

### 5-5. フィールド数上限

- チームあたり最大 20 フィールド（`is_active` 問わず）。超過時は `FIELD_LIMIT_EXCEEDED`（400）を返す。

## 6. バッチ設計（リマインド通知）

### MemberInfoUpdateReminderBatchService

```java
@Scheduled(cron = "0 0 9 * * *", zone = "Asia/Tokyo")
@SchedulerLock(name = "memberInfoUpdateReminderBatch", lockAtMostFor = "30m", lockAtLeastFor = "5m")
public void run() {
    // 1. is_active=1 かつ refresh_interval_months IS NOT NULL の全フィールドを取得
    // 2. 各チームのアクティブメンバーを取得
    // 3. 期限切れ or 未回答 かつ last_reminder_sent_at が24時間以上前のユーザーに通知
    // 4. last_reminder_sent_at を更新（通知後）
    // 5. 1バッチあたり最大500ユーザー処理（超過分は翌日に繰り越し）
}
```

### 通知内容

- **タイトル**: `[チーム名] 情報の更新をお願いします`
- **本文**: `「{フィールド名}」の更新期限が過ぎています。ご確認ください。`
- **ディープリンク**: `/teams/{teamId}/member-info`

### リマインドロジック詳細

| 条件 | 挙動 |
|---|---|
| 未回答フィールドが1つ以上ある | 通知対象 |
| 期限切れフィールドが1つ以上ある | 通知対象 |
| 同日に既に通知済み（`last_reminder_sent_at >= TODAY`）| スキップ |
| 複数フィールドが期限切れ | 1通にまとめて送信（最初の対象フィールド名を本文に使用）|

### 未回答ユーザーのリマインド管理

- responses 行が存在しない（未回答）ユーザーに対して、リマインドを送信する際は `last_reminder_sent_at` のみ設定した responses 行を作成する（`value_plain/value_encrypted/confirmed_at` は NULL のまま）。
- これにより「通知済みか否か」を responses テーブルで一元管理できる。

## 7. フロントエンド概要

### 管理者画面: `/teams/[id]/settings/member-info`

- フィールド一覧（ドラッグ＆ドロップ並び替え → PUT /fields/reorder を呼び出し）
- フィールド追加・編集モーダル
  - fieldName / fieldType（TEXT/PHONE/EMAIL/DATE）
  - isRequired / isSensitive チェックボックス
  - refreshIntervalMonths: 選択肢「なし / 1年 / 3年 / 5年」
- メンバー回答ステータス一覧テーブル（完了/未完了/期限切れ）
  - is_sensitive の値は `***` 表示
  - 「リマインド送信」ボタン（POST /responses/{userId}/remind）
  - クールダウン中（24時間以内送信済み）の場合はボタンを非活性化

### メンバー画面: `/teams/[id]/member-info`

- フィールド一覧と自分の現在値（is_sensitive の値は復号して本人に表示）
- 期限切れフィールドは赤背景でハイライト
- 入力フォーム（fieldType に応じて `<input type="text|tel|email|date">`）
- 一括保存ボタン

## 8. セキュリティ考慮事項

| 項目 | 対策 |
|---|---|
| 認可（メンバー在籍確認） | 全エンドポイントで `accessControlService.checkMembership(userId, teamId, "TEAM")` |
| ADMINのみ操作 | フィールドCRUD・status・remindエンドポイントで `accessControlService.checkAdminOrAbove(userId, teamId, "TEAM")`（ADMIN + DEPUTY_ADMIN を許可） |
| 機密値マスク | ADMINのstatusレスポンスで `is_sensitive=TRUE` → `"***"` 固定返却（サービス層でマスク） |
| 暗号化 | `EncryptedStringConverter`（AES-256-GCM, 128bit IV, 環境変数キー） |
| Blind Index | 機密フィールドへの検索クエリは不要設計（検索機能なし）→ 不要 |
| IDOR対策 | `/responses/me` は常に認証済みユーザーの user_id を使用。パスにユーザーIDを含めない |
| SQLインジェクション | JPA/Spring Data のみ使用、ネイティブクエリ不使用 |
| レート制限 | upsertエンドポイントに 10req/min のレート制限。実装: Bucket4j + Caffeine を使用した `OncePerRequestFilter` パターン（`ActionMemoRateLimitFilter` と同一方式） |
| 退会時のデータ削除 | `fk_tmir_user ON DELETE CASCADE` により自動削除 |

## 9. エラーコード（MemberInfoErrorCode）

| コード | HTTP | 意味 | GlobalExceptionHandler 登録要否 |
|---|---|---|---|
| FIELD_NOT_FOUND | 404 | フィールドが存在しない | 登録不要（デフォルト 404 で返る） |
| FIELD_BELONGS_TO_OTHER_TEAM | 403 | 別チームのフィールドへのアクセス | **要登録**（デフォルト 400 になるため） |
| REQUIRED_FIELD_MISSING | 400 | 必須フィールドが未回答（upsert時） | 登録不要 |
| INVALID_FIELD_TYPE_VALUE | 400 | PHONE/EMAIL/DATE の値フォーマット不正 | 登録不要 |
| FIELD_LIMIT_EXCEEDED | 400 | チームのフィールド数が上限（20）を超過 | 登録不要 |
| INACTIVE_FIELD_UPDATE | 400 | 無効化されたフィールドへの回答は受け付けない | 登録不要 |
| INVALID_INTERVAL_VALUE | 400 | refreshIntervalMonths に許可値（12/36/60）以外が指定された | 登録不要 |
| REMIND_TOO_SOON | 429 | 直近24時間以内にリマインド送信済み | **要登録**（デフォルト 400 になるため） |

> `FIELD_BELONGS_TO_OTHER_TEAM` と `REMIND_TOO_SOON` は `GlobalExceptionHandler.ERROR_CODE_STATUS_MAP` への登録が必要。実装時に忘れないこと。
