# F15.4 Phase 5: 店舗詳細ページの未ログイン公開 + 地図表示

> **ステータス**: 🟡 設計完了・マスター裁可待ち
> **依存**: F15.4 Phase 1〜4（PR #718/#746 マージ済み 2026-05-17）
> **最終更新**: 2026-05-18

## 1. 背景と目的

F15.4 Phase 1〜4 で「組織トップ→検索→結果カード」までの未ログイン公開導線が完成したが、
**カードクリック後の店舗詳細が auth middleware で弾かれる**ため、コンバージョン経路
（「行ってみよう」→「アカウント作る」）が成立しない。

Phase 5 で店舗詳細ページの未ログイン公開と地図表示を追加し、F15.4 の使命を完遂する。

## 2. スコープ

### In
- 新規 API `GET /api/v1/public/teams/{id}` (未ログイン可、レート制限あり)
- 抑制版 DTO `TeamPublicDetailResponse`
- 新規フロントページ `/public/teams/[id]` (middleware なし)
- ログイン誘導 CTA (タブ「メンバー」「お知らせ」等にオーバーレイ)
- `teams.map_embed_url` カラム追加 (Google Maps 埋め込み URL)
- 管理画面の Google Maps URL 入力欄 + バリデーション + 警告文
- i18n 6 言語

### Out
- 緯度経度ベースの半径検索 (別 Phase)
- 複数店舗の地図一覧表示 (別 Phase)
- PRIVATE チームの公開
- メンバー一覧の公開
- チャット履歴/告知/ファイル/出席情報の公開

## 4. API 設計

### 4.1 エンドポイント
`GET /api/v1/public/teams/{id}` (新規・認証不要・レート制限あり)

### 4.2 認可方針
- Spring Security: `.requestMatchers(HttpMethod.GET, "/api/v1/public/teams/*").permitAll()` を追加
- パターンは `*` (1 階層) で限定。`/**` (再帰) は使わない (サブパス事故防止)
- 既存 `GET /api/v1/teams/{id}` は変更なし (ログイン必須のまま)

### 4.3 ステータスコード
| コード | 条件 |
|---|---|
| 200 | 取得成功 |
| 404 | チーム不在 / 削除済み / visibility != PUBLIC / archived チーム |
| 429 | レート制限超過 |

### 4.4 レート制限
F15.4 既存 `OrganizationTeamSearchRateLimitFilter` を改名 (`PublicTeamApiRateLimitFilter`)、
対象パスを両方 (`/api/v1/organizations/*/teams/search` と `/api/v1/public/teams/*`) に拡張。

- 未ログイン: 60 req/min/IP (検索 30 より緩め、ページ滞在中の API 再叩き許容)
- ログイン: 200 req/min/user

## 5. 地図表示方針 (3 案比較)

| 案 | 内容 | 詳細表示 | 半径検索 | 地図一覧 | DDL | 運用 |
|---|---|---|---|---|---|---|
| 案 1 | `map_embed_url` テキスト保存 | ✅ | ❌ | ❌ | 小 | 小 |
| 案 2 | `lat`/`lng` + Spatial Index | ✅ | ✅ | ✅ | 中 | 中 |
| 案 3 | 段階的 (Phase 5 は案 1、別 Phase で案 2) | ✅ | △ | △ | 段階的 | 段階的 |

**採用: 案 3 (段階的)。Phase 5 のスコープは案 1 部分のみ。**

### 5.1 採用理由
- Phase 5 のミッション「店舗詳細ページに地図を出す」は案 1 だけで完結する（埋め込み iframe を貼るだけ）
- 案 2（緯度経度 + Spatial Index）は半径検索が要件になってから着手しないと過剰投資。ジオコーディング運用（住所→lat/lng 変換）は別途バッチ・API キー管理が発生する
- 案 1 は DDL が 1 カラム追加（`map_embed_url VARCHAR(2048)`）のみで済み、運用も「管理画面から Google Maps の共有 URL を貼る」だけ
- 将来 lat/lng が必要になっても **案 1 で追加した `map_embed_url` カラムは捨てなくて済む**（埋め込みは独立した UX 価値を持つ）→ 手戻りリスクが低い

### 5.2 セキュリティ要件
- 保存時バリデーション: 正規表現 `^https://www\.google\.com/maps/embed\?` で始まる URL のみ受理
- CSP: `frame-src https://www.google.com` を追加
- 管理画面側で「貼り付け方法」のヘルプリンクと「未ログインにも公開される」警告

### 5.3 既知のリスク
- **Google Maps Embed の利用規約**: API キーなしの共有リンク埋め込みは規約上グレー領域がある。Google Maps Platform の公式 Embed API（無料枠あり）への移行を中期的に検討
- **iframe の CSP**: `frame-src https://www.google.com` を CSP に追加する必要あり
