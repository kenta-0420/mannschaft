## 2. 認証マーク `TrustBadge.vue`

- **表示条件**: API の `badgeVisible == true`（`CERTIFIED` / `UNDER_REVIEW`）。**FE で state 値を直接分岐しない**（BE の `badgeVisible` が唯一の判定・[03 §4.2](03_security.md)）。`UNDER_REVIEW` でも見た目は `CERTIFIED` と**完全同一**（公開面に「再審査中」文言を出さない）。
- **見た目**: チェックマーク入り盾アイコン＋ツールチップ `trust.badge.tooltip`。色はブランド緑 `#047857`（QR 中央バッジと同系・既存トークンがあればそれを使用）。
- **配置先（消費側・読み取り専用）**:
  - マッチングドメインの相手団体カード
  - F09.19 広告 spotlight 掲載枠の掲載主体名の横
  - F19.1 公開チーム/組織ページのヘッダ（団体名の横）
  - チーム/組織のログイン後プロフィールヘッダ
- Props: `scopeKind: 'TEAM' | 'ORG'`, `scopeId: number`（内部で #3 を useFetch・一覧面では親が一括取得して `badgeVisible: boolean` を直接渡せる `visible` prop も持つ＝N+1 回避）。

## 3. 信任関係の公開表示 `TrustEndorsementList.vue`

- F19.1 公開ページ・団体プロフィールに「信頼の輪」セクションとして埋め込む。
- 表示内容: `incoming`（この団体を信任している団体）・`outgoing`（この団体が信任している団体）をタブまたは 2 リストで表示。各行 = 相手方団体名＋相手方の `TrustBadge`＋信任日。`counterpartPublicSlug` があるときのみ公開ページへリンク（[03 §4.1](03_security.md)）。
- 空状態: `trust.list.emptyIncoming` / `trust.list.emptyOutgoing`。
- 件数バッジ: `validEndorsementCount` を「{n} 団体から信任」として表示（`trust.list.incomingCount`）。

## 4. 信任管理タブ（団体管理者）

構成（上から順・段階開示）:

1. **状態カード**: 自団体の認証状態（`UNCERTIFIED`=「未認証」/`CERTIFIED`=「認証済み」/`UNDER_REVIEW`=「認証済み（運営確認中）」/`REVOKED`=「認証取消」）＋有効信任件数（例「3 / 3 件」）。管理者向けには生 state（4 値）を文言表示してよい（**生 state は管理者向け認証付き DTO でのみ取得**。公開 DTO は `UNDER_REVIEW` を `CERTIFIED` に丸めるため公開面には現れない・[02 §6.1](02_api_design.md)/[03 §4.2](03_security.md)）。
2. **信任するボタン** → `TrustEndorseDialog`（#5 資格 API を先に叩き、`eligible=false` ならボタンを非活性＋`blockingReasons` を i18n 文言で表示。年間残数 `annualQuotaRemaining` を「今年あと {n} 件」と表示）。
3. **信任した団体一覧（outgoing）**: 各行に取消ボタン → 確認モーダル（`trust.manage.revokeConfirm`・相手方が認証を失いうる旨を明記）。
4. **信任された一覧（incoming）**: 読み取りのみ。

### 4.1 信任付与ダイアログ `TrustEndorseDialog.vue`

- 入力: 対象団体の検索（既存の公開団体検索 `/discover` 系 API を流用・TEAM/ORG 切替）。
- 確認文言 `trust.endorse.confirmBody`: 「この信任は双方のプロフィールに公開されます」を必ず表示。
- エラー表示: `TRUST_001`〜`TRUST_006` を i18n キーへマッピング（§6.2）。エラーは握りつぶさず具体的理由を表示。

## 5. 運営レビューキュー（SYSTEM_ADMIN）

- 一覧: `under_review_since` 昇順（滞留の長い順）・団体名/種別・有効信任件数・初回認証日・現在の信任元一覧（レビュー材料）。
- 行操作: 「認証を維持（approve）」/「認証を取り消す（reject・理由入力必須）」→ いずれも確認モーダル。
- 付帯操作: アンカー付与/解除・任意団体の REVOKE（理由必須）。
- 既存の system-admin 画面群（fee-policies 等）とレイアウト・認可導線を揃える。

## 6. i18n（`trust.json` 新設・6 言語）

### 6.1 ファイルと登録（必須手順）

- 新規ロケールファイル: `frontend/app/locales/{ja,en,zh,ko,es,de}/trust.json`（6 言語すべて作成。未翻訳は暫定で日本語と同値可）。
- **`nuxt.config.ts` の i18n `locales[].files` 配列に 6 言語ぶんの `trust.json` を登録すること**（登録漏れはキーが解決されず生キー表示になる。JSON ファイルの存在確認だけでは偽陽性・memory `project_i18n_locale_file_registration_required`）。
- ネームスペースは前置なし（`auth.json` のみ auth ラップの例外・memory `project_i18n_auth_json_namespace_wrapper_exception`）。参照は `$t('badge.label')` ではなく **`$t('trust.badge.label')` 形式になるか否かを既存 `common.json` 系の参照実装に合わせて確認**（他ファイルは前置なしが正・実装時に既存パターンへ一致させる）。
- 文言中に裸の `@` を書かない（Nuxt ビルド破壊・`{'@'}` エスケープ・memory `project_i18n_at_sign_breaks_nuxt_build`）。

### 6.2 キー一覧（ja の文言例つき・**NG語不使用**）

## 7. FE 実装の注意（既存の罠）

- **生成型を優先**: API 型は `frontend/app/types/generated/`（openapi-typescript）を使う。BE マージ後 `npm run generate:types` を同一 PR 系列で実施（memory `project_openapi_json_chronic_drift`）。手動型でフィールドを"嘘"補完しない（`feedback_fe_api_type_assertion_field_lie`）。
- **ページルート**: `[id].vue` と `[id]/child.vue` の共存で親化事故（memory `project_nuxt_sibling_route_parent_needs_nuxtpage`）。信任管理をネストページにする場合は `[scopeId]/index.vue` 形式で兄弟化する。
- **単一要素ルート**: 新規ページのテンプレートはルート直下単一要素（PageTransition 対策・memory `project_pagetransition_single_element_root`）。
- **一覧の描画ゲート**: 信任一覧は非同期取得順序に依存するため、ready computed＋skeleton で描画をゲート（`feedback_async_ordered_list_gate_render`）。
- **公開面のバッジ**: 公開ページ（F19.1）は未ログインで動くため、`TrustBadge` の取得 API は認証ヘッダなしで成功すること（permitAll・[03 §2](03_security.md)）。
