## 1. 目的・確定範囲

本人が個人ダッシュボードから勉強時間・科目・体重・走行時間・強度・メニュー等を記録し、自分の振り返りに使う。希望する場合だけ、本人が所属するチームとチーム管理者が定義したテンプレートを選び、共有内容を確認して投稿する。1原本が同時に共有できる先は1チームとする。非共有でも保存と個人グラフを利用でき、所属チームが0件でも利用できる。

共有先の既存タイムラインへ表示し、チーム専用の活動履歴では人・期間・テンプレートで絞り込む。努力由来カードには、いいね・みたよ・コメント・返信・引用・再投稿を付けず、フレンドチーム転送・外部公開も禁止する。この制限は既存の通常投稿やF06.4の活動コメントを廃止するものではない。通知配信・ランキング・ポイント・公開URL・添付・自由な計算式・外部連携は今回の範囲外。

## 2. 画面・導線

F02.2.2の固定5カテゴリを維持し、「マイコンテンツ・所属」に新規ウィジェット `personal-effort` / BE `PERSONAL_EFFORT` を追加する（従来24件から25件、同カテゴリ末尾）。既存表示/順序設定に従い、新規キーは既定表示とする。カテゴリの作成・移動機能は追加しない。全件非表示時も設定画面と個人メニュー「頑張り記録」から `/my/effort-records` へ到達できる。

### 2.1 初回保存と共有確認のAPI順序

入力画面には「共有内容の確認前に個人記録を保存します。共有をやめても個人記録は残ります」と表示する。UUIDが必要なpreviewのために、画面表示・チーム選択・入力変更だけで原本を暗黙保存しない。「保存して共有」という省略表記は用いず、上記の二つの明示操作を区別する。

- 新規の「自分だけに保存」: 入力検証 → `POST /effort-records/me` → 応答のUUID/versionを同じ画面へ保持 → 個人保存済みを表示。preview/共有APIは呼ばない。
- 新規の「保存して共有内容を確認」: 入力検証 → `POST /effort-records/me` を1回 → UUID/versionを保持して保存済みを表示 → `POST /effort-records/me/{id}/team-share/preview` → 同じ画面でpreviewを表示。preview失敗時も個人保存済みを維持する。
- previewの「この内容を共有」: `PUT /effort-records/me/{id}/team-share` にpreviewTokenと現在versionを送る。原本POSTを再送しない。応答の共有状態を表示する。
- previewの「入力へ戻る」または共有取消: 共有APIを呼ばず、保存済み個人原本は残す。原本も消したい場合は通常の明示削除操作を使う。previewToken期限切れだけでは原本を削除しない。
- 既存原本で未保存変更なしの「共有内容を確認」: 原本GETのUUID/versionからpreviewへ進む。変更ありならボタンを「変更を保存して共有内容を確認」とし、`PUT /effort-records/me/{id}` の成功後に返却versionでpreviewする。既存原本から新規原本POSTを行わない。

通信切断後は同じcreate Idempotency-Keyの再送で元UUIDを回復し、別keyで複製しない。previewから戻って入力を修正した場合も、既に得たUUIDへのPUTとする。共有先・テンプレート・mapping・allowlistだけの変更では原本を増やさず、新previewを取得する。

私的メモは原本専用の別欄とし、共有checkbox自体を置かない。必須項目を含め共有フィールドは本人が選ぶ。未選択はprivateに残り、共有欄には出ない。空allowlistでの共有は拒否する。preview後の原本・テンプレート変更はpreviewを失効させ、再確認を求める。編集でフィールドが追加されても既存allowlistへ自動追加しない。

保存と共有は別結果として表示する。「個人保存済み／共有準備中」「共有済み」「共有失敗・再試行」「共有取消済み」「管理者が非表示」を区別し、共有失敗を個人保存失敗や空一覧として表示しない。取消中は即座に共有読取を止める。管理者非表示を本人の編集・再試行で解除しない。

loading/error/empty/loadedを分離し、DashboardWidgetCard、SectionCard、PageHeader、PageLoading、DashboardEmptyState、DashboardErrorState、useErrorHandler、useNotificationを使う。390pxで横はみ出しなし、44px操作領域、入力16px以上、キーボード操作・項目ラベル・エラー読み上げを必須とする。グラフは色だけに依存せず凡例と数値表を併設する。

## 3. テンプレートと数値の意味

非共有はユーザーに紐づく設定不要の標準プリセット（STUDY_V1、EXERCISE_V1、WEIGHT_V1）を選べる。プリセットは固定の定義UUIDとstable field keyを持ち、6言語の表示キーを返す。勉強は科目＋分数、運動は分数＋強度＋メニュー、体重はkg。個人によるテンプレート作成は追加しない。チーム共有は既存 `GET /api/v1/activity-templates?scope_type=TEAM&scope_id=...` の所属確認済みTEAMテンプレートだけ使用する。

private原本の作成時に定義をsnapshotとして凍結する。共有時に別TEAMテンプレートを選べるが、元記録を増やさず共有専用mappingとtarget定義snapshotだけを作る。互換semantic/unit/typeの入力値を引き継いで本人確認し、不足値だけ補う。mapping/共有allowlistはtarget field keyに束縛し、私的noteを元にしない。チームの定義が改名・変更・廃止されても原本の表示・グラフを維持する。新しい定義を選ぶ操作は新規記録として扱い、既存記録のtemplate identityを編集しない。保存済みsnapshotの値編集は廃止後も本人に許可する。廃止後の新規共有・取消後の再共有は拒否し、既存共有の同一定義での訂正と取消は許可する。

既存テンプレートはBIGINTなのでUUIDへ移行しない。個人集計用のdefinitionUuidは新規effort定義対応表で発番し、既存TEAM templateIdをID参照で結ぶ。初回利用時の一意作成を保証する。template UUID、stable field key、canonical unit、semanticの4要素がseries identityである。フィールド名変更は同じ意味なら同一key、型・単位・意味変更は新keyを採番し、古いseriesと混ぜない。既存field IDから初期keyを固定生成し、管理者編集時にkeyの使い回しを検証する。

| semantic / unit | 入力と集計 |
|---|---|
| DURATION / MINUTE | 0〜1440、整数分。期間SUM。別記録の重複時間は自動判定せず、そのまま合計 |
| WEIGHT / KILOGRAM | 0より大、1000以下、小数2桁。推移は日内最新（updatedAtではなくcreatedAt,id降順）。平均・SUMにしない |
| INTENSITY / RPE | 0〜10、整数。カテゴリとして表示し、時間と足し合わせない |
| SUBJECT / NONE | 1〜100文字、選択肢はstable option keyと当時のlabelをsnapshot。科目時間内訳のカテゴリ |
| MENU / NONE、TEXT / NONE | 最大2000文字。集計しない。HTML解釈しない |
| NUMBER / 管理者の単位 | 0〜999999999.99、小数2桁。負数・NaN・Infinity・桁超過拒否。SUM可否はsnapshotのsemanticで決定し、未知の意味は集計不可 |

durationは最大1項目、subjectも最大1項目の対応をsnapshotに明示する。科目内訳は同一definitionUuidのdurationとsubjectの対応がある場合だけ提供する。未入力はnull（未記録）、0は明示的な記録。必須欄はnull・空文字・空白のみを拒否し、任意欄の空文字はnullに正規化する。任意数値のnullを0へ置き換えない。

### 3.1 期間・グラフの計算

記録日 `recordedOn` は本人が選ぶLocalDate、`recordTimezone` は作成時の本人IANA TZをsnapshotとする。TZ変更で記録日を再計算しない。今日の初期値と未来日判定だけ現在の本人TZを使う。記録日は1900-01-01〜本人TZの今日、期間は両端包含、最大366日。週は月曜〜日曜、月は暦月、年は1/1〜12/31、任意も同じAPIの明示date_from/date_toへ変換する。閏日・DSTでもDATE単位で集計し、時間秒への換算をしない。

週/月は日粒度、年は月粒度、任意は1〜62日=日、63〜366日=月。APIがbucketと使用期間を返し、FEは別集計しない。棒は時間SUM、折線は体重の日内最新（年/月粒度は月内最新）、円は科目別の時間SUMを表示する。未記録bucketはvalue=null/sampleCount=0、明示0はvalue="0.00"/sampleCount>0。折線のnullを線で補間しない。科目未選択かつdurationがある分は専用「科目未指定」カテゴリへ入れ、実在科目名と衝突しないreserved keyにする。

集計はDB DECIMALとJava BigDecimalで行い、内部丸めなし。APIの数値は小数2桁の10進文字列。割合だけ最終表示でHALF_UP小数1桁とし、端数合計が100.0にならない場合があることを説明する。分母が0またはデータなしなら円を描かず、0合計／未記録を別表示し、NaNや架空100%を作らない。異なるseriesを合算しない（勉強と運動の横断SUMは今回なし）。単位変換・体重減少の評価・健康上の推奨値は提供しない。

## 4. 所有権・公開範囲・ライフサイクル

privateは認証主体ownerUserIdだけがCRUD/集計可能。管理者・SYSTEM_ADMINにも本APIでprivate内容を返さない。team projectionは対象チーム所属者のみ読取可能で、チームの公開設定から公開へ昇格させない。共有値・共有対象label・記録日・投稿者公開プロフィールだけを返す。private note、未選択値、private UUID、定義の未選択field、同期内部エラーをteam DTOへ含めない。

F00 ContentVisibilityChecker#canViewUuidとUUID resolverを追加し、私的原本とチーム共有を別source typeとして解決する。タイムライン・専用履歴・詳細・検索/集約フィード・リンク展開・既存反応/返信/引用/再投稿の全経路で適用する。shared source versionが現在の原本contentRevisionと一致し、許可が有効であり、projectionがVISIBLEのときだけ表示する。原本・権限照会失敗や不一致はfail closed。通常のタイムライン更新APIで本文を書換えたり、親IDを指定して返信したりする迂回もBEで拒否する。

| 操作 | 結果 |
|---|---|
| 原本編集 | contentRevision増加で古いprojectionを即読取不可。同じshare UUIDで既存allowlistの値だけ更新。新fieldは非共有 |
| 本人共有取消 | private側許可を先にREVOKED。投影/タイムライン削除遅延でも即非表示。原本と個人集計は維持 |
| 原本削除 | private論理削除＋共有許可失効を同じowner TXで確定。共有側は削除イベントで隠す。本人一覧/集計から除外 |
| 管理者非表示 | チーム管理者によるshareのMODERATED状態を維持。原本維持。本人再試行では復活しない。今回管理者復元UIなし |
| チーム/組織削除 | F00で即deny、team projectionを後処理で論理削除。原本・定義snapshot維持、共有再試行不可 |
| 退会申請 | 既決の退会方針§13.13に従い、共有本文を維持し著者表示だけ退会者へ匿名化。private APIは停止するが撤回期間中の原本を保持し、30日後AccountPurgedEventで消去。共有許可/版を検証する非本文tombstoneを残す。明示取消/削除は別操作として即非表示 |
| チーム共有資格喪失 | 自己脱退・管理者の所属解除・共有可能な所属資格の喪失で自動REVOKED。TEAM側加入期間IDで即非表示、owner後処理遅延でも共有不可。原本/個人グラフ維持、再加入で復活なし |

### 4.1 脱退時の自動共有解除（2026-11-09裁可）

ユーザーは「2。脱退時に自動で共有データが見えなくなる方がチーム管理しやすい」と決定した。自己脱退、管理者による所属解除、その他の当該チームへの共有資格喪失で、既存共有を自動REVOKEDとする。タイムライン・専用履歴・詳細・検索・個人集約・cacheを含む全経路は、TEAM側の現在加入期間IDと共有に束縛された加入期間IDの一致を毎回検証し、退出確定直後から読取をdenyする。ownerシャードの失効イベントを待たない。

個人原本の閲覧/編集/グラフは維持し、再加入でも以前の共有は復活させない。再共有は新しい加入期間IDでlive定義と本人previewを再確認し、新たな共有許可を確定する。旧preview・旧command retry・遅延ackは加入期間ID不一致で拒否する。退出→短時間再加入→旧イベント到着でも、新許可を旧イベントで失効させず、旧許可を復活させない（[加入期間IDの設計](F06.4.1_personal_effort_records_data.md#8-チーム共有資格の権威状態と加入期間id)）。

アカウント退会は既決§13.13に従う別理由であり、本文を保持して著者だけ匿名化する。退会処理に伴う所属整理はACCOUNT_WITHDRAWAL理由として資格履歴を凍結し、明示脱退/所属解除と区別する。同時に明示脱退があれば、その加入期間の失効/REVOKEDを優先し、退会・撤回・匿名化の後処理で覆さない。仕様の未回答事項は解消済み。この反映差分の最終精査を完了した。設計完了は機能実装済みを表さない。

## 5. 実装構成・規模・観測

新規 `effortrecord` ドメインにController、非TX Facade、EffortRecordAccessPolicy、OwnerService、ShareService、StatsServiceとDTOを置く。Policy→AccessControlServiceで所属・既存テンプレート管理権限を確認し、他ドメインRepositoryを呼ばない。private ownerスコープRepositoryはuserIdを必須条件とし、organization_idで無理に束ねない。チームRepositoryはAbstractTenantAwareRepository、organization_id/team_id両方必須。owner DBとteam DBをまたぐTXは作らない。

1記録最大15field、本文JSON合計64KiB、private note2000文字。履歴limit最大100、集計最大366日・最大12series（通常は1series）・1series最大366bucket。SQLはowner/dateまたはtenant/team/dateのindex範囲内だけ読み、全ユーザー横断scan、1行ごとのprofile/template照会、巨大INはしない。profile/可視性確認は1page単位でまとめ、private原本から共有値を組み立てて返す方式を禁止する（許可snapshotだけ利用）。

観測項目はsave/share/update/revoke/moderateの成功失敗数、共有pending滞留時間、F00 deny理由別件数、同期失敗件数、集計latency/走査件数。メトリクスlabelにuserId/shareIdを使わない。ログはrequestId、操作、owner ID、team/organization ID、share UUID、version、結果だけとし、体重・科目・メニュー・note・snapshot・tokenを記録しない。監査は権限変更・共有取消・管理者非表示・削除をF10.3へAFTER_COMMITで記録し、監査失敗を業務TXへ巻き戻さない。同期例外はERROR＋監査、本人へは一般化した失敗状態を返す。

実装時の負荷試験基準は同一条件でowner10万記録・team100万projectionを投入した実MySQL、page20/集計366日を100並列、p95履歴500ms・集計1s以下。測定環境/EXPLAIN/件数を証跡に残す。これは未測定の目標値であり達成済みではない。共有F00照会不能時も値を返さないため、可用性を優先して古いsnapshotを返すキャッシュを作らない。
