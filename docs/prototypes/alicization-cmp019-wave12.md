- 対象: Issue #3483 / PR #3485。募集 NO_SHOW 仮マーク時の本人通知と異議申立期限。
- 環境: 実 BE `localhost:8081`、実 FE `localhost:3003`、実 MySQL、Playwright Chromium。BE は JDK 25 の JAR で起動した。

## 決めたシナリオの実機 E2E

`frontend/tests/e2e/real/cmp-019-wave12-no-show-notification.real.spec.ts` の TEAM / ORGANIZATION 2 ケースとログイン準備が通過した。各ケースで専用募集 2 件と応募者を実 API で作成し、管理者の仮マーク、本人宛て HIGH 通知の API・DB・遷移 URL、本人画面の異議申立、重複送信の拒否、一般会員・他人・所属違い・募集違い・参加者違いの拒否を確認した。通知は 1 件のみで、拒否された操作から通知は増えなかった。各ケース終了後、作成した募集 ID に限って後始末し、専用募集は実 DB で 0 件を確認した。

初回の画面検証では、試験用 FE の `localhost:3003` が BE の CORS 許可に入っておらず、ブラウザの履歴 API 取得が遮断された。試験用 BE の起動引数に `localhost:3003` を追加し、同じシナリオを再実行して通過した。アプリ実装の CORS 設定ファイルは変更していない。

端末への push 受信はローカルに push 購読端末がないため未確認。通知レコードの作成、本人の通知 API、既存配送基盤への経路を確認した。

## 3住民の自由探索

| 住民・配役 | 目的と観測 |
| --- | --- |
| 一般 × 素直（TEAM 会員） | 通知一覧で「もっと読む」を約 15 回使って本人宛ての「欠席が記録されました」を発見し、`/my/no-shows` へ進んだ。[申立前の画面](evidence/cmp019-wave12/general-history.png)では募集 `#90226`、確認待ち、`ADMIN_MARKED`、ISO 形式の日時を確認。理由を入力して申立を完了し、[申立中表示](evidence/cmp019-wave12/general-appeal-submitted.png)は再読込後も維持された。コンソールエラー・失敗 HTTP は観測なし。 |
| ADHD 傾向 × 中断・復帰（組織会員） | ダッシュボードの通知から募集 `#90228` の履歴へ進み、[申立フォーム](evidence/cmp019-wave12/adhd-appeal-form.png)に入力後、別タブへ移動して戻った。入力文は維持され、申立 API は 200、[画面も「異議申立中」](evidence/cmp019-wave12/adhd-appeal-submitted.png)へ変化した。通知既読 API `POST /api/v1/notifications/3188770/read` は 409 を返し、エラー報告パネルが出た。レスポンス本文は未採取。同じタブの背後リンクは開いたモーダルに遮られたため、中断は別タブで確認した。 |
| スマホ片手操作 × 表示崩れ（非会員の応募者） | 390×844 と 360×800 の独立したモバイル Context でログイン。本人の通知 API と履歴 API は 200 で、募集 `#90230` の仮マークと `/my/no-shows` への遷移先を返した。一方、履歴画面は追加待機後も [`loading`（390px）](evidence/cmp019-wave12/mobile-loading-390.png)と [`loading`（360px）](evidence/cmp019-wave12/mobile-loading-360.png)から進まず、UI の通知確認と申立は未達。収集した通信に失敗 HTTP はなく、両幅で画面全体の横はみ出しはなかった。履歴本体と申立ボタンは未表示のため、文字切れやタップ領域は未評価。 |

殿様は一般・中断復帰の画像を実際に確認し、対象記録が申立後に `disputed=1` になったことを実 DB で照合した。モバイルの画像でも `loading` のみを確認した。履歴カードに募集 ID と `ADMIN_MARKED` の内部値、日時文字列しか出ず、対象日時・判定理由・期限を本人が読み取れない点は実画像と現行テンプレートで裏付けた観測である。通知既読 409 とモバイルの読み込み継続は、この実行では原因を特定しておらず、今回の変更に起因する不備として確定していない。
