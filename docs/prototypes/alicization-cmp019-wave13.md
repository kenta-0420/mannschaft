## 決めたシナリオの実機 E2E

`frontend/tests/e2e/real/cmp-019-wave13-no-show-dispute-notification.real.spec.ts` とログイン準備が通過した（2 passed）。専用 TEAM 募集 2 件で、本人の理由付き申立、管理者への NORMAL 通知の API・実 DB 照合、通知 UI から NO_SHOW 管理画面への遷移、理由表示、非本人の拒否、非主催者の通知不在・裁定一覧拒否、連続・並列二重申立の拒否と通知 1 件を確認した。試験の `finally` が作成した募集 ID に限ってアーカイブ・削除する。

初回の実機試験では DB CLI のタブ出力と画面テキストの完全一致指定がテスト側の誤りだった。別の試行では BE 起動時の CORS 環境変数名を誤り、ブラウザの通信が遮断された。これらを修正して同じシナリオを再実行し、green を確認した。失敗試行の専用データはタイトル・ID を照合して個別に片付けた。

## 殿様の裏取りと判定

- [管理画面の画像](evidence/cmp019-wave13/admin-no-shows.png)で申立理由と記録 ID を、[本人履歴の画像](evidence/cmp019-wave13/member-history.png)で申立中の状態を、[権限外画面の画像](evidence/cmp019-wave13/outsider-no-shows-360.png)で記録不表示とトーストの切れを実際に確認した。決めた実機 E2E では管理者通知を UI でクリックして同じ管理画面へ到達した。
- 管理者の探索時、対象通知 `3221495` より後に同じアカウント宛ての通知が実 DB に 290 件存在した。大量の既存・定期通知に埋もれた観測であり、Wave 13 の通知が欠落した事実ではない。通知 UI から古い対象を効率よく探す改善は別件として扱う。
- 本人履歴に異議理由は出ないが、今回の受け入れ条件と F03.11 の記述は主催者が理由を確認して裁定することを要求している。本人向け再表示は探索上の気づきとして残す。
- モバイルの 403 トーストの切れと小さいメニューは画像・寸法の観測にとどめた。今回の通知・認可の成否には影響せず、同条件での CSS 原因確認をまだしていないため、確定不備や blocker にはしない。
