# WeatherAPI.com APIキー ローテーション手順

## 概要

WeatherAPI.com の API キーを安全にローテーションする手順書。

**実施タイミング:**
- 年 1 回（目安: 毎年 1 月）
- API キー漏洩疑いが発生した時（緊急時は末尾の緊急手順を参照）

---

## 前提条件

- WeatherAPI.com 管理画面（https://www.weatherapi.com/my/ ）へのアクセス権限
- 本番環境の環境変数（`WEATHER_API_KEY`）を更新できる権限（インフラ担当者）
- ステージング環境へのデプロイ権限

---

## 手順

### 1. 新規 API キーの発行

1. WeatherAPI.com 管理画面にログインする。
2. **API Keys** セクションを開く。
3. **Add Key** ボタンをクリックし、新しい API キーを発行する。
4. キー名に発行日（例: `mannschaft-prod-20270101`）を含めて識別しやすくする。
5. 新しいキーの値をセキュアなパスワードマネージャーに保管する（Slack / メール等への平文送信禁止）。

### 2. ステージング環境での動作確認

1. ステージング環境の環境変数 `WEATHER_API_KEY` を新しいキーに更新する。
2. アプリケーションを再起動する。
3. 動作確認:
   - `/api/v1/dashboard/weather` エンドポイントに疎通確認リクエストを送る。
   - レスポンスが `200 OK` で返ること、かつ `dataSource: "weatherapi.com"` が含まれることを確認する。
   - Micrometer メトリクス `weather.api.calls{result=success}` がカウントアップされることを確認する。
4. 問題なければ本番適用に進む。問題があれば旧キーに戻して原因を調査する。

### 3. 本番環境への適用

1. メンテナンス時間帯（低トラフィック時間）に実施することを推奨する。
2. 本番環境の環境変数 `WEATHER_API_KEY` を新しいキーに更新する。
3. アプリケーションをローリング再起動する（ダウンタイムなし）。
   - Valkey キャッシュが最大 1 時間のバッファとして機能するため、再起動中もユーザーへの天気情報提供は継続される。
4. 再起動完了後、本番ログに `WeatherAPI.com 取得失敗` エラーが急増していないことを確認する。

### 4. 旧キーの無効化

1. 新キーの適用から **7 日間** は旧キーを残し、問題が出た場合のロールバック手段として保持する。
2. 7 日経過して問題がないことを確認したら、WeatherAPI.com 管理画面から旧キーを削除する。
3. パスワードマネージャーからも旧キーのエントリを削除する。

### 5. 動作確認（本番）

1. アプリケーションログを確認し、以下のエラーが出ていないことを確認する:
   - `WeatherAPI.com 取得失敗`
   - `HTTP 403 Forbidden`（キー無効時に発生）
2. Actuator メトリクスエンドポイントで以下を確認する:
   ```
   GET /actuator/metrics/weather.api.calls?tag=result:success
   GET /actuator/metrics/weather.api.calls?tag=result:error
   ```
   - `error` カウントが急増していないこと。
3. WeatherAPI.com 管理画面でリクエスト数グラフを確認し、新キーでリクエストが正常に計上されていることを確認する。

---

## 不正利用検知

- **WeatherAPI.com 管理画面**: 使用量グラフを**週次**でチェックする。急激な使用量増加は漏洩の兆候。
- **Micrometer メトリクス**: `weather.api.calls{result=error}` の急増（通常比 3 倍以上）を監視する。
  - エラー率 > 10%/h 時は Slack `#ops-alerts` チャンネルにアラートが自動送信される。
- **ログ監視**: `WeatherAPI.com 取得失敗` ログが 1 時間以内に 10 件以上連続する場合は要調査。

---

## 緊急時（API キー漏洩疑い）

**即座に対応すること。Valkey キャッシュが 1 時間バッファとして機能するため、キー失効から再起動まで天気表示が一時的に stale（古いデータ）になるが、サービスは継続する。**

1. WeatherAPI.com 管理画面にログインし、漏洩が疑われるキーを**即座に削除（失効）**する。
2. 上記「手順 1〜5」を通常より迅速に実施する（ステージング確認を簡略化して構わない）。
3. インシデントレポートを `#security-incidents` Slack チャンネルに投稿する:
   - 漏洩発覚の経緯
   - 対応した時刻
   - 新キーの発行・適用完了時刻
4. 原因調査を行い、再発防止策を検討する（ログに平文キーが出ていないかの確認含む）。
