# 番人: BackgroundEntryPolicyDeclarationGuardTest の凍結台帳
# （種別: バックグラウンド入口の未宣言件数と総数）。
#
# 【重要】この台帳は Gate 基盤工事④-B（第二〜四陣）で返済する「残債の台帳」であり、免罪符ではない。
# 新規に足したバックグラウンド入口を宣言せずここへ追記することは禁止する。
# 既存分のみ、④-B の付与作業が未着手である事実として凍結している。
#
# 【行形式】<種別>|<完全修飾クラス名>|<未宣言件数>|<入口の総数（宣言済み＋未宣言）>
# 種別: SCHEDULED / TRANSACTIONAL_EVENT_LISTENER / EVENT_LISTENER / SQS_LISTENER
#
# 【キーはクラス単位。メソッド名は含めない（PR #2725 の事故を踏まえた設計）】
# メソッド名を含めていた初版（DateTimeAndZoneGuardTest）は、本件と無関係なメソッド名変更だけで
# CI を赤くする事故を起こした。同じ轍を踏まないためクラス単位の件数のみを凍結する。
#
# 【なぜ「総数」も凍結するのか】
# 未宣言件数だけを凍結すると、同一クラス内で「既存の1件に宣言を付ける」と
# 「新しい未宣言の入口を1件足す」を同時に行ったとき、未宣言件数が相殺されて
# 台帳と一致したままになり、新しい入口が宣言なしで素通りする。
# 第二〜四陣はまさに「宣言を付けていく」作業なので、この経路は現実に踏まれる。
# 総数を併せて凍結すれば、
#   ・宣言を付けるだけ         → 未宣言 −1・総数 ±0  → chip-away として許可
#   ・入口を新設               → 総数 +1             → 相殺されようがなく検出
#   ・入れ替え（宣言+1・未宣言+1） → 未宣言 ±0・総数 +1  → 検出
# となり、メソッド名を台帳に載せずに穴が閉じる。
#
# 【更新の作法】
# ・宣言を付けたら、そのクラスの行の <未宣言件数> を減らす（0 になっても行は残す。総数の凍結に使う）
# ・入口を新設したら、必ず宣言を付けたうえで <総数> を増やす
# ・クラスごと消えたら行を削除する（陳腐化として検出される）
