# 陣払い（古い足軽worktreeの撤収）

> このスキルは運用作業のため `model: sonnet` 指定（殿のOpus/Fable温存・feedback_opus_infra_ops_danger）。

大名システム（`Agent(isolation:"worktree")`）が残した `.claude/worktrees/agent-*` のうち、
**HEADコミットが指定日数以上前のもの**を安全に撤去する。`$ARGUMENTS` が日数（未指定なら **7**）。


あわせて、放置すると際限なく溜まる次の2つも掃除する（どちらも `git worktree list` に現れないため、
worktree の棚卸しだけでは永久に回収されない）:

- **登録の外れた残骸ディレクトリ** — `git worktree remove` がディレクトリ本体の削除に失敗した跡（手順5）
- **マージ済みローカルブランチ** — worktree を消しても残り続ける（手順6）

これは worktree の git 管理操作であり、本陣で実行してよい例外作業（CLAUDE.md 参照）。

## 厳守する安全則
- 対象は `.claude/worktrees/agent-*` のみ。`dev-main`/`e2e-run`/`bootstrap-apply` 等の **非agent worktree は触らない**。
- **指定日数以内の worktree は残す**（他セッションで稼働中の足軽の可能性があるため）。
- **手順3・4（worktree 撤去に伴うブランチ削除）で消してよいのは、worktree ディレクトリと
  throwaway な `worktree-agent-*` ブランチのみ。**
  `feature/*`・`feat/*` 等のブランチは **温存**（他PR・他セッションが参照しうる。worktree削除でもコミット済み成果は git に残る）。
  **worktree を消したという理由だけで作業ブランチを消してはならない。**
- **手順6だけはこの例外**で、接頭辞ではなく**マージ済みという証拠**で判定する。
  `worktree-agent-*` に限ると `feature/*` が際限なく溜まり（実測 1,001本）掃除の目的を果たせない。
  そこで接頭辞で絞る代わりに、**「main の祖先」または「ローカル先端 SHA がマージ済み PR の
  head SHA と一致」**という中身の証拠で絞る。いずれも成果は main に入り切っており、消しても失われない。
  証拠が無いもの（PR が無い・未マージ・SHA 不一致）は**接頭辞に関わらず温存**する。
- `--force` 削除は **未コミット変更を失う**。dirty な worktree は中身を確認してから削除する（下記手順2）。
- locked な worktree は `--force` でも消えない → **unlock してから削除**（手順4）。

## 手順

### 1. 棚卸し（指定日数以上前の agent worktree を一覧化）
```bash
cd "C:/Claude/mannschaft"
DAYS="$ARGUMENTS"; case "$DAYS" in ''|*[!0-9]*) DAYS=7;; esac   # /陣払い の引数（数値）。未指定/不正なら7
cutoff=$(date -d "$DAYS days ago" +%s)
echo "閾値: $(date -d @$cutoff '+%Y-%m-%d') より前のHEADを対象（$DAYS日以上前）"
git worktree list | awk '{print $1}' | grep "/agent-" | while read -r p; do
  [ -z "$p" ] && continue
  ts=$(git -C "$p" log -1 --format=%ct 2>/dev/null)
  d=$(git -C "$p" log -1 --format=%cd --date=short 2>/dev/null)
  if [ -z "$ts" ]; then echo "ERR  $(basename $p) (log取得不可・stale候補)"
  elif [ "$ts" -lt "$cutoff" ]; then
    dirty=$(git -C "$p" status --porcelain 2>/dev/null | head -1)
    echo "OLD  $d $(basename $p)$([ -n "$dirty" ] && echo ' ⚠dirty')"
  else echo "keep $d $(basename $p)"; fi
done | sort
```

### 2. dirty な OLD worktree の未コミット内容を確認
手順1で `⚠dirty` が付いたものについて、失う未コミット変更が保全価値あるか確認する。
```bash
# 例: git -C ".claude/worktrees/agent-XXXX" status --porcelain | head
```
`.claude/settings.local.json` のみ・診断スクラッチ・放棄テスト等で価値が無ければそのまま撤去してよい。
**実体のあるソース変更が残っていたら、その worktree だけ撤去を保留し殿に報告する。**

### 3. OLD worktree を削除（通常＝非locked）
手順1の `OLD` の ID 群を `OLD=` に列挙して実行。
```bash
cd "C:/Claude/mannschaft"
OLD="<手順1のOLDのID群をスペース区切りで>"
for id in $OLD; do
  p=".claude/worktrees/agent-$id"
  git worktree remove --force "$p" 2>/dev/null && echo "removed agent-$id" || echo "FAILED agent-$id（locked疑い→手順4）"
done
git worktree prune
for id in $OLD; do git branch -D "worktree-agent-$id" 2>/dev/null && echo "branch worktree-agent-$id 削除" || true; done
```

### 4. FAILED（locked）を unlock してから削除
手順3で `FAILED` になったものは locked。20日前等のコミットなら **死んだagentのstale lock** なので unlock して撤去する。
```bash
cd "C:/Claude/mannschaft"
FAILED="<手順3でFAILEDになったID群>"
for id in $FAILED; do
  p=".claude/worktrees/agent-$id"
  git worktree unlock "$p" 2>/dev/null
  git worktree remove --force "$p" 2>/dev/null && echo "removed agent-$id (unlock後)" || echo "STILL-FAILED agent-$id（要手動確認）"
done
git worktree prune
for id in $FAILED; do git branch -D "worktree-agent-$id" 2>/dev/null && echo "branch worktree-agent-$id 削除" || true; done
```

### 5. 登録の外れた残骸ディレクトリを掃除

`git worktree remove` は **`.git` を先に消してからディレクトリ本体を消す**。Gradle デーモン等が
ファイルを掴んでいると本体の削除だけが失敗し、**登録は解除されたのに実体が残る**。この残骸は
`git worktree list` に出ないため手順1の棚卸しにも現れず、誰にも回収されないまま溜まり続ける
（2026-09-04 実測: 44件・8.13GB が滞留していた。1件あたり約 527MB）。

```bash
cd "C:/Claude/mannschaft"
# 登録済み worktree の集合に無いディレクトリ＝残骸
# ⚠️ `--porcelain` は環境によって効かず（ツール出力が加工され素の形式が返る）、
#    awk が何も拾わず「登録済み0件＝全部が残骸」と誤判定する（2026-09-04 実測）。
#    素の形式（第1フィールド＝パス、角括弧内＝ブランチ名）で解析すること。
git worktree list | awk '{print $1}' | xargs -n1 basename | sort > /tmp/registered.txt
# ⚠️ 候補は **ディレクトリのみ**。通常ファイルを巻き込まないこと
find .claude/worktrees -mindepth 1 -maxdepth 1 -type d -printf '%f
' | sort > /tmp/ondisk.txt
comm -13 /tmp/registered.txt /tmp/ondisk.txt > /tmp/orphans.txt

# 安全則どおり **自動削除は agent-* のみ**。それ以外は報告するだけで自動では消さない
grep    -E '^agent-' /tmp/orphans.txt > /tmp/orphans_agent.txt
grep -v -E '^agent-' /tmp/orphans.txt > /tmp/orphans_other.txt
echo "自動対象(agent-*): $(wc -l < /tmp/orphans_agent.txt) 件"
echo "要判断(非agent):   $(wc -l < /tmp/orphans_other.txt) 件"; cat /tmp/orphans_other.txt
```

**削除前の安全確認（必須）**: 残骸には `.git` が無いため git から dirty 判定ができない。
代わりに **main に存在しないパスのファイルが埋もれていないか**を調べる。

```bash
cd "C:/Claude/mannschaft"
git ls-tree -r --name-only origin/main | sort > /tmp/main_files.txt
EXCL='(^|/)build/|(^|/)node_modules/|(^|/)\.gradle|(^|/)\.nuxt/|(^|/)\.output/|(^|/)logs/|(^|/)dist/|(^|/)coverage/|(^|/)test-results/|(^|/)\.claude/|(^|/)\.git($|/)'   # 先頭 / は任意（find の出力はルート相対）
for n in $(cat /tmp/orphans_agent.txt); do
  d=".claude/worktrees/$n"
  if [ -e "$d/.git" ]; then echo "SKIP $n（.git があるため残骸ではない）"; continue; fi
  uniq=$( (cd "$d" && find . -type f | sed 's|^\./||') | grep -Ev "$EXCL" | sort | comm -23 - /tmp/main_files.txt | head -50 )
  if [ -z "$uniq" ]; then echo "SAFE $n"; else echo "CHECK $n"; echo "$uniq" | sed 's/^/    /'; fi
done
```

`SAFE` と判定できたものだけを削除する（`CHECK` は下記の見分け方で個別に判断してから）。

> **非 agent の残骸（`dev-main` / `e2e-run` / 手動で作った worktree 等）は自動では消さない。**
> 安全則どおり、殿が1件ずつ素性を確かめ、マスターに諮ってから撤去すること。
> 一覧は `/tmp/orphans_other.txt` に出ている（放置すると容量を食い続けるため、
> 見えなくするのではなく**可視化して個別判断**する）。

```bash
cd "C:/Claude/mannschaft"
SAFE="<上で SAFE と出た名前をスペース区切りで>"
for n in $SAFE; do
  rm -rf ".claude/worktrees/$n" 2>/dev/null
  [ -e ".claude/worktrees/$n" ] && echo "FAILED $n（プロセスが掴んでいる）" || echo "removed $n"
done
```

> `FAILED` になったら掴んでいるプロセスを特定する。Windows 側は
> `Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*<名前>*' }`、
> **WSL 側は cwd を見る**:
> `for p in /proc/[0-9]*; do case "$(readlink $p/cwd)" in *<名前>*) echo $p;; esac; done`。
> 2026-09-04 には、WSL idle 停止対策で常駐させた `sleep` が当該ディレクトリを cwd に
> していたために消せなかった（cwd を移して張り直したら消えた）。

- **`.git` が残っているものは削除しない**（撤去途中ではなく現役の可能性がある）。手順3へ回す。
- 固有ファイルが出たら、`git log --all -- ':(literal)<path>'` で**リテラル pathspec**として履歴を照会し、
  main から意図的に削除された遺物か、未保全の作業かを見分ける。
  **角括弧を含むパス（`[slug].vue` 等）を素の pathspec で渡すと文字クラスとして解釈され、
  「履歴に無い」と誤判定する。** `:(literal)` を必ず付けること（2026-09-04 実測）。
- なお本手法は「main と同じパスにあって中身だけ変更されたファイル」は検出できない。残骸は既に
  `--force` 撤去が実行済み（＝未コミット変更は当時放棄済み）であることを前提に許容する。

### 6. マージ済みローカルブランチを掃除

ローカルブランチは worktree を消しても残り続け、放置すると数百〜千本規模で溜まる
（2026-09-04 実測: 1,001本）。**削除は本陣で実行してよい**（本陣保護フックが明示的に許可している）。

**判定の要点**: 本リポジトリのマージは **squash** なので、マージ済みブランチのコミットは main の
祖先にならない。`git branch --merged origin/main` はほとんど引っかからず（実測 1,001本中 15本のみ）、
**`-d` は常に「未マージ」として拒否される**。よって判定は **PR のマージ状態**で行い、削除は `-D` を使う。

⚠️ **名前の一致だけで消してはならない。** ブランチはマージ後に削除され、**同じ名前で別の作業が
作り直される**ことがある。名前だけで判定すると、その稼働中の作業を消す。必ず **head SHA まで**
照合し、ローカルの先端がマージ済み PR の head SHA と一致するものだけを消すこと
（2026-09-04 実測: 696本を名前一致で消したところ、6本が名前再利用だった。いずれもリモートに
残っていたため `git fetch origin <名前>:<名前>` で復元できたが、ローカル限りの作業なら失っていた）。

```bash
cd "C:/Claude/mannschaft"
# マージ済み PR の head を ref+SHA の対で全件取得
# （--limit は 1000 で頭打ちになるため API をページングする。実測 2,830件）
gh api --paginate "repos/kenta-0420/mannschaft/pulls?state=closed&per_page=100" \
  --jq '.[]|select(.merged_at!=null)|"\(.head.ref)	\(.head.sha)"' | sort -u > /tmp/merged_pairs.txt

# worktree が使用中のブランチは対象外（git 自身も削除を拒む）
git worktree list | sed -n 's/.*\[\(.*\)\].*/\1/p' | sort -u > /tmp/in_use.txt

# 条件1: main の祖先（通常マージ分。squash 全盛でも取りこぼさないため必ず含める）
# 条件1: main の祖先 かつ throwaway な worktree-agent-*（成果が main に入り切っている使い捨て）
#   ⚠️ 祖先であることは「PR がマージされた証拠」ではない。main から切っただけの診断用・
#      予約用ブランチも祖先になる。接頭辞の条件を外すと安全則の『PR が無いものは温存』を破る。
git branch --merged origin/main --format='%(refname:short)' \
  | grep -E '^worktree-agent-' | sort -u > /tmp/anc.txt

# 条件2: ローカル先端 SHA がマージ済み PR の head SHA と一致（squash マージ分）
git for-each-ref --format='%(refname:short)%09%(objectname)' refs/heads | sort -u > /tmp/local_pairs.txt
comm -12 /tmp/local_pairs.txt /tmp/merged_pairs.txt | cut -f1 | sort -u > /tmp/sha_matched.txt

cat /tmp/anc.txt /tmp/sha_matched.txt | sort -u \
  | comm -23 - /tmp/in_use.txt | grep -vx main > /tmp/to_delete.txt
wc -l < /tmp/to_delete.txt
```

**削除して安全な条件**（どちらかを満たすもののみ。上のコマンドは両方を対象に入れている）:
1. `git branch --merged origin/main` に現れ、**かつ `worktree-agent-*`**（使い捨て。中身は完全に main にある）
   — 祖先であることだけでは PR のマージ証拠にならない。main から切っただけの診断用ブランチも祖先になる。
2. **ローカル先端 SHA が、マージ済み PR の head SHA と一致する**（squash マージ済み）
   — 名前ではなく **SHA** で照合すること。名前一致だけでは再利用されたブランチを巻き込む。

**温存するもの**:
- `main` と、**worktree が使用中**のブランチ
- PR が無い／未マージのブランチ（診断用・実験用・中断中の作業。判定できないものは消さない）

```bash
xargs -a /tmp/to_delete.txt git branch -D
```

> ⚠️ **パイプを付けた形は現行フックの版によっては拒否される**ことがある
> （`git branch -D x | tail` の除外が末尾で閉じられない不具合。PR #3105 で修正）。
> 拒否されたら素の形（パイプ・リダイレクト無し）で実行する。

### 7. 結果報告
```bash
cd "C:/Claude/mannschaft"
echo "残存 agent worktree 総数: $(git worktree list | grep -c '/agent-')"
echo "残骸ディレクトリ: $(comm -13 /tmp/registered.txt /tmp/ondisk.txt | wc -l) 件"
echo "ローカルブランチ総数: $(git for-each-ref --format='%(refname:short)' refs/heads | wc -l)"
```
削除した worktree 件数・残骸ディレクトリ件数と回収容量・削除したローカルブランチ本数と温存本数（およびその理由）・`STILL-FAILED`（あれば原因）を殿が要約してマスターに報告する。

## 注意
- locked が**直近日数**（稼働中の可能性）の場合は unlock/削除しない。本コマンドは閾値より古いものだけを対象とするため通常は安全だが、迷ったら殿が個別判断する。
- `git worktree remove` が Permission denied になるのは Gradle daemon 等のファイルロックが原因のことがある。少し待つか、当該プロセス停止後に再実行する。
