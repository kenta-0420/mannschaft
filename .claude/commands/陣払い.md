# 陣払い（足軽 worktree の安全な撤収）

`.claude/worktrees/agent-*` だけを対象に、単一の実行スクリプトで棚卸しする。既定は **dry-run** であり、実際の撤去は殿が明示した `--apply` のときだけ行う。

```powershell
cd C:\Claude\mannschaft
node scripts/worktree-cleanup.mjs --days 7
node scripts/worktree-cleanup.mjs --days 7 --apply
```

## 安全契約

- 対象は `.claude/worktrees/agent-*` のみ。`feature/*`、非agent worktree、本陣は削除しない。
- `--apply` で撤去できるのは、期限超過かつ clean で、branch が `worktree-agent-*` のものだけ。
- dirty、`git worktree lock`、`index.lock` 検出、Git検査失敗、実行中が疑われるものは理由を出して保持する。`index.lock` はスクリプトが削除しない。
- missing/prunable は分類だけ行い、自動 `git worktree prune` はしない（非agent登録を巻き込むため）。未登録ディレクトリも自動削除しない。
- 登録済み worktree 内の `frontend/node_modules` junction/シンボリックリンクも `nested-junction` として保持する。先にリンク自体だけを外し、リンク先が不変であることを確認してから再実行する。
- junction/シンボリックリンクは必ずリンクだけを先に外す。リンク先や本陣の `node_modules` を巻き込まない。

結果には対象数・削除数・保持数・残存 stale 数・失敗理由が出る。終了ゲートには次を用いる。

```powershell
node scripts/worktree-cleanup.mjs --days 1 --check --limit 60
```

総 worktree が 60 本超、または stale が残れば非0で終了する。dirty/locked 等の理由を解消せずに完了扱いにはしない。

## 追加の手動整備（既存手順を維持）

上のスクリプトは**登録済み agent worktree の棚卸し・撤去だけ**を担当する。以下は別の安全契約を持つ既存運用であり、dry-run の結果を確認してから個別に実施する。無差別な force 削除へ戻してはならない。

### 5. 登録外の残骸ディレクトリを保全確認して整理

`git worktree remove` 後に登録だけ外れ、実体が残ったディレクトリは `git worktree list` に現れない。候補はディレクトリに限定し、登録済みの名前との差だけを可視化する。

```bash
cd "C:/Claude/mannschaft"
git worktree list | awk '{print $1}' | xargs -n1 basename | sort > /tmp/registered.txt
find .claude/worktrees -mindepth 1 -maxdepth 1 -type d -printf '%f\n' | sort > /tmp/ondisk.txt
comm -13 /tmp/registered.txt /tmp/ondisk.txt > /tmp/orphans.txt
grep -E '^agent-' /tmp/orphans.txt > /tmp/orphans_agent.txt
grep -v -E '^agent-' /tmp/orphans.txt > /tmp/orphans_other.txt
```

- 非agent残骸は自動では消さない。殿が素性を確認して個別判断する。
- `.git` が残る候補は現役の可能性があるため削除せず、登録済み worktree の手順へ戻す。
- agent残骸も、まず `origin/main` に無いファイルを確認する。生成物・キャッシュを除外しても固有ファイルが出たら保留し、`git log --all -- ':(literal)<path>'` で履歴を照合する。`[slug].vue` 等で glob 解釈させないため `:(literal)` は必須。
- `SAFE` と保全確認できた**個別パスだけ**を削除する。削除失敗時は Windows の `Win32_Process` と WSL の cwd を確認し、プロセスを特定してから再試行する。junction はリンクだけを外し、リンク先を削除しない。

### 6. squash 済みローカルブランチを PR head SHA で照合して整理

worktree を消してもローカルブランチは残る。本プロジェクトは squash merge のため `git branch --merged origin/main` だけでは不十分であり、**名称一致では削除しない**。使用中の branch を除外したうえで、次のどちらかの証拠があるものだけを候補にする。

1. `origin/main` の祖先で、かつ `worktree-agent-*`（使い捨て branch）である。
2. ローカル先端 SHA が、GitHub 上の merged PR の head SHA と一致する。

```bash
cd "C:/Claude/mannschaft"
gh api --paginate "repos/kenta-0420/mannschaft/pulls?state=closed&per_page=100" \
  --jq '.[]|select(.merged_at!=null)|.head.sha' | sort -u > /tmp/merged_shas.txt
git worktree list | sed -n 's/.*\[\(.*\)\].*/\1/p' | sort -u > /tmp/in_use.txt
git branch --merged origin/main --format='%(refname:short)' | grep -E '^worktree-agent-' > /tmp/ancestor_candidates.txt
git for-each-ref --format='%(objectname)%09%(refname:short)' refs/heads | sort > /tmp/local_by_sha.txt
join -t "$(printf '\t')" /tmp/merged_shas.txt /tmp/local_by_sha.txt | cut -f2 > /tmp/sha_candidates.txt
cat /tmp/ancestor_candidates.txt /tmp/sha_candidates.txt | sort -u | comm -23 - /tmp/in_use.txt | grep -vx main > /tmp/branch_candidates.txt
cat /tmp/branch_candidates.txt
```

候補を目視し、使用中・未マージ・証拠なしを除外してから、**候補名を明示して** `git branch -D <branch>` を実行する。名前の再利用、PR無し、head SHA不一致の branch は温存する。
