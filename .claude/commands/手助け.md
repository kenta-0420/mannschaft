# 手助け（使い方モーダルの作成）

殿として、家老に対象ページを偵察させ、足軽を出陣させて **そのページ専用の「使い方モーダル」** を作る。
モーダルは **PageHeader の `help` フラグ＋`@help`** で開き、中身は **マイプロジェクト（`ProjectGuideModal` / `ProjectGuideContent`）と同じ「色付き丸アイコン＋カード」方式** で、機能ごとに「これは何か → どんな時に使う → 使い方の手順」を**初めて見る人にも分かるよう丁寧に**書く。

> **なぜやるのか**: 画面が増えるほど「どう使えばいいか分からない」が起きる。各ページに統一様式の使い方ガイドを用意すれば、ユーザーが迷わず操作でき、サポート問い合わせも減る。`/手助け` はこのガイド作成を金型どおり再現するためのスキル。

## いつ使うか

- 「この画面の使い方説明を付けて」と言われたとき
- 機能は揃ったが使い方が分かりにくい画面に、ガイドを足したいとき
- 既存の使い方ボタン（直書き）を統一様式のモーダルに寄せたいとき

## 引数

- `$ARGUMENTS` … 対象ページ（`.vue` のパス、または「チャット画面」「シフト希望」などの画面名）。
  画面名で渡された場合は、家老がまず該当 `.vue` を特定する。複数ページ対象なら1ページずつ順に作る（モーダルはページ単位）。

## 金型（必ず参照する手本・これに倣う）

| 役割 | 手本ファイル |
|---|---|
| **モーダル本体（最良の手本）** | `frontend/app/components/project/ProjectGuideModal.vue`（Dialog ラッパー）＋ `frontend/app/components/project/ProjectGuideContent.vue`（カード本体） |
| **第2の実例** | `frontend/app/components/settings/SecurityHelpDialog.vue` ＋ `frontend/app/components/settings/SecurityHelpContent.vue` |
| **呼び出し側の配線** | `frontend/app/pages/my/projects/index.vue`（`<PageHeader ... help @help="showGuide = true">`、末尾に `<ProjectGuideModal v-model:visible="showGuide" />`） |
| **PageHeader の help/actions 内蔵** | `frontend/app/components/PageHeader.vue`（`help` prop＋`@help` emit＋`#actions` スロット。既に内蔵済み・変更不要） |

## 成果物（1ページあたり）

そのページの機能ドメインのコンポーネントディレクトリ（例: チャットなら `components/chat/`）に2ファイル新設し、ページとロケールを配線する。

1. **`<Xxx>GuideContent.vue`** … カード本体（`ProjectGuideContent.vue` を写経）
2. **`<Xxx>GuideModal.vue`** … Dialog ラッパー（`ProjectGuideModal.vue` を写経。`#footer` に閉じるボタン）
3. **対象ページ `.vue`** … `const showGuide = ref(false)` を足し、`<PageHeader ... help @help="showGuide = true">`、テンプレート末尾に `<XxxGuideModal v-model:visible="showGuide" />`
4. **i18n** … `frontend/app/locales/{ja,en,zh,ko,es,de}/<適切な>.json` に `<xxx>_guide`（または既存 namespace）でキー追加。**6言語すべて・キー構造完全一致**。まず ja を丁寧に書き、他5言語は ja コピー可（後で翻訳）。

### コンポーネント雛形

`<Xxx>GuideModal.vue`（`ProjectGuideModal` と同一構造）:
```vue
<script setup lang="ts">
/** <画面名>の使い方を案内するモーダル。v-model:visible で開閉。本体は <Xxx>GuideContent に分離。 */
const visible = defineModel<boolean>('visible', { default: false })
</script>

<template>
  <Dialog
    v-model:visible="visible"
    modal
    :header="$t('<xxx>_guide.title')"
    class="w-full max-w-2xl"
    data-testid="<xxx>-guide-modal"
  >
    <div class="overflow-y-auto py-2">
      <XxxGuideContent />
    </div>
    <template #footer>
      <Button :label="$t('button.close')" icon="pi pi-times" text @click="visible = false" />
    </template>
  </Dialog>
</template>
```

`<Xxx>GuideContent.vue`（`ProjectGuideContent` の写経。各機能＝1カード）:
```vue
<script setup lang="ts">
const { t, tm } = useI18n()
type StepRecord = Record<string, string>
// 連番ステップ（step1, step2...）を順序付き配列へ正規化（tm() の値を t() で個別解決）
function resolveSteps(key: string): string[] {
  const raw = tm(key) as StepRecord | null
  if (!raw || typeof raw !== 'object') return []
  return Object.keys(raw).map((k) => t(`${key}.${k}`))
}
const setupSteps = computed<string[]>(() => resolveSteps('<xxx>_guide.<section>.steps'))
</script>

<template>
  <div class="space-y-4">
    <p class="text-sm leading-relaxed text-surface-600 dark:text-surface-300">
      {{ t('<xxx>_guide.description') }}
    </p>

    <!-- 機能ごとに1カード -->
    <SectionCard>
      <div class="flex items-start gap-4">
        <div class="flex h-10 w-10 shrink-0 items-center justify-center rounded-full bg-blue-100 text-blue-600 dark:bg-blue-900/30 dark:text-blue-400">
          <i class="pi pi-<icon> text-xl" aria-hidden="true" />
        </div>
        <div class="w-full">
          <h2 class="mb-2 text-lg font-semibold">{{ t('<xxx>_guide.<section>.title') }}</h2>
          <p class="mb-3 text-sm leading-relaxed text-surface-600 dark:text-surface-300">
            {{ t('<xxx>_guide.<section>.body') }}
          </p>
          <!-- 手順は番号付きリスト -->
          <ol class="list-decimal space-y-1 pl-5 text-sm text-surface-600 dark:text-surface-300">
            <li v-for="(step, i) in setupSteps" :key="i">{{ step }}</li>
          </ol>
        </div>
      </div>
    </SectionCard>
  </div>
</template>
```

### カードの装飾パターン（`ProjectGuideContent` 準拠）

- アイコンは **色付き丸**: `flex h-10 w-10 shrink-0 items-center justify-center rounded-full bg-{color}-100 text-{color}-600 dark:bg-{color}-900/30 dark:text-{color}-400` ＋ `<i class="pi pi-XXX text-xl" aria-hidden="true" />`
- 色はカードごとに変える（例: blue / green / violet / amber / teal）。アイコンは内容に合うもの（`pi-shield` 安全 / `pi-desktop` 端末 / `pi-key` 鍵 / `pi-exclamation-triangle` 注意 / `pi-users` 共有 / `pi-calendar` 予定 / `pi-comments` チャット 等）
- 手順 → **番号付きリスト** `list-decimal`／要点 → `pi-check text-green-500` の箇条書き／注意・補足 → `rounded-lg bg-surface-50 p-3 dark:bg-surface-800` ＋ `pi-info-circle` の囲みボックス
- ダイアログ内なのでカードの入れ子は避け、見出し `h2`＋本文＋リストで構成

## 偵察ファースト（内容を捏造しない・最重要）

**使い方の文章は、対象ページの実コードを読んでから書く。** 想像で機能を捏造しない（メモリ `feedback_empirical_bug_detection_over_speculation`）。家老は対象 `.vue` と関連 composable を読み、次を洗い出して「カード割り」を作る:

- そのページに**実在する機能セクション**（フォーム・一覧・タブ・ボタン・ダイアログ等）
- 各機能の**操作手順**（どのボタンを押すと何が起きるか。`@click` ハンドラ・呼んでいる API・遷移先を確認）
- **状態や制約**（権限で出る/出ないボタン、必須項目、上限、「現在」タグのような特別表示、削除不可などのガード）
- **つまずきポイントと対処**（エラーになりやすい操作、復旧手順）があれば1カード設ける

書きぶりの方針:
- **初めて触る人前提**で、専門用語は噛み砕く（例: 生の英字列は「ブラウザとOSの情報です」と補足）
- **入力摩擦の低い導線を優先して案内**（マスターはADHD傾向。最短ルートを先に・難しい設定は後述。メモリ `user_adhd_tendency`）
- 命令形で短く。1カード＝1トピック。手順は番号付きで「上から順にやれば終わる」形に

## i18n ルール

- 文字列は**直書き禁止**。`<xxx>_guide`（例 `chat_guide` / `shift_guide`）を新設するか、その画面ドメインの既存 json に追記。
- **6言語**（ja/en/zh/ko/es/de）すべてに、**同一キー構造**で追加。ja を正に丁寧記述、他はとりあえず ja コピー可（後で翻訳）。
- ボタン「閉じる」は既存 `button.close`、ヘッダーボタンのラベルは PageHeader 側 `button.help`（追加不要）。
