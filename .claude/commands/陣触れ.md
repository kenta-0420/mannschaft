# 陣触れ（フロントエンド起動）

Nuxt 開発サーバーを起動する。
**使い方**: `/伝令` の後に `/陣触れ` を実行。バックエンドとフロントエンドが揃い、開発環境が整う。

## 前提条件

- `/伝令` 済みであること（Spring Boot 稼働中 + swagger.json 取得済み）

## 手順

### 1. 本陣を最新 main に同期（pull）

FE dev サーバーは本陣ディレクトリ（`C:\Claude\mannschaft\frontend`）をそのまま配信するため、
起動前に origin/main の最新を取り込まないと、マージ済みの修正が反映されず**古いコードのまま起動**してしまう。
PowerShell で実行する（Bash の本陣 git ブロックを回避するため。`--ff-only` なので分岐があれば安全に中断する）。

```powershell
git -C "C:\Claude\mannschaft" pull --ff-only
```

> ローカルに未コミットの変更があると pull は中断する。意図しない差分（改行コードのみ等）であれば
> `git -C "C:\Claude\mannschaft" checkout -- <該当ファイル>` で破棄してから再実行する。

### 2. 既存プロセス停止

3000 ポートで既に起動している場合は停止する（再起動のため）。
`lsof` は Git Bash から Windows プロセスを検出できないため PowerShell を使う。
PID 0（TimeWait の残骸）を除外して実プロセスのみ対象にする:

```powershell
$conn = Get-NetTCPConnection -LocalPort 3000 -ErrorAction SilentlyContinue | Where-Object { $_.OwningProcess -gt 0 } | Select-Object -First 1
if ($conn) {
    Stop-Process -Id $conn.OwningProcess -Force -ErrorAction SilentlyContinue
    Write-Host "既存の Nuxt プロセスを停止しました (PID: $($conn.OwningProcess))"
    Start-Sleep -Seconds 2
} else {
    Write-Host "既存プロセスなし"
}
```

### 3. 依存パッケージ確認

node_modules が存在しない場合のみインストールする:

```bash
if [ ! -d "/C/Claude/mannschaft/frontend/node_modules" ]; then
  echo "node_modules が見つかりません。npm install を実行します..."
  cd /C/Claude/mannschaft/frontend && npm install
fi
```

### 4. Nuxt 開発サーバー起動

バックグラウンドで起動し、ログをファイルに記録する:

```bash
cd /C/Claude/mannschaft/frontend && npm run dev > /tmp/nuxt-dev.log 2>&1 &
echo "Nuxt 起動中... (PID: $!)"
```

起動完了を待機（最大60秒）:

```bash
echo "Nuxt 起動待機中..."
for i in $(seq 1 60); do
  if curl -s -o /dev/null -w "%{http_code}" http://localhost:3000 2>/dev/null | grep -q "200"; then
    echo "起動確認 (${i}秒)"
    break
  fi
  sleep 1
  if [ "$i" -eq 60 ]; then
    echo "ERROR: 60秒以内に起動しませんでした"
    echo "--- ログ末尾 ---"
    tail -20 /tmp/nuxt-dev.log
    exit 1
  fi
done
```

### 5. 結果報告

| 項目 | 状態 |
|------|------|
| 本陣 pull | ✅ / ❌ |
| Nuxt 起動 | ✅ / ❌ |
| URL | http://localhost:3000 |

✅ なら「**陣触れ完了。フロントエンド陣営、出陣準備整いました。http://localhost:3000**」と報告する。
❌ の場合は `/tmp/nuxt-dev.log` の末尾を確認し、原因を提示する。

## 検証・E2E 用 worktree で起動する場合（ポート 3001）

本陣の dev サーバー（3000）と並行で、検証・E2E 用に**本陣と別 worktree** で起動するときは、衝突を避けるため **FE を 3001 固定**で起動する（BE は `/伝令` を 8081 で起動。CLAUDE.md「常駐サーバーのポート規約」参照）:

```bash
cd <worktreeのfrontend> && npm run dev -- --port 3001 > /tmp/nuxt-dev-3001.log 2>&1 &
```

このとき API 接続先（`NUXT_PUBLIC_API_BASE` 等）が検証用 BE（8081）を指すよう環境変数も合わせること。

## 備考

- Nuxt の停止は `/撤収` に追加するか、PowerShell で `Stop-Process -Id (Get-NetTCPConnection -LocalPort 3000 | Where-Object { $_.OwningProcess -gt 0 }).OwningProcess -Force` で手動停止
- ポートが 3000 以外になる場合（競合時）はログで確認する
- `swagger.json` を更新した場合は Nuxt の型生成が自動で走る（Nuxt の設定による）
