# 統一（デザイン統一・共通コンポーネントへの寄せ）

殿として、家老に「直書きされたUIパターン」を偵察させ、足軽を出陣させて **共通コンポーネント・共通 Composable へ寄せ、画面のデザインを一元化** する。

> **なぜやるのか**（FE規約 §3a）: 同じUIパターンを各ファイルに直書きすると、デザイン変更・バグ修正のたびに数十〜百以上のファイルを直す羽目になる。共通部品へ一元化すれば **1箇所直せば全体に反映** される。`/統一` はこの「寄せ」を機械的に遂行するためのスキル。

## いつ使うか

- 新規ページ／既存ページで、共通部品を使わず Tailwind を直書きしてデザインがバラついているとき
- 「PageHeader をちゃんと使ってデザインを揃えて」と指示されたとき
- レビュー（`/検分`）で直書きUIが見つかり、まとめて寄せたいとき

## 引数

- `$ARGUMENTS` … 対象範囲（例 `/統一 frontend/app/pages/teams`、`/統一 市の画面まわり`）。
  **省略時は現在の変更差分**（`git diff --name-only origin/main...HEAD` の `*.vue`）を対象にする。範囲が広すぎると足軽が溢れるので、指定があればそれを優先する。

## 正準カタログ（寄せ先・FE規約 §3a が一次情報）

新規・既存問わず、UI は必ず下記の共通部品へ寄せる。**直書き（右列）は禁止**。

### 共通コンポーネント

| 用途 | 寄せ先 | 直書き禁止パターン |
|---|---|---|
| ページヘッダー（タイトル＋戻る） | `<PageHeader title="..." />` | `<h1 class="text-2xl/4xl font-bold ...">` の直書き |
| ページ内セクション・カード | `<SectionCard>` | `rounded-xl border border-surface-* bg-surface-0 ...` の直書き |
| ダッシュボードウィジェット | `<DashboardWidgetCard>` | 同上のカード直書き |
| ローディング表示 | `<PageLoading>` | `<ProgressSpinner>`・独自スピナーの直書き |
| 空状態表示 | `<DashboardEmptyState>` | `flex flex-col items-center text-center ...` の直書き |
| 削除・操作確認 | `<ConfirmDialog>`(PrimeVue) / `useConfirm()` | ネイティブ `confirm()` |

### 共通 Composable

| 用途 | 寄せ先 | 直書き禁止パターン |
|---|---|---|
| API エラー処理 | `useErrorHandler()` | `try/catch` + `console.error` |
| フィールドエラー表示 | `useErrorHandler().getFieldErrors()` | `fieldErrors.value = {}` の自前管理 |
| トースト通知 | `useNotification()` | `useToast()` の直接呼び出し |
| ページネーション | `usePagination()` | `page`/`rows`/`totalRecords` の個別管理 |

> 共通部品が要件に合わない場合でも **直書きで逃げない**。props を足してコンポーネント自体を拡張する（§3a「判断基準」）。

## PageHeader の正しい使い方（最重要・メモリ `project_pageheader_backbutton_optout`）

`PageHeader` は **戻るボタンをデフォルト ON で内蔵**（opt-out 方式）。**手動で `<BackButton>` を併置するのは禁止**（CI ガードテストで fail する）。

- 戻り先固定: `<PageHeader title="..." back-to="/my" />`（動的は `:back-to="`/teams/${slug}`"`）
- 戻り先なし: 何も付けない（既定で `router.back()`）
- **戻るボタンは必ず表示する**（`:back="false"` は原則禁止）
- カスタムラベル: `back-label`。i18n の正キーは **`button.back`**（`common.button.back` は**存在しない誤キー**）
- `class` 等のフォールスルー属性はタイトル行に束ねられる（`<PageHeader class="...">` は従来どおり効く）
- **例外**: 権限拒否フォールバック分岐（`v-else-if="permissionDenied"`）内は PageHeader 非描画ゆえ `<BackButton>` 温存可（ガード allowlist 済み）

## 直書きの探し方（偵察の起点 grep）

家老／足軽は次のパターンを起点に対象を洗い出す（あくまで起点。文脈で誤検出を除外する）:

```bash
# PageHeader を使わず h1 を直書きしているページ
grep -rln 'text-\(2\|3\|4\)xl font-bold' frontend/app/pages | xargs grep -L 'PageHeader'
# カード div の直書き
grep -rn 'rounded-xl border border-surface' frontend/app/pages frontend/app/components | grep -v 'SectionCard\|DashboardWidgetCard'
# 独自スピナー
grep -rn 'ProgressSpinner\|animate-spin' frontend/app/pages
# ネイティブ confirm / 自前 try-catch + console.error / useToast 直呼び
grep -rn 'window\.confirm\|[^.]\bconfirm(' frontend/app/pages
grep -rn 'console\.error' frontend/app/pages
grep -rn 'useToast()' frontend/app/pages
# PageHeader と BackButton の併存（CIガード対象・直ちに是正）
grep -rl 'PageHeader' frontend/app/pages | xargs grep -l 'BackButton'
```

## 手順（大名システム必須）

> CLAUDE.md の大名システム厳守。**本陣（`C:\Claude\mannschaft` 直下）で直接 checkout・編集・commit しない**。必ず `Agent(isolation:"worktree")` 経由で worktree 隔離する。複数ページにまたがる寄せは並行足軽で分担する。

1. **偵察（家老 / `Explore`）**: 対象範囲に対し上記 grep を回し、寄せるべきファイルと「どの直書き → どの共通部品」の対応表を作る。誤検出（既に共通部品を使っている・例外 allowlist）を除外する。
2. **陣立て上奏**: 対象ファイル一覧・寄せ方針・分担（足軽 N 隊）をマスターに提示し御裁可を得る。範囲が小さく自明なら殿の裁量で着手してよい。
3. **出陣（足軽 / `Agent(isolation:"worktree", model:"sonnet")`）**: 各隊が担当ファイルを共通部品へ書き換える。
   - **model は必ず明示する**（省略は親モデル継承＝高価モデル浪費。デザイン寄せは sonnet 既定、単純置換のみなら haiku、判断が重い難所のみ opus。`feedback_model_routing`）
   - **見た目を変えない寄せが基本**（リファクタ）。意図的なデザイン変更が要るなら必ずマスター確認。
   - 文字列は **i18n 直書き禁止**。既存キーを使うか 6 言語に追加してから `$t('key')`。
   - `any` 禁止・生成型優先。`BackButton` の手動併置は作らない。
4. **検証（各足軽が自分の worktree で必ず実走）**:
   ```bash
   cd frontend
   npx vitest run tests/unit/pageheader-backbutton-coexistence.spec.ts   # PageHeader×BackButton 併存ガード
   npm run typecheck
   npm run lint
   ```
   足軽の「typecheck 通った」自己申告は鵜呑みにせず、殿が裏取りする（メモリ `feedback_empirical_bug_detection_over_speculation`）。
5. **統合・検分**: コミット済み worktree を本陣へ `git merge`（マージは `gh`／worktree 経由・本陣 git 禁止）。`/検分` で「直書き残存ゼロ・デザイン差分が意図どおり・ガード緑」を照合してから上奏。

## 守ること（やってはいけないこと）

- **見た目を勝手に変えない**。`/統一` は原則 *寄せ（リファクタ）* であり、デザイン刷新ではない。配色・余白を変えるなら別途マスター承認。
- **対処療法で逃げない**（根治治療の原則）。共通部品が合わないからと直書きに戻すのではなく、部品を拡張する。
- **i18n 直書き禁止**・`any` 禁止・`types/generated/` 直接編集禁止。
- **PageHeader に手動 BackButton を併置しない**（CI ガードで弾かれる）。
- 本陣で直接コミットしない（worktree 隔離・`/検分` 後に統合）。
