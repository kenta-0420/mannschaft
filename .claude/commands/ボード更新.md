# ボード更新（棚卸しボードの再生成・再公開）

殿様として、β機能棚卸し台帳（正本）を読み直し、棚卸しボード（Artifact のWebページ）を
最新の中身へ差し替えて**同じURL**へ再公開する。

## 位置づけ（正本と投影）

- `docs/inventory/feature-inventory.yaml` が**正本**、棚卸しボードは**投影（生成ビュー）**にすぎない。
  ボードを手で編集して正本と食い違わせてはならない。差分が出たら必ず正本側を直し、ボードは
  本スキルで機械的に再生成する。
- ボードは claude.ai の Artifact として公開されており、**同じ `file_path` で再公開すれば同じURLが保たれる**。
  現在のボードURLは以下の通り。

  ```
  https://claude.ai/code/artifact/d576b6ca-7eef-4090-b37c-e9794b826e17
  ```

  もしこのURLが失われていたら `Artifact` ツールの `action: "list"` で探すか、上記URLを `url` パラメータに
  渡して更新する。**`url` を渡さずに新規publishすると別URLが発行されてしまう**（マスターが共有している
  リンクが無効になる）ので、必ず既存URLへの更新として扱うこと。

## 手順

### 1. 正本を読む

本陣の作業木は古い可能性があるため、`origin/main` の最新版を直接読むのが安全である。

```bash
git fetch origin main
git show origin/main:docs/inventory/feature-inventory.yaml
```

冒頭コメントの語彙定義（実装状態・検証状態・β区分・layer 等）を必ず読み直し、下記「集計ルール」の
前提が変わっていないか確認する。台帳のスキーマは番人 `FeatureInventorySchemaGuardTest`
（`backend/src/test/java/com/mannschaft/app/common/architecture/`）が守っているため、
台帳側に見慣れない語彙が増えていた場合は番人が更新されている＝集計ルールも合わせて見直す合図である。

### 2. 集計する

下記「集計ルール」に従い、`records` の各レコードを分類する。

### 3. HTMLを組み立てる

既存ボードの意匠（下記「HTML構造」）を保ったまま、集計結果で中身だけ差し替える。
**毎回ゼロから意匠を考えないこと。** 骨子をコピーし、カード・チップ・統計の中身だけ置き換える。
HTMLはスクラッチパッドディレクトリに書く。

### 4. 再公開

`Artifact` ツールで**同一 `file_path`**（またはURLを直接指定）で publish する。
- `favicon` は 📋 のまま変えない
- `title` も変えない（タブとギャラリーでの同一性を保つため。ArtifactのURLはfile_path一致か
  `url` 指定でのみ維持される）

### 5. 報告

何が変わったか（前回のボードとの差分。列間移動した feature_key、新規追加・削除された blockers 等）を
時代劇口調の表で上奏する。

`--dry-run` 指定時は手順2の集計結果だけを報告し、手順3以降（HTML組み立て・再公開）は行わない。

## 集計ルール

### CORE（`layer: 能力` かつ `release.beta: コア`）

カンバン列に振り分ける。列の判定は**上から順に評価し、最初に条件へ当たったものを採る**（後続の条件は評価しない）。

1. **不備あり**: `implementation` のいずれかが `不具合あり`、または `blockers` が非空
2. **未棚卸**: `implementation` の全項目が `不明`
3. **実装未完**: `implementation` のいずれかが `未実装` または `部分実装`
4. **検証中**: `implementation` が全て `実装済`/`対象外` かつ、`verification` のいずれかの軸が
   `未実行`/`失敗中`/`未作成`
5. **β準備完了**: `implementation` が全て `実装済`/`対象外` かつ、`verification` の主要軸が `通過`

どれにも当たらないもの（例: 実装は全て `実装済`/`対象外` だが `verification` が空 `{}` で
検証状況の記載自体が無いレコード）は「未棚卸」に寄せる。**検証未着手を「β準備完了」側に楽観的に
倒さないこと** — 記載が無いのは「安全」ではなく「まだ分からない」であり、灰色（未棚卸）で正直に見せる。

### 非CORE（`layer: ドメイン`）

`release.beta`（`停止` / `内部限定`）別にグリッド表示する。`blockers` が非空なら警告チップを添える。

### 統計（ヘッダに表示）

- 総レコード数
- CORE数（`layer: 能力` かつ `release.beta: コア`）
- `blockers` を持つレコード数（CORE・非CORE合算）
- `release.deploy_safety: デプロイ阻害` のレコード数

### 検算（2026-08-19時点の台帳での実測値。ルール確認の参考値であり、都度再集計すること）

- 総レコード数 43（CORE 25 / 非CORE 18）
- CORE カンバン内訳: 不備あり 4（personal-profile / village-events / dashboard / reservation）、
  未棚卸 20、実装未完 0、検証中 1（timeline）、β準備完了 0
- 非CORE: 停止 16 / 内部限定 2、うち blockers 非空 5
  （shift / billing-payment / promotion / gdpr-disclosure / webhook-sync）
- `blockers` 非空の合計 9（CORE 4 + 非CORE 5）
- `deploy_safety: デプロイ阻害` は 0 件（現状は全レコードが `不明`）

## HTML構造（既存ボードの意匠。骨子はそのまま踏襲する）

- ライト/ダーク両対応のCSSトークン。`:root` にライトパレットを定義し、
  `@media (prefers-color-scheme: dark)` は `:root:not([data-theme="light"])` でガード、
  `:root[data-theme="dark"]` でも同じ値を再定義する（どちらの向きの明示切替にも対応するため）。
  `body` には必ずトークン由来の `background` を敷く（透過させると host のテーマに乗っ取られる）。
- セマンティックカラー: 緑=完了/通過、青=進行中、黄=要対応、赤=不備、灰=不明
- セクション構成（上から）:
  1. ヘッダ（タイトル＋統計チップ。上記「統計」の4項目）
  2. CORE能力カンバン（5列: 不備あり／未棚卸／実装未完／検証中／β準備完了）
  3. Gate基盤工事の進捗（下記「手で足す情報」参照。YAMLに無いので殿が判断して記す）
  4. 非COREドメイングリッド（`release.beta` 別に区画。停止／内部限定）
  5. 住民からの報告（`/アリシゼーション` 結果。下記「手で足す情報」参照）
- カードは左端に状態色のストライプ（`border-left` 4px 程度）、`feature_key` を等幅フォント・小文字で添える
  （台帳の一意キーであり、正本への参照として常に見える位置に置く）
- 横スクロールはカンバンのコンテナ内（`overflow-x: auto` の列コンテナ）に閉じる。`body` 自体を
  横スクロールさせない
- 日本語フォントスタック、数値は `font-variant-numeric: tabular-nums`

## 手で足す情報（YAMLに存在しないもの）

### Gate基盤工事の進捗

台帳には記載が無い。以下4段の工事の状態は、**殿が `docs/task-list.md` と PR の実状から判断して記す**
（YAMLへ機械的に反映される項目ではないため、都度の裏取りが必須）。

1. 公開フラグ読取API
2. FE routeガード middleware
3. `@RequireFeature` AOP
4. バッチ/リスナー宣言必須番人

### 住民からの報告

`/アリシゼーション` の探索結果である。台帳の `blockers` に転記済みのものはそこから拾えるが、
**未裏取りの観測はボードにのみ載る**（`/アリシゼーション` フェーズ6で殿が裏取りする前の一次記録）。
運用として、**`/アリシゼーション` 実施後に本スキルを回す**ことを前提とする（順序が逆だと最新の観測が
ボードへ反映されない）。

## 注意事項

- YAMLの語彙は番人 `FeatureInventorySchemaGuardTest` が守っている。ボード側で台帳に存在しない
  独自語彙（状態名・区分名）を作らない
- 台帳の状態を**ボード更新のついでに書き換えない**。本スキルは読み取り専用。台帳の変更が必要と
  気づいた場合は、別途 worktree + PR で台帳を直してから改めて本スキルを回す
- 「不明」が多いのは正常である。埋まっていないことを隠さず、正直に灰色で見せる
- ボードは Artifact なので **クローズドな正本ではない**。ボードを見て判断を下すのは構わないが、
  監査・追跡可能性が要る場面（Issue起票・裏取りの証跡）では必ず `docs/task-list.md` /
  `feature-inventory.yaml` 側を参照する
