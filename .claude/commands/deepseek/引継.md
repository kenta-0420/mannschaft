# 引継（セッション引き継ぎ書の生成）

> このスキルは運用作業のため `model: flash` 指定（殿のPro/Pro温存・feedback_pro_infra_ops_danger）。

セッションが途中で固まって復活できないときのために、**いま生きているこのセッションの文脈を 1 枚の引き継ぎ書にまとめ、別エージェントへそのまま貼れるプロンプトとして出力する**。
手書きで毎回書き起こす手間をなくすのが目的。**ファイルにも保存する**ので、この後セッションが落ちても残務は失われない。

## いつ使うか
- セッションが不安定・重い／長時間タスクの途中で「そろそろ危ないかも」と感じたとき（**予防的に先に走らせておく**）
- 既に応答が止まりかけ・別エージェントへ乗り換える直前
- 単純に作業を中断して、後で自分 or 別エージェントが再開できる状態にしたいとき

> セッションが**完全に**死ぬとこのコマンドも動かせない。**怪しいと思ったら早めに**叩いておくこと。

## 引数
- `$ARGUMENTS` … 任意のメモ（例 `/引継 予約F03.4の認可ゲート、CIが赤で止まってる`）。
  作業の主題や、文脈から読み取りにくい「特に伝えたいこと」を一言添えると引き継ぎ精度が上がる。省略可。

## 手順

### 1. 現在状態を機械的に収集（最小コマンド）
次を 1 回ずつ叩いて事実を集める（推測でなく実測を載せるため）:
```bash
pwd                                                   # 本陣か worktree か
git worktree list                                     # 隔離状況
git rev-parse --abbrev-ref HEAD                        # 現在ブランチ
git status --short                                     # 未コミット変更
git log --oneline -10                                  # 直近コミット
git diff --stat HEAD                                   # 触ったファイル概要
```
- 進行中の戦役台帳があれば `.claude/campaigns/` の最新ファイルも確認する。
- CI/PR が絡むなら、**1 回だけ** `gh pr list --author @me --state open --json number,title,headRefName,mergeStateStatus`（`/物見` の作法に従い連続ポーリング禁止）。
- 関連する設計書・メモリ（`MEMORY.md` のインデックス）で該当項目があれば拾う。

### 2. このセッションの会話履歴から「文脈」を再構成
収集した事実に加え、**今回のセッションで何を目指し・何を決め・どこで詰まったか**を会話の流れから拾い、後述のテンプレを埋める。
特に次を漏らさない:
- マスター（殿）の**御裁可・方針決定**（「〜でいく」と確定した設計判断）
- まだ**承認待ち**の事項（次のエージェントが勝手に進めてはいけない箇所）
- 試した仮説と**棄却した選択肢**（同じ轍を踏ませない）

### 3. 引き継ぎ書を生成してファイル保存
- 保存先: `.claude/handoffs/`（無ければ作成）
- ファイル名: `引継-<主題のkebab>-<YYYYMMDD-HHMM>.md`（時刻は `date '+%Y%m%d-%H%M'` で採る）
- 中身は下記テンプレに沿って**日本語**で記述する。
- テンプレ「0. 新エージェントへの最初の指示」の `<保存先パス>` には、**いま保存した実際のフルパスを埋め込む**（後任が完了後に自分自身を削除できるように）。

### 4. 貼り付け用プロンプトを画面にも出力
保存に加えて、**そのままコピーして新エージェントへ渡せる完成プロンプト**をコードブロックで画面に出す（ファイルを開かなくても即引き継げるように）。
貼り付け用プロンプトにも「**完了したら引き継ぎ書 `<保存先パス>` を削除すること**」の一文を必ず含める。
末尾に「保存先パス」を一言添える。

## 引き継ぎ書テンプレ（これを埋める）

```markdown
# 引継書: <主題>（<YYYY-MM-DD HH:MM>）

## 0. 新エージェントへの最初の指示
あなたは前任セッションの作業を引き継ぐ。まず本リポジトリの `CLAUDE.md`／`backend/.claudecode.md` の規約に従うこと。
**大名システム厳守**: 開発作業は本陣（`C:\Claude\mannschaft` 直下）で直接行わず、必ず `Agent(isolation:"worktree")` 経由で worktree 隔離して進める。着手前に `pwd` で作業ディレクトリを確認すること。
下記「残務」の先頭から再開してよいが、「承認待ち」項目はマスターの御裁可を得るまで着手しないこと。

**【完了後の片付け】この引き継ぎ書（`<保存先パス>`）は、残務がすべて片付き引き継ぎが無事完了したら削除すること。** 役目を終えた引き継ぎ書を残すと、次回以降「未消化の残務」と誤認される。途中で別のセッションへさらに引き継ぐ場合は削除せず、新しい引き継ぎ書を `/引継` で作り直してから古い方を消す（残務が宙に浮かないようにする）。

## 1. ゴール（最終目的）
<このタスクが完了したと言える状態。1〜3行で。>

## 2. 背景・経緯／確定した方針
<なぜこれをやっているか。マスターの御裁可・設計判断。関連する設計書/メモリへのリンク。>

## 3. これまでにやったこと（完了済み）
- <コミット/PR/ファイル変更。git log・PR番号で具体的に。>

## 4. 現在の状態（実測）
- 作業ディレクトリ: <pwd の結果。本陣 or worktree パス>
- ブランチ: <branch 名>
- 未コミット変更: <git status --short の要約。無ければ「なし」>
- 触ったファイル: <git diff --stat の要約>
- CI/PR: <PR番号と mergeStateStatus、または「該当なし」>
- dev サーバ等の常駐状態: <起動中なら BE/FE のポート。無ければ「なし」>

## 5. 残務（次にやること・順序付き）
1. <最初に手を付けるべき具体的アクション>
2. ...
（各項目は「どのファイルで・何を・どう確認するか」まで具体に。）

## 6. ブロッカー・詰まり／注意点
- <今まさに止まっている原因。エラーメッセージの要点>
- <棄却した選択肢（同じ轍を踏ませない）>
- <踏みやすい地雷・関連メモリ>

## 7. 承認待ち（勝手に進めてはいけない事項）
- <マスターの御裁可が必要な未確定事項。無ければ「なし」>

## 8. 参照
- 設計書: <パス>
- メモリ: <MEMORY.md の該当項目>
- 戦役台帳: <.claude/campaigns/ の該当ファイル、あれば>
```

## 守ること
- **推測で埋めない**。状態は手順 1 の実測値を載せる。分からない欄は「不明（要確認）」と正直に書く。
- **対処療法の記録を残さない**。詰まりは握りつぶさず、原因の連鎖をそのまま引き継ぐ（根治治療の原則）。
- 機微情報（トークン・秘密鍵）は引き継ぎ書に書かない。
- このコマンドは**生成と保存のみ**。実装・マージ・破壊的 git 操作はしない。
