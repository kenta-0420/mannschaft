# 陣払い（古い足軽worktreeの撤収）

> このスキルは運用作業のため `model: flash` 指定（殿のPro/Pro温存・feedback_pro_infra_ops_danger）。

大名システム（`Agent(isolation:"worktree")`）が残した `.claude/worktrees/agent-*` のうち、
**HEADコミットが指定日数以上前のもの**を安全に撤去する。`$ARGUMENTS` が日数（未指定なら **7**）。

これは worktree の git 管理操作であり、本陣で実行してよい例外作業（CLAUDE.md 参照）。

## 厳守する安全則
- 対象は `.claude/worktrees/agent-*` のみ。`dev-main`/`e2e-run`/`bootstrap-apply` 等の **非agent worktree は触らない**。
- **指定日数以内の worktree は残す**（他セッションで稼働中の足軽の可能性があるため）。
- 削除するのは worktree ディレクトリと、**throwaway な `worktree-agent-*` ブランチのみ**。
  `feature/*`・`feat/*` 等のブランチは **温存**（他PR・他セッションが参照しうる。worktree削除でもコミット済み成果は git に残る）。
- `--force` 削除は **未コミット変更を失う**。dirty な worktree は中身を確認してから削除する（下記手順2）。
- locked な worktree は `--force` でも消えない → **unlock してから削除**（手順4）。

## 手順

### 1. 棚卸し（指定日数以上前の agent worktree を一覧化）
```bash
cd "C:/Claude/mannschaft"
DAYS="$ARGUMENTS"; case "$DAYS" in ''|*[!0-9]*) DAYS=7;; esac   # /陣払い の引数（数値）。未指定/不正なら7
cutoff=$(date -d "$DAYS days ago" +%s)
echo "閾値: $(date -d @$cutoff '+%Y-%m-%d') より前のHEADを対象（$DAYS日以上前）"
git worktree list | awk '{print $1}' | grep "/agent-" | while read -r p; do
  [ -z "$p" ] && continue
  ts=$(git -C "$p" log -1 --format=%ct 2>/dev/null)
  d=$(git -C "$p" log -1 --format=%cd --date=short 2>/dev/null)
  if [ -z "$ts" ]; then echo "ERR  $(basename $p) (log取得不可・stale候補)"
  elif [ "$ts" -lt "$cutoff" ]; then
    dirty=$(git -C "$p" status --porcelain 2>/dev/null | head -1)
    echo "OLD  $d $(basename $p)$([ -n "$dirty" ] && echo ' ⚠dirty')"
  else echo "keep $d $(basename $p)"; fi
done | sort
```

### 2. dirty な OLD worktree の未コミット内容を確認
手順1で `⚠dirty` が付いたものについて、失う未コミット変更が保全価値あるか確認する。
```bash
# 例: git -C ".claude/worktrees/agent-XXXX" status --porcelain | head
```
`.claude/settings.local.json` のみ・診断スクラッチ・放棄テスト等で価値が無ければそのまま撤去してよい。
**実体のあるソース変更が残っていたら、その worktree だけ撤去を保留し殿に報告する。**

### 3. OLD worktree を削除（通常＝非locked）
手順1の `OLD` の ID 群を `OLD=` に列挙して実行。
```bash
cd "C:/Claude/mannschaft"
OLD="<手順1のOLDのID群をスペース区切りで>"
for id in $OLD; do
  p=".claude/worktrees/agent-$id"
  git worktree remove --force "$p" 2>/dev/null && echo "removed agent-$id" || echo "FAILED agent-$id（locked疑い→手順4）"
done
git worktree prune
for id in $OLD; do git branch -D "worktree-agent-$id" 2>/dev/null && echo "branch worktree-agent-$id 削除" || true; done
```

### 4. FAILED（locked）を unlock してから削除
手順3で `FAILED` になったものは locked。20日前等のコミットなら **死んだagentのstale lock** なので unlock して撤去する。
```bash
cd "C:/Claude/mannschaft"
FAILED="<手順3でFAILEDになったID群>"
for id in $FAILED; do
  p=".claude/worktrees/agent-$id"
  git worktree unlock "$p" 2>/dev/null
  git worktree remove --force "$p" 2>/dev/null && echo "removed agent-$id (unlock後)" || echo "STILL-FAILED agent-$id（要手動確認）"
done
git worktree prune
for id in $FAILED; do git branch -D "worktree-agent-$id" 2>/dev/null && echo "branch worktree-agent-$id 削除" || true; done
```

### 5. 結果報告
```bash
cd "C:/Claude/mannschaft"
echo "残存 agent worktree 総数: $(git worktree list | grep -c '/agent-')"
```
削除した件数・残した件数・温存した `feature/*` ブランチ・`STILL-FAILED`（あれば原因）を殿が要約してマスターに報告する。

## 注意
- locked が**直近日数**（稼働中の可能性）の場合は unlock/削除しない。本コマンドは閾値より古いものだけを対象とするため通常は安全だが、迷ったら殿が個別判断する。
- `git worktree remove` が Permission denied になるのは Gradle daemon 等のファイルロックが原因のことがある。少し待つか、当該プロセス停止後に再実行する。
