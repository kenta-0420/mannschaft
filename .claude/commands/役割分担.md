# 役割分担（タスク別モデル振り分け）

> このスキル自体は参照用のため `model: haiku`（呼び出しても軽量に終わらせる）。

大名システムでモデルを使い分ける際の**振り分け基準**を定義する。Codex 側に作成済みの同名スキルと対になるもの。

**呼称の使い分け（重要）**: Claude Code 上ではモデルをそのまま **Opus / Sonnet / Haiku** と呼ぶ。Codex 側の同名スキルでは同じ対応関係を **Sola（Opus）/ Terra（Sonnet）/ Luna（Haiku）** という呼称で扱う。両者は同一の振り分け基準を指す別名であり、Claude Code のセッション内でSola/Terra/Lunaという呼称は使わない。

## 振り分け方針（現行・2026-09-01時点の御下命を反映）

**既定は Sonnet。Opus は「Sonnet で実際に詰まった／判断が割れた」場合の格上げ先とし、着手時点での予防的な格上げはしない。**

| タスクの性質 | 既定モデル | 補足 |
|---|---|---|
| 絵図（設計書作成・要否精査） | Sonnet → 詰まったら Opus | 機械的な精査・反映は Sonnet、解釈が割れる箇所のみ Opus |
| 検分（コードレビュー） | **Codex 既定**（Claude 側で回す場合は Sonnet、敵対的検証ステージのみ Opus） | 2026-09-01 御下命でFable/Opus検分は使わない方針 |
| 軍議（設計・タスク分解） | Sonnet（偵察・列挙）／Opus（設計判断・トレードオフ精査） | 家老 Plan/Explore も model 省略禁止・明示必須 |
| コーディング・実装全般（FE/BE） | **Sonnet** | 認可・DB(Flyway)・複雑な型でも着手時は Sonnet、差し戻された箇所だけ Opus |
| テスト・E2E・ビルド確認 | **Sonnet** | |
| インフラ操作・プロセス起動停止・環境確認 | **Sonnet**（Opus/Fable には絶対させない） | Opus は「まず深く理解しろ」バイアスで運用タスクを壊す実績あり |
| 単純grep/置換・ファイル列挙・定型雑務・索敵 | **Haiku** | |

Fable 5 は殿がこのモデルで動いている場合のみ登場する特別枠。殿の采配・裁定・最終検分の裏取りに限定し、足軽へは通常継承しない。詳細・時限ルールの経緯はメモリ `feedback_model_routing` を参照。

## 使い方

- `Agent`/`Workflow` 呼び出し時は `model` パラメータ（`opus`/`sonnet`/`haiku`）を毎回明示すること（省略禁止）。
- 振り分け基準そのものの変更履歴・実測値（Opus乱用時のトークン消費など）は `feedback_model_routing` メモリが正本。本スキルは参照用の要約に留め、判断根拠の詳細はメモリ側を参照する。
