# 物見（CI/PR 戦況の低頻度確認）

> このスキルは運用作業のため `model: sonnet` 指定（殿のOpus/Fable温存・feedback_opus_infra_ops_danger）。

物見櫓から戦場を遠望する斥候のように、**1回だけ**叩いて CI/PR の戦況を検め、報告して退く。
`gh run watch` の常時ポーリングや並行 watch は GitHub API クォータ（5000/hr・全セッション共有）を
枯らし 403 を招くため**使わない**。10分周期で回したいときは `/loop 10m /物見 <PR番号...>` で包む。

## いつ使うか
- 複数エージェント並行中など、CI 完了をポーリングで待つと API が枯れる場面
- 「数分後にもう一度だけ確認したい」単発チェック

## 引数
- `$ARGUMENTS` … 空白区切りの PR 番号（例 `/物見 1728 1732`）。
- 省略時は「自分の OPEN PR」を対象にする。

## 手順（必ず "1ラウンドだけ" 叩いて終わる）

### 1. 対象 PR の特定（最小 API 呼び出し）
- 引数があればその PR 番号を対象にする。
- 引数が無ければ **1 回だけ** `gh pr list --author @me --state open --json number,title,headRefName` を叩き、
  対象 PR を得る（多すぎる場合は戦役台帳 `.claude/campaigns/` の最新ファイルに載る進行中 PR に絞る）。

### 2. 各 PR の状態を 1 回ずつ取得（PR 1件＝API 1コール）
各対象 PR に対して **1 回だけ** 次を叩く（ループ watch 禁止）:
```
gh pr view <PR> --json number,title,state,mergeable,mergeStateStatus,statusCheckRollup
```
- `statusCheckRollup` から各チェックの `status`/`conclusion` を読む（**個別ジョブのログは取得しない**）。
- 失敗チェックがあり原因を要約する必要があるときに限り、**1 回だけ**
  `gh run view <runId> --log-failed | Select-String "error:|FAILED|Caused by"`（先頭 ~25 行）で要点抽出。
  `gh run view --log`（全ログ）は禁止。

### 3. 判定と報告（PR ごとに一行）
各 PR を次の語彙で分類して簡潔に報告する:
| 判定 | 条件 | 推奨アクション |
|---|---|---|
| 🟢 マージ可 | state=OPEN・mergeStateStatus=CLEAN・全チェック SUCCESS | 検分後マージ |
| 🟡 要追従 | mergeStateStatus=BEHIND（CIは緑） | worktree で main 取込→push（`--admin` 迂回禁止） |
| ⏳ 進行中 | チェックに IN_PROGRESS/QUEUED あり | 待機（次の物見へ） |
| 🔴 red | いずれかのチェック FAILURE | 原因要約（手順2の log-failed 1発）→根治 |
| ✅ マージ済 | state=MERGED | 完了（次回対象から外す） |

### 4. 退く（ここで終わる）
- **このコマンドは1ラウンドで必ず終了する。** 自前で `Start-Sleep` ループや `gh run watch` を回さない。
- まだ ⏳進行中 が残るなら、報告の最後に「次の物見の目安」を一言添える
  （`/loop 10m /物見 <PR...>` を使えば自動で10分後に再確認、と案内）。

## API クォータ枯渇（403）時の作法
1. `gh api rate_limit --jq '.resources.core | "残\(.remaining)/\(.limit) reset=\(.reset)"'` で reset（Unix時刻）を確認。
2. 一次制限なら **reset まで待つ（最大~60分・瞬間全回復）**。二次制限（短時間叩きすぎ）は `Retry-After`≈60秒。
3. リトライ連打しない。`/loop` 周期を延ばす（例 `/loop 20m`）か、reset 時刻以降に再開する。

## 禁止事項（枯渇の元）
- `gh run watch`（内部3秒ポーリング）/ 並行 watch 多数起動
- `gh pr checks` や `gh run view` の短間隔ループ
- `gh run view --log`（全ログ取得＝数万トークン）
- このコマンド内での foreground スリープループ

## 報告フォーマット例
```
🏯殿様:【物見】CI戦況（HH:MM時点・1ラウンド）

- #1732 🟢 マージ可（CLEAN・Compile&Test SUCCESS）→ 検分後マージ
- #1728 🟡 要追従（BEHIND・CIは緑）→ worktreeでmain取込
- #1740 ⏳ 進行中（shard 2/4 実行中）

API残: 4870/5000（reset 12:43）
次の物見: `/loop 10m /物見 1728 1740`（自動10分周期）
```
