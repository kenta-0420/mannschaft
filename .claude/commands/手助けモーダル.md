# 手助けモーダル（モーダル母体の使い方ガイド）

殿として、家老に対象モーダルを偵察させ、足軽を出陣させて **そのモーダル専用の「使い方ガイド」** を作る。
通常の `/手助け` は **PageHeader の `help` フラグ**で開く前提だが、**PageHeader を持たない `Dialog`（モーダル）画面**にはそれが使えない。本スキルはその穴を埋める。

中身は `/手助け` と同じ **マイプロジェクト（`ProjectGuideContent`）方式の「色付き丸アイコン＋カード」** を流用し、機能ごとに「これは何か → どんな時に使う → 使い方の手順」を初めて見る人にも分かるよう丁寧に書く。**違うのは“どこに置き・どう開くか（配線）”だけ。**

> **なぜ別スキルなのか**: ウィザードや作成ダイアログのように「画面＝モーダル」な機能が増えている。これらは PageHeader を持たないため `/手助け` の標準配線（`help` フラグ）が使えない。母体がモーダルのときの“正しい置き方”を金型化し、UX 事故（モーダル on モーダルの窮屈さ・閉じる動線の混乱）を避けて再現可能にするのが本スキル。

## いつ使うか

- 母体が `Dialog`（モーダル）で **PageHeader が無い**画面に使い方ガイドを足したいとき（例: 告知ウィザード、各種 作成/編集ダイアログ）
- `/手助け`（ページ＋PageHeader）では配線できないと分かったとき
- 既存のモーダル内に手書きの「？」説明があり、統一様式に寄せたいとき

> 母体が **PageHeader を持つ通常ページ**なら、本スキルではなく `/手助け` を使う。

## 引数

- `$ARGUMENTS` … 対象モーダル（`.vue` のパス、または「チーム内告知ウィザード」などの画面名）。
  画面名で渡された場合は、家老がまず該当モーダル `.vue` を特定する。複数モーダル対象なら1つずつ順に作る。

## 配線方式（既定は②。①は窮屈になる時の代替のみ）

| 方式 | 内容 | 採否 |
|---|---|---|
| **② インライン折りたたみ（既定・推奨）** | 母体モーダル内に「使い方」トグル（`Button text` ＋ 開閉 `ref`）を置き、押すと**同じモーダル内で**ガイドカード領域が展開する。モーダルを重ねない。 | **既定でこれを使う** |
| ① モーダル on モーダル（代替） | 母体モーダルのヘッダーに「？」アイコンを置き、押すと**別の `Dialog` を上に重ねて**開く。PrimeVue の `Dialog` は z-index スタックを自前管理するので技術的には動く。 | **母体が小さい/単機能で②だと窮屈な時だけ**。多段ウィザードや縦長モーダルでは②を優先 |

> ②を既定にする理由: モーダル二重は閉じる動線（×が2つ）が紛らわしく、特にスマホで窮屈（マスターはADHD傾向＝迷いを増やさない。メモリ `user_adhd_tendency`）。同一モーダル内の折りたたみなら、操作の文脈を保ったまま使い方を出し入れできる。

| 役割 | 手本ファイル |
|---|---|

## 成果物（1モーダルあたり）

そのモーダルの機能ドメインのコンポーネントディレクトリ（例: 告知なら `components/announcement/`）に **カード本体1ファイル**を新設し、母体モーダルに**折りたたみ配線**＋ロケールを足す。

1. **`<Xxx>GuideContent.vue`** … カード本体（`ProjectGuideContent.vue` を写経。各機能＝1カード）
2. **母体モーダル `.vue`（②配線）** … `const showHelp = ref(false)` を足し、ヘッダー付近かボディ先頭に「使い方」トグルボタン、その直下に展開領域 `<XxxGuideContent v-if/v-show>` を置く
3. **i18n** … `frontend/app/locales/{ja,en,zh,ko,es,de}/<適切な>.json` に `<xxx>_guide` でキー追加。**6言語すべて・キー構造完全一致**。まず ja を丁寧に書き、他5言語は ja コピー可（後で翻訳）。

### ② 折りたたみ配線の雛形（母体モーダル内）

母体が PrimeVue `Dialog` の場合、ヘッダー右に「使い方」トグルを置き、本文先頭で展開する:

```vue
<script setup lang="ts">
// 既存の母体モーダルの script に追記
const showHelp = ref(false)
</script>

<template>
  <Dialog v-model:visible="visible" modal :header="$t('...')" class="w-full max-w-2xl">
    <!-- 使い方トグル（本文先頭・右寄せ） -->
    <div class="mb-2 flex justify-end">
      <Button
        :label="$t('<xxx>_guide.toggle')"
        :icon="showHelp ? 'pi pi-chevron-up' : 'pi pi-question-circle'"
        text
        size="small"
        :aria-expanded="showHelp"
        data-testid="<xxx>-guide-toggle"
        @click="showHelp = !showHelp"
      />
    </div>

    <!-- 展開領域（同一モーダル内・重ねない） -->
    <Transition name="fade">
      <div
        v-if="showHelp"
        class="mb-4 rounded-lg border border-surface-200 bg-surface-50 p-4 dark:border-surface-700 dark:bg-surface-800"
        data-testid="<xxx>-guide-panel"
      >
        <XxxGuideContent />
      </div>
    </Transition>

    <!-- ↓ 既存のモーダル本文（ウィザード等）はそのまま -->
  </Dialog>
</template>
```

> PrimeVue の `<Accordion toggleable>` や `<Panel toggleable>` を使ってもよい（プロジェクトの既存使用に合わせる）。独自レイアウトを発明せず、既存の折りたたみ部品の作法に倣う。多段ウィザードなら「ヘッダーに1つだけトグル」を置き、全ステップ共通の使い方を1パネルで見せると迷いが少ない。

### `<Xxx>GuideContent.vue`（`ProjectGuideContent` の写経。各機能＝1カード）

```vue
<script setup lang="ts">
const { t, tm } = useI18n()
type StepRecord = Record<string, string>
// 連番ステップ（step1, step2...）を順序付き配列へ正規化（tm() の値を t() で個別解決）
function resolveSteps(key: string): string[] {
  const raw = tm(key) as StepRecord | null
  if (!raw || typeof raw !== 'object') return []
  return Object.keys(raw).map((k) => t(`${key}.${k}`))
}
const audienceSteps = computed<string[]>(() => resolveSteps('<xxx>_guide.<section>.steps'))
</script>

<template>
  <div class="space-y-4">
    <p class="text-sm leading-relaxed text-surface-600 dark:text-surface-300">
      {{ t('<xxx>_guide.description') }}
    </p>

    <!-- 機能ごとに1カード -->
    <SectionCard>
      <div class="flex items-start gap-4">
        <div class="flex h-10 w-10 shrink-0 items-center justify-center rounded-full bg-blue-100 text-blue-600 dark:bg-blue-900/30 dark:text-blue-400">
          <i class="pi pi-<icon> text-xl" aria-hidden="true" />
        </div>
        <div class="w-full">
          <h2 class="mb-2 text-lg font-semibold">{{ t('<xxx>_guide.<section>.title') }}</h2>
          <p class="mb-3 text-sm leading-relaxed text-surface-600 dark:text-surface-300">
            {{ t('<xxx>_guide.<section>.body') }}
          </p>
          <ol class="list-decimal space-y-1 pl-5 text-sm text-surface-600 dark:text-surface-300">
            <li v-for="(step, i) in audienceSteps" :key="i">{{ step }}</li>
          </ol>
        </div>
      </div>
    </SectionCard>
  </div>
</template>
```

### カードの装飾パターン（`ProjectGuideContent` 準拠）

- アイコンは **色付き丸**: `flex h-10 w-10 shrink-0 items-center justify-center rounded-full bg-{color}-100 text-{color}-600 dark:bg-{color}-900/30 dark:text-{color}-400` ＋ `<i class="pi pi-XXX text-xl" aria-hidden="true" />`
- 色はカードごとに変える（blue / green / violet / amber / teal）。アイコンは内容に合うもの（`pi-users` 対象範囲 / `pi-send` 送信 / `pi-megaphone` 告知 / `pi-bookmark` テンプレート / `pi-exclamation-triangle` 注意 等）
- 手順 → **番号付きリスト** `list-decimal`／要点 → `pi-check text-green-500` の箇条書き／注意・補足 → `rounded-lg bg-surface-50 p-3 dark:bg-surface-800` ＋ `pi-info-circle` の囲みボックス
- モーダル内の折りたたみ領域はさらに狭いので、**カードの入れ子は避け**、見出し `h2`＋本文＋リストで簡潔に

## 偵察ファースト（内容を捏造しない・最重要）

**使い方の文章は、対象モーダルの実コードを読んでから書く。** 想像で機能を捏造しない（メモリ `feedback_empirical_bug_detection_over_speculation`）。家老は母体モーダル `.vue` と関連 composable を読み、次を洗い出して「カード割り」を作る:

- そのモーダルに**実在する機能セクション**（ステップ・フォーム・トグル・送信ボタン・選択肢等）
- 各機能の**操作手順**（どのボタンで何が起きるか。`@click`・呼んでいる API・遷移を確認）
- **状態や制約**（権限で出る/出ない要素、必須項目、上限、既定値、ガード）
- **つまずきポイントと対処**（エラーになりやすい操作）があれば1カード設ける

書きぶり:
- **初めて触る人前提**で専門用語は噛み砕く
- **入力摩擦の低い導線を優先**（最短ルートを先に。メモリ `user_adhd_tendency`）
- 命令形で短く。1カード＝1トピック。手順は番号付きで「上から順にやれば終わる」形に

## i18n ルール

- 文字列は**直書き禁止**。`<xxx>_guide`（例 `broadcast_guide`）を新設するか、その画面ドメインの既存 json に追記。
- **6言語**（ja/en/zh/ko/es/de）すべてに、**同一キー構造**で追加。ja を正に丁寧記述、他はとりあえず ja コピー可。
- トグルのラベルは `<xxx>_guide.toggle`（例「使い方」）。閉じるボタンは②では不要（折りたたむだけ）。
- ロケールファイルは **nuxt.config の `files` 配列に登録済みのもの**に追記する（新規ファイルを足すなら6言語とも `files` 登録必須。メモリ `project_i18n_locale_file_registration_required`）。
