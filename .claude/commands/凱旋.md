# 凱旋（検分 → CI緑裏取り → マージ）

戦（実装）を終えた足軽の成果PRを、**検分で品質を検め・CI緑を実体で裏取りし・mainへマージ**して凱旋させる一気通貫スキル。
`--admin` 指定時は、CI緑＋検分合格を確認した上でブランチ保護を越えて admin マージしてよい（マスター委譲済み）。

> 位置づけ: **設計→軍議→試練→出陣→検分→実機E2E** の後段、「検分〜マージ」を1コマンドに束ねたもの。
> 単発の検分だけなら `/検分`、CI戦況だけなら `/物見` を使う。

## 引数
- `[PR番号]`: 対象PR。省略時は現ブランチに紐づく OPEN PR を `gh pr view --json number` で解決。
- `--admin`: ブランチ保護を越えた admin マージを許可（**CI緑＋検分合格が絶対前提**）。無指定なら通常マージ。

## 手順

### 1. 対象PRの特定と前提確認
```bash
gh pr view <PR> --json number,state,headRefName,headRefOid,mergeable,mergeStateStatus
```
- `state=OPEN` を確認。既に MERGED/CLOSED なら退く。
- head SHA を控える（後の裏取り用）。

### 2. 検分（必須・スキップ禁止）
`feedback_inspection_required_before_merge`: **CI通過だけでマージしてはならない。必ず検分を行う。**
- 差分が広い/複数観点なら `/検分`（Workflow 検分）を起動。小さければ従来検分。
- 受け入れ条件↔テスト↔実装のトレーサビリティ、配線の正確性、**新依存を足したら @InjectMocks 兄弟テストの mock 漏れ**（フルシャードNPEの温床。`project_media_url_resolution_architecture`）を照合。
- 足軽の自己申告は鵜呑みにせず、`git show`/実テスト実走で実体裏取り（`feedback_verify_tool_output_fabrication`）。
- **検分でNGが出たら凱旋を中断**し、足軽に差し戻す。緑になるまでマージしない。

### 3. CI緑の裏取り（偽exit0を信じない・ポーリング枯渇しない）
```bash
rid=$(gh run list --branch <headRef> --limit 1 --json databaseId -q '.[0].databaseId')
gh run view $rid --json status,conclusion -q '"status=\(.status) conclusion=\(.conclusion)"'
```
- **`gh run watch` の exit code を信じるな**（`feedback_gh_run_watch_false_exit0`: cancel/in_progressでもexit0を誤報。この環境では即離脱し `watch_exit=1` でも run は in_progress のまま）。**必ず `gh run view --json conclusion` の実値**で判定。
- まだ `in_progress`（Test shard 実行中は数十分かかる）なら、**低頻度の有界ループ**で完了を待つ（`gh pr checks` の "pending" は走行中を含む＝queue詰まりと誤認しない）:
  ```bash
  for i in $(seq 1 30); do s=$(gh run view $rid --json status -q .status); [ "$s" = completed ] && break; sleep 60; done
  gh run view $rid --json status,conclusion -q '.conclusion'
  ```
  これは `run_in_background` で回し通知を待つ。**連続ポーリング/並行watchは禁止**（`feedback_no_ci_polling`: API 5000/hr 全セッション共有・403で全gh停止）。
- 判定: `conclusion=success` かつ `gh pr checks <PR>` が **Failed: 0**。**フルシャード（Test shard 0〜3）が緑**であることを必ず確認（局所実走の緑に騙されない・NPE系はここで初検知）。
- `failure` なら `gh run view $rid --job <失敗job> --log-failed | grep -E "FAILED$|NullPointer|expected:"` で失敗テストを特定→足軽に差し戻し。**マージしない**。

### 4. マージ（gh のみ・本陣git禁止）
`feedback_merge_gh_only_no_honjin_git` / `feedback_merge_via_worktree_no_admin`: マージは `gh` だけ。本陣 working tree で git 操作しない。
```bash
# --admin 指定時（CI緑＋検分合格が前提）
gh pr merge <PR> --squash --admin --delete-branch
# 無指定時
gh pr merge <PR> --squash --delete-branch
```
- BEHIND（mergeStateStatus=BEHIND）で通常マージが弾かれ、かつ `--admin` 指定なら admin で越える。`--admin` 無指定でBEHINDなら worktree足軽で `git merge origin/main`→push→CI緑→通常マージ（本陣gitは使わない）。
- 直後に**マージ実体を裏取り**（`feedback_verify_tool_output_fabrication`）:
  ```bash
  gh pr view <PR> --json state,mergeCommit -q '"state=\(.state) mergeCommit=\(.mergeCommit.oid[0:9])"'
  git fetch origin main --quiet && git log --oneline -1 origin/main   # mergeCommit が main 先頭に在るか
  ```

### 5. 後片付け（worktree 撤去）
- ローカルブランチ削除が `used by worktree` で失敗するのは、当該ブランチを足軽worktreeが握っているため（正常）。撤去する:
  ```bash
  git worktree remove --force .claude/worktrees/agent-xxxxx
  git branch -D <feature-branch>; git worktree prune
  ```
- **junction注意**（`feedback_worktree_remove_junction_deletes_honjin_node_modules`）: `frontend/node_modules` が本陣へのjunctionなら、`git worktree remove` がjunction先の本陣実体を巻き込み削除する。撤去前に `ls .../frontend | grep node_modules` で確認し、junctionあれば `cmd //c rmdir` でリンクを先に外す（BE-onlyでjunction無ければそのまま撤去可）。
- 検証用dev サーバ（`:8081`/`:3001` 等）を足軽が起こしていたら、PID cmdline裏取りの上 kill（`wsl --shutdown` 厳禁・本陣8080/3000は触るな）。

## 上奏（マスターへ）
```
🏯殿様:【凱旋】マスター、PR #<n>「<title>」を main へ凱旋させました
- 検分: <合格/差し戻し内容>
- CI: run <id> conclusion=success（フルシャード緑・Failed 0）※実体裏取り
- マージ: MERGED / mergeCommit <sha>（origin/main 先頭に反映確認）
- 後片付け: worktree撤去済・検証サーバkill済・本陣無傷
```

## 禁止事項（凱旋の鉄則）
- **検分せずマージ**（CI緑だけでマージ）
- **`gh run watch` の exit code でCI合否を判定**（必ず `gh run view --json conclusion` の実値）
- **CI連続ポーリング/並行watch**（API枯渇→403で全gh停止）
- **本陣 working tree での git 操作**（マージは gh のみ・pre-commitフック/本陣gitガードで機械的に拒否される）
- **足軽の自己申告を無検証で信用**（識別子・マージ結果は `gh --json`＋`git show origin/main` で裏取り）
- **フルシャード未確認でのマージ**（局所緑に騙されない）
